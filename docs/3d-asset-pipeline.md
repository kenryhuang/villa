# 低成本 3D 游戏资产制作流水线

整理日期：2026-09-15。适用于 Villa 的 Godot 3D 农庄，以及同类小团队、风格化游戏项目。

目标：从文字描述和参考图片出发，制作可以在游戏中正常显示、运动、交互，并能持续复用和扩展的模型资产库。

本文是一套推荐工作流，不代表相关平台、插件或自动化工具已经接入项目。平台价格、积分规则、下载权限和许可依据整理日期查询的官方资料记录，采购和发布前应再次确认。

## 1. 推荐组合与整体流程

**推荐组合：Meshy 生成图片和特色模型，Blender 整理模型与统一规范，成熟角色底模和共享动画库补齐资产，最终以 GLB 导入 Godot。**

低成本建设完整资产库的重点，是建立可换装角色、可组合建筑和可复用动作。一套验证过的基础资产应能扩展为多个居民或场景变体。

```text
文字描述与风格基准
        ↓
角色／物件参考图
        ↓
图片转 3D → 原始模型与贴图归档
        ↓
Blender：整理网格、材质、尺寸、原点和活动部件
        ├─ 静态物件／建筑 → 碰撞与活动部件准备
        └─ 角色 → 骨骼绑定 → 权重修正 → 共享动画／专用动作
        ↓
导出 GLB
        ↓
Godot：外层场景、碰撞、动画状态、挂点和交互
        ↓
游戏内验收 → 合格资产库 → 换装、配色与组合变体
```

| 阶段 | 推荐工具 | 阶段产物 |
| --- | --- | --- |
| 文字转图片 | 已有文生图工具，或 Meshy 内置图片生成 | 风格统一、结构明确的参考图 |
| 图片转 3D | Meshy Image to 3D；Tripo 作为备选 | 原始网格与贴图 |
| 模型整理 | Blender | 合理面数、材质、尺寸及独立活动部件 |
| 骨骼绑定 | Meshy 自动绑定起步，Blender 修正 | 经基本姿势测试的骨架与权重 |
| 动作制作 | Quaternius 动画库、Blender 专用动作 | 可供多个 NPC 复用的动作库 |
| 游戏集成 | Blender 导出 GLB，Godot 导入 | 带动画、碰撞、挂点和交互的游戏场景 |

## 2. 文字描述与参考图片

### 2.1 先确定风格基准

先制作并确认一张代表游戏风格的基准图，固定以下内容：

- 人物头身比例、轮廓和面部简化程度。
- 建筑尺度、屋顶形状和装饰密度。
- 色板、材质粗糙感和手绘细节程度。
- 从实际游戏镜头距离观察时，需要保留的识别特征。

后续资产沿用基准图作为参考。主角、NPC、建筑和道具应放到相同光照的测试场景中比较，避免单独看都精美、放在一起却风格不一致。

### 2.2 生成适合建模的角色图

- 全身完整，采用 A-pose 或 T-pose。
- 双腿分开，手臂与身体留出间隙，手脚清晰可见。
- 使用简单背景和均匀光照，避免强烈阴影被误认为材质颜色。
- 农具、武器和可替换配饰单独生成，避免与身体融合。
- 先确定主图，再制作相应侧面和背面，检查服装、发型与比例是否一致。
- 使用多视图输入时分别提交各视角，避免将排版后的三视图海报误当成一个物体。

阿禾参考描述：

> 温暖手绘风格的成年村庄农夫，全身，约五头身比例，蓝灰色短上衣、棕色长裤、布鞋，简洁清晰的面部，A-pose，双手不持物且与身体分开，双脚分开，浅灰背景，柔和均匀光照，无文字、无道具、无底座。

Meshy 的图片模块支持参考图和迭代编辑，并能将确定后的图片送入 3D 生成流程。初期可优先使用已有图片工具；需要一体化工作流时，再考虑使用 Meshy 内置图片功能。[官方图片生成说明](https://help.meshy.ai/en/articles/13696156-how-to-use-the-text-to-image-feature)

## 3. 图片转 3D：小批比较，先确认形体

优先选择 Meshy 的原因是图片、模型、网格整理、绑定和动画集中在同一套工具里，便于减少转换工作；不意味着它对所有类别的模型都优于其他平台。

第一次试产使用以下三类对象：

1. 穿普通衣服的人形 NPC，用于检查手脚、背面和关节结构。
2. 手推车等结构明确的物件，用于检查车轮、把手和独立部件。
3. 磨坊等特色建筑，用于检查整体比例、屋顶和活动构件。

先检查轮廓、侧背面和部件结构，再为合格形体生成最终贴图。Meshy 提供面向实时渲染的 Smart Topology 模式，可以与普通模式对比；按游戏实际观感和后续整理成本选择。[官方图片转 3D 说明](https://docs.meshy.ai/en/webapp/image-to-3d)

如果某类模型效果持续不理想，可将相同参考图交给 Tripo 做对比。Tripo 当前免费计划标注非商业用途，商业发行应使用具备相应许可的资产。[Tripo 官方价格与许可说明](https://www.tripo3d.ai/pricing)

生成结果作为原始素材保留。不要只保存平台预览图或最终 GLB，应同时归档原始网格、贴图、输入图片和生成参数。

## 4. Blender 整理与游戏化处理

### 4.1 在绑定前完成主要网格修改

- 分离门、车轮、风车叶片、工具等活动部件，设置正确转轴。
- 修复角色手脚粘连，检查肩、肘、髋、膝附近的网格分布。
- 清理无用内部面、漂浮碎片及明显穿插。
- 统一尺寸、朝向、原点、贴图密度和材质风格。
- 减少不必要的面和材质槽；必要时重新烘焙贴图。
- 保留原始生成版本和整理后的编辑版本。

简单减面不等于角色拓扑整理。静止时好看的角色，弯腿或抬手后仍可能塌陷。绑定完成后再大幅修改拓扑，通常需要重新检查甚至重做权重。

Meshy 官方也建议先整理网格，再执行自动绑定。[官方绑定说明](https://docs.meshy.ai/en/webapp/guides/3d-model/rigging)

### 4.2 初始性能预算

针对当前农庄视角，可先以普通 NPC **约 8,000～20,000 三角面、1K～2K 贴图、尽量少的材质槽**作为试产起点。

这是项目建议值，不是引擎限制或性能保证。应在目标机器上，用预计同屏角色数量、实际灯光与阴影设置测试后调整。建筑和道具按屏幕占比与复用数量单独制定预算。

## 5. 角色底模、骨骼与动作库

### 5.1 少量底模扩展多个居民

先完成两三个基础体型，再用发型、帽子、上衣、围裙、配色和配饰扩展居民。主要 NPC 可增加独立头部或特色服装，以保留辨识度。

这种方式能复用已经验证过的关节、权重和动作，避免每个 NPC 从零生成一套不同的身体结构。

成熟底模可以从 Quaternius 的模块化角色包开始试用。该包提供可组合部件和动画，标注 CC0，可用于商业项目。先改造一个样本，确认它与农庄风格相容，再批量采用。[Quaternius 模块化角色包](https://quaternius.com/packs/ultimatemodularcharacters.html)

### 5.2 自动绑定后必须检查变形

特色角色可以先用 Meshy 自动绑定，再在 Blender 检查和修正：

- 走路时髋部、膝盖、脚踝是否自然。
- 抬手和弯肘时肩膀、腋下是否塌陷。
- 蹲下时衣服是否严重穿插。
- 握持工具时手掌、手指及工具方向是否正确。

复杂面部表情、特殊尾巴和非标准骨骼需要单独处理。自动绑好骨架不代表所有动作已经可用。[Meshy 绑定范围与限制](https://docs.meshy.ai/en/webapp/guides/3d-model/rigging)

### 5.3 基础动作共享，农作动作专门整理

基础动作优先使用 **Quaternius Universal Animation Library 的免费部分**。该库提供 Godot 适配版本，标注 CC0；完整包、扩展内容和 Blender 源文件的获取范围依版本而异。[Quaternius 动画库](https://quaternius.com/packs/universalanimationlibrary.html)

建议先建立待机、走路、跑步、转身、坐下和挥手等基础动作，再补充农庄专用动作：

- 播种、浇水、挥锄、收割。
- 搬箱、操作工作台。
- 钓鱼及其他需要准确持物的活动。

农具作为独立模型挂在手部骨骼上。在 Blender 中整理握持和接触姿势，在 Godot 中对齐动作效果发生的时刻。不要假设通用挥手或攻击动作能直接替代所有劳动动作。

Mixamo 可以作为补充。Adobe 官方说明其角色与动画可免费用于商业游戏，但自动绑定主要面向双足人形，且中国地区账号不可用。因此不将其作为项目唯一动画来源。[Adobe Mixamo FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html)

## 6. 导入 Godot 与游戏内验收

### 6.1 统一导出与场景结构

保留 `.blend` 作为编辑源文件，导出 `.glb` 进入游戏。Godot 官方推荐 glTF 2.0；GLB 可以携带网格、贴图、骨骼和动画。[Godot 3D 格式说明](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

给导入模型建立外层 `.tscn`，在外层组织碰撞、交互区域、脚本和挂点，便于后续更新或替换模型。

人形角色使用 `BoneMap` 和 `SkeletonProfileHumanoid` 做骨骼映射，并检查参考姿势。共享动画需要兼顾骨骼名称和参考姿势，不能只靠名称一致。[Godot 骨骼重定向说明](https://docs.godotengine.org/en/4.7/tutorials/assets_pipeline/retargeting_3d_skeletons.html)

初期优先使用原地行走动画，由现有角色控制器负责移动；随后匹配步幅与播放速度。若后续采用根运动，需要统一控制器与动画的位移职责。

### 6.2 每件资产的验收标准

- 在实际游戏镜头、灯光下，风格和比例正确。
- 导入后没有缺失贴图、明显法线问题或异常朝向。
- 角色走路、转身、蹲下、抬手等动作没有明显变形和滑步。
- 手持工具方向正确，手部接触位置合理。
- 锄地、浇水等逻辑效果与动作中的接触时刻一致。
- 建筑入口、碰撞、活动部件和交互区域符合玩法要求。
- 在目标同屏数量下，性能满足项目预算。
- 从编辑源文件重新导出后，游戏集成仍然有效。

## 7. 预算、试产规模与许可

### 7.1 先订阅一个月，完成样板后再扩产

整理时，Meshy 官方入门教程列出 Pro **20 美元/月、1,000 积分**。实际购买前应确认当前结算价格、月付与年付区别及优惠条件。[Meshy 官方入门与套餐说明](https://help.meshy.ai/en/articles/9991793-how-to-use-meshy-complete-beginner-s-tutorial)

按图片、模型与贴图合计 **35～45 积分一轮**做粗预算，1,000 积分约支持 **22～28 轮生成**。这不是合格资产数量；形体重做、贴图返工和额外处理会减少最终产出。不同模型版本和模式费用不同，以提交任务时显示的消耗为准。[积分消耗说明](https://help.meshy.ai/en/articles/10000507-how-many-credits-does-each-generation-task-cost)

为控制开销，先准备参考图和资产清单，再集中制作。初期只订阅一家 3D 平台，手动完成网页端生成和筛选；流程稳定后再考虑 API 批量接入。

### 7.2 免费试用和下载限制

Meshy 免费计划可用于试流程，但当前只有 Meshy 6 Lite 模型提供有限免费下载，Meshy 6／7 模型下载需要付费。免费输出采用 CC BY 4.0，需要按许可署名。付费期间创建的私有许可资产在降级后仍可下载，具体以账号和当时条款为准。[Meshy 免费计划说明](https://help.meshy.ai/en/articles/15696428-what-is-included-on-the-free-plan)

每件外部或生成资产都记录来源、生成时使用的套餐、许可和署名要求。参考图片也应具有相应使用权限。平台声明的商用许可不能替代对输入素材来源的确认。[Meshy 资产权利说明](https://help.meshy.ai/en/articles/10137554-what-is-the-ownership-of-the-generated-models)

### 7.3 第一批交付目标

| 交付物 | 验收目标 |
| --- | --- |
| 1 个完整 NPC | 在游戏中正常走路、说话、挥锄和拿工具 |
| 1 套共享骨架与基础动作库 | 第二个角色能够复用，验证重定向流程 |
| 1 座特色建筑 | 活动部件、碰撞和交互功能齐全 |
| 5 件特色道具 | 可以通过配色、尺寸和组合扩展变体 |

第一批的重点是打通完整链路。样板通过后再批量扩展居民、建筑和装饰物，不用生成数量代替游戏内完成度。

## 8. 本项目的资产管理与自动化分工

沿用项目现有目录职责：

- `art/blender/`：可编辑 Blender 源文件。
- `assets/models/`：供 Godot 使用的模型与贴图。
- `scripts/tools/`：生成、整理和导出脚本。
- `scenes/farm3d/`：正式农庄场景及相关集成。

建议为新增资产配套保存：资产 ID、参考图片、原始生成结果、编辑源文件、来源与许可、生成参数、Blender 版本、导出设置、动画名称和验收结果。具体清单格式可在首批试产时确定。

Codex 适合负责资产清单、Blender CLI 批处理、尺寸与命名检查、导出检查和 Godot 集成。形体筛选、关节变形与风格验收保留人工确认；可通过多角度渲染和游戏内预览协助判断。

Blender MCP 可用于打开场景后的交互微调。可重复的整理和导出步骤优先固化为 Python 脚本，再用 CLI 执行。

现有生成脚本可能覆盖对应资产。对于 AI 导入或手工整理的模型，应明确哪份文件是后续编辑依据：要么把修改同步到生成脚本，要么将模型转为独立维护，避免再次运行旧脚本时丢失修改。
