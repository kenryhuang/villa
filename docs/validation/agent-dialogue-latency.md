# Agent 对话响应验证

2026-09-08。来源 trace：`tmp/farm3d-65afa1b104598-ffe300efd7-1788880102-5060561.ndjson`。

## 问题与修复

三次对话请求均已发出，分别等待约 34.95、5.57、14.22 秒后因关闭对话而取消，期间没有内容或工具响应。后台自主决策耗时 128～325 秒，对话原先与这些请求共用普通 FIFO 队列。客户端取消同一个 NPC 的后台请求，并不能保证释放的服务槽位先给对话：它可能立即被别的后台请求占用。trace 没记录远端实际开始时刻，无法仅据此拆分每次请求的排队和上游耗时。

本次修改：

- 对话优先于排队的自主决策和记忆压缩。全部槽位忙时取消一轮尚未完成的后台远端请求，等它释放槽位后执行对话，再重新请求被让出的后台轮次。并发上限不增加；部分工具调用不提交为游戏命令；真正被用户取消的任务不复活。
- 对话上下文保留身份、当前资源、当前项目完整状态、有效交易/合作条款及少量近期事件。农田、其他主体历史、旧项目和建筑加工履历改为摘要或按需读取。读取工具仍访问完整原始快照，不以省略字段代表对象不存在。
- 寒暄或“你在做什么”直接依据当前活动回答，不要求先进行多轮市场分析。对话继续关闭扩展思考，执行结果仍由 Godot 验证后显示。

用原 trace 的一条对话测量，提示中的上下文从约 68,356 字符减为约 15,427 字符（约 77%）。这是该样本的测量，具体长度取决于当前项目和有效条款。
