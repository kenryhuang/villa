日期：2026-09-08。分支：`feature/3d-farm-preview`；基线提交 `9462470`，对应其上的工作区实现。状态：实现、领域集成和正式图形界面自动交互通过。

## 交付与账目规则

真实建筑持有稳定 `instance_id`、`owner_id` 和带版本的经营政策。玩家与 NPC 复用原库存、钱包及交易预留逻辑。费用表按建筑实例设置，允许选择开放配方、暂停对外营业及保留自用队列；空配方列表表示兼容原有“全部开放”，在 UI 中取消全部配方会同时关闭对外营业。

| 时点 | 客户 | 建筑所有者 | 成品 |
|---|---|---|---|
| 接受订单 | 扣实际原料，托管约定费用 | 尚未收入 | 尚未生产 |
| 实际开工 | 不再扣费 | 收取托管费用 | 随游戏时间加工 |
| 取消未开工订单 | 原料和托管费原数退回 | 没有收入 | 不生成 |
| 完成 | NPC 自动入库；玩家到建筑领取 | 不再收款 | 只归对应客户 |
| 自用 | 只扣原料 | 不发生给自己的转账 | 归自己 |

背包无法容纳退款时保留订单和托管，整理背包后可以重试；无法领取时保留客户成品。有租用订单或客户待领取成品时禁止拆除。只有所有者能改价、维修或申请拆除，维修继续使用原成本与维修计时。

存档版本更新为 6，继续读取 1～5 版本：没有产权字段的建筑默认归玩家，使用由类型和地块组成的稳定迁移 ID。旧租用单没有新托管字段，按“已经付款”继续交付，不重复向所有者付款，不凭空补出退款。损坏存档仍走原有初始开局策略。

## 验收结果

```powershell
.\tests\run_living_world_tests.ps1 -Stage P1 -IncludeDependencies
```

- P1 专项：60 项通过，涵盖玩家→NPC、NPC→玩家、NPC→NPC、所有者自用；真实 UI 下单；价格版本与旧订单锁价；费用不足、满背包、非法取货／改价／拆除；取消及重复取消；排队／运行／待领取／已取消／已交付读档；旧建筑及预付款订单迁移；NPC 自费维修。
- 原生产系统：407 项通过。测试中三条 dispatch／rollback 错误是已有故障注入测试的预期输出，运行器检查最终退出码及断言结果。
- 原 3D 风车：112 项通过；食品工坊：77 项通过。
- P0、Agent、服务端以及其他玩法回归见 [P0 报告](P0.md)。

经济核对示例：玩家排队支付 4 金币时，老李余额仍为 1000；取消后玩家金币与谷物完全恢复。老李调价到 9 后，新单开工余额变为 1009；运行中重载、交付均不重复收款。NPC 相互加工及 NPC 向玩家加工时，三个主体的钱包总和保持不变。原有预付款订单完成只增加客户面粉，不增加玩家金币。

## 试玩入口

```powershell
godot_console.exe --path . -- --living-world-scenario=P1
# 需要对话让 NPC 实际下单时，先运行 Agent 服务并添加：
godot_console.exe --path . -- --living-world-scenario=P1 --living-world-live-agents
```

开局预置两座完整风车，地块分别是 `(32,31)` 和 `(38,31)`，所有者分别是玩家、老李。点击老李的风车投入自己的谷物并支付加工费；关窗后等待加工，再回面板领取。点击自己的风车可打开“经营设置”。与阿禾或老李对话，可以让他们查询费表并租用建筑。确定性测试完整覆盖这些主体组合。

隔离场景不自动加载或覆盖正式存档，显式保存写入 `tmp/living-world/P1.json`。正常 F5 仍使用 `data/farm_3d_save.json`，不会向你的正式农场强行添加测试建筑。
