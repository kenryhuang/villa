### 实现边界

- `BuildingInstance` 接受有限的正负整数坐标，实际建筑占地仍由当前地图网格验证边界、重叠及地块状态，不以放宽坐标解析绕过这些检查。
- `data/cache/farm3d/` 存储可重建的网格和小地图底图，已加入Git忽略。缓存键包含地形、球场、网格、小地图实现及Godot版本；内容带校验摘要。缺失、损坏或实现变化均重新生成。缓存不包含作物、建筑、市场占地等动态状态；网格高度和坡度使用64位浮点保持原始结果。
- HUD与调试传送页共享静态底图，角色位置、方向和传送点击仍由各自控件处理。没有源脚本文件或缓存目录不可写时，仍能按原地形算法生成；导出包的持久缓存优化不在本次性能承诺内。
- `Farm3DSession.load_game()` 为同步读档建立准备作用域。完整验证通过后保留独立的事件存储、收件箱和投影候选；仅输入内容、角色身份与上下文一致时复用。发生篡改重新验证，提交或失败后清理候选，其他读档不会继承一次“验证通过”标记。
- 全部测量使用独立存档副本，原玩家存档和备份未被改写。

## 结论

启动主要耗在主线程的地图数据计算、小地图生成和 NPC 存档事件校验/重放。存档文件读取与 JSON 解析约 0.1 秒，首帧提交约 0.3～0.4 秒；这两项不是此次采样的主要瓶颈。

图形模式到首帧的两次新游戏采样为 **12.182 / 9.140 秒**，正常读档采样为 **12.960 / 14.447 秒**。新游戏本身已有明显启动成本，正常读档还需额外的 NPC 历史恢复工作。采样有系统负载波动，不能把单次总时长相减当作固定读档成本。

## 测量方法

- 使用正式 `scenes/farm3d/main.tscn`，默认36居民规模，保留项目图形设置；同时做无画面与图形模式验证。
- 在 `tmp/startup-profile/` 生成继承原脚本的临时计时脚本，不修改生产脚本。关键阶段通过原函数或原函数体执行，插入计时。测量脚本加载的额外开销约数十毫秒，计入总时长。
- 使用当前存档和 `.bak` 的独立副本，禁止自动保存和远程 Agent 请求。正常恢复用约7.43 MB的备份：第69天、3座建筑、2478条 Agent 历史事件。当前约7.47 MB存档有独立的校验失败，见下文。
- 计时从 Godot 启动计时器到场景初始化后首个 `frame_post_draw`；不含编辑器启动、资源首次导入、远程模型决策。图形进程以隐藏窗口启动。已有导入/驱动缓存，不能代表首次安装后的冷启动。
- 原始 JSON、stdout/stderr 日志及临时脚本在 `tmp/startup-profile/`，保持 Git 忽略。计时阶段存在父子嵌套，不能把所有日志行直接相加。

## 代码原因与优化顺序

1. **小地图重复生成。** `scripts/farm3d/farm_minimap.gd:148` 的 `_make_terrain()` 每实例遍历256×224像素，反复计算地形高度、阴影、水域和球场颜色。右下角HUD和 `scripts/ui/debug_panel.gd:147` 的传送页各创建一份。当前“缓存”只保存在实例内，两者不共享。优先共享静态底图，或烘焙为资源；调试页可首次打开时再创建。
2. **NPC事件重复校验与重放。** `scripts/farm3d/farm_session.gd:499` 调用 Agent 验证；`scripts/ai_agent/agent_runtime.gd:652` 的 `from_dict()` 再验证一次；`:746` 的正式恢复又重放全部事件。两次验证和一次恢复合计约3～4秒。应让校验生成可复用的候选状态，在全存档通过后一次性提交，保留完整性检查和失败原子性，不能简单删掉校验。
3. **静态地图数据每次重算。** `scripts/farm3d/flat_grid.gd:18` 为57,344格重新计算高度、坡度和地类，3D地形与小地图也访问相同地形函数。可将高度/坡度/基础地类烘焙或缓存，并对地形版本做失效处理，再叠加存档中的动态地块状态。
4. **首帧前串行完成全部工作。** `scripts/farm3d/main.gd:24` 顺序初始化地形、游戏系统、HUD、NPC。分阶段加载和进度画面可以改善等待反馈；只拆帧并不会减少总计算量。

## 单独发现：负坐标建筑导致当前存档被拒绝

采样副本中4座建筑逐一使用原 `BuildingInstance.from_dict()` 验证：

| 建筑 | 网格坐标 | 验证 |
| --- | --- | --- |
| 食品工坊 | (20, 19) | 通过 |
| 风车 | (25, 24) | 通过 |
| 蜂箱 | (29, 9) | 通过 |
| 蜂箱 | (-2, 0) | 拒绝 |

`scripts/buildings/building_instance.gd:606` 的 `_is_grid_coordinate()` 仍要求坐标≥0，而扩展后的3D地图允许负网格坐标。于是 `Farm3DSession._valid_save()` 在建筑恢复校验处返回失败，启动打印“Farm save could not be loaded; starting a fresh farm”，退回第1天、0建筑。本次当前存档副本的图形启动耗时10.387秒，**这是失败回退耗时，不是成功读档耗时**。

该问题应优先修复，并用扩展地图边界验证负坐标，而不是删除存档里的建筑。正式启动回退后自动保存仍开启，后续自动保存可能覆盖原文件；本次测量已隔离副本，未触碰原存档或备份。

以上为优化前诊断；修复、优化后的实测及回归结果见本文开头。3D地形网格/碰撞烘焙与加载进度画面未在本次实现。
