# 单击砍树与树木倒地动画正式设计

日期：2026-08-04  
状态：已确认  
关联设计：`docs/superpowers/specs/2026-08-04-manual-gathering-design.md`

## 1. 目标

本次修改将砍树从“同一棵树需要重复点击五次”改为“一次点击、一次完整动作、整棵树完成砍伐”。同时修正斧头悬浮在角色上方的问题，补齐与现有手绘 2D 树木一致的砍痕、倾倒和树桩素材，并让玩家在斧头选中时通过绿色/红色标识提前判断树木能否砍伐。

矿石继续保持每次采集 1 单位和 1.2 秒动作，不在本次修改范围内。

## 2. 可砍树种

仅下列 5 个树种可砍，且地图上的所有对应实例均可砍：

| 资源标识 | 中文名称 |
|---|---|
| `pine-small` | 小松树 |
| `pine-tall` | 高松树 |
| `canopy-small` | 小冠树 |
| `canopy-medium` | 中冠树 |
| `round-small` | 小圆冠树 |

`fruit`、`oak-large`、`pine-large`、`round-medium` 和 `yellow` 保持装饰用途，不进入采集、刷新和资源存档。

可砍资格由树种白名单决定，不再由树木是否位于旧资源林区域决定。既有稳定树木 ID 继续作为存档键；新纳入采集的散布树第一次读取旧存档时使用完整容量默认值。

## 3. 斧头悬停判定

斧头槽位处于选中状态时，指针射线可以识别所有站立树木：

- 可砍树：树根处显示半透明绿色圆环；
- 不可砍树：树根处显示半透明红色圆环；
- 指针移出树木、取消工具、切换工具、进入建造模式、打开遮挡输入的 UI 或开始砍伐时隐藏圆环；
- 点击红色树不启动寻路、不切换资源状态、不消耗体力或耐久，并显示“此树不可砍伐”。

颜色只表达树种和当前树木状态是否允许砍伐。背包空间、体力和耐久仍由点击后的事务预检给出明确文字原因，避免红色同时代表多个不可区分的错误。

所有树保留实体树干碰撞。不可砍树只开放指针悬停/点击判定层，不注册为采集资源或 A* 动态资源；其实体阻挡继续按装饰树处理。

## 4. 单击砍倒与经济结算

新鲜树木容量仍为 5，刷新周期仍为 3 天。一次成功动作的结果为：

- `remaining_units: 5 -> 0`；
- 玩家背包增加 `wood ×5`；
- 扣除 8 体力；
- 扣除 1 点斧头耐久；
- 释放动作时钟锁后推进 10 游戏分钟；
- 树木进入树桩状态并设置 `respawn_day = 当前总天数 + 3`。

旧存档中已经部分砍伐的可砍树，一次动作只获得其 `remaining_units`，随后进入树桩状态，避免重复产生已经取得的木材。新系统正常运行后不会再产生新的部分树木状态。

预检必须验证背包能一次容纳完整奖励数量。背包不足、体力不足、斧头损坏、目标变化、玩家取消或资源提交失败时，资源、背包、体力、耐久、时间和对外事件全部保持不变。

`ToolSystem` 继续使用同一原子事务入口，但奖励数量改为采用目标预览返回值。矿石目标仍返回数量 1，因此其行为不变。

## 5. 两秒砍倒流程

树木动作总时长为 2.0 秒，矿石动作维持 1.2 秒。控制器从目标查询动作时长，进入动作状态后继续持有现有拥有者式时钟锁。

| 时间 | 表现 |
|---:|---|
| 0.00–0.65 秒 | 第 1 帧：根部出现砍口，树冠轻微摇晃；斧头第一次命中并产生少量木屑 |
| 0.65–1.35 秒 | 第 2 帧：砍口扩大，树身向远离角色的一侧明显倾斜；斧头再次命中 |
| 1.35–2.00 秒 | 第 3 帧：树木接近倒地，落地产生较明显木屑和短促回弹 |
| 2.00 秒 | 原子提交成功后切换为对应树种的手绘树桩；显示实际产出与刷新日 |

倾倒方向根据屏幕空间中角色相对树木的位置决定：树木始终向角色的反方向倒下。三张砍倒帧以一个标准方向绘制，运行时通过水平翻转复用另一方向。

取消发生在事务提交前时，树木平滑恢复原始贴图、位置、缩放和调制颜色，砍倒帧与木屑被清理，不留下部分视觉状态。

## 6. 斧头位置

斧头只在树木动作中使用树根锚点：

- 锚点位于树木根部朝向角色的一侧；
- 水平距离树干中心约 0.45 米；
- 离地约 0.20 米；
- 斧柄末端仍是旋转圆心；
- 斧头命中阶段的斧刃与树干低处砍口重合。

镐子继续使用当前角色侧挂点，不受本次斧头定位修改影响。

## 7. 美术资产

每个可砍树种制作一张透明背景的横向状态图集，包含 4 个等宽单元：

1. 砍倒第 1 帧；
2. 砍倒第 2 帧；
3. 砍倒第 3 帧；
4. 最终树桩。

共 5 张状态图集、20 个状态单元。路径约定：

```text
assets/vegetation/felling/<variant>-felling-sheet.png
```

素材要求：

- 透明背景、正交/等距游戏视角；
- 与对应原树贴图保持树冠、树皮、根系、光源方向、边缘柔度和色彩饱和度一致；
- 三个砍倒帧保持根部像素锚点一致，避免切帧跳动；
- 树桩保留可读的年轮、暖棕色树皮和外露根系，不使用灰色程序几何体；
- 图集单元不得互相重叠，四周保留透明安全边距。

运行时使用 `AtlasTexture` 切分图集，不生成额外运行时图片。若图集缺失或尺寸非法，树木保持原始站立贴图并拒绝进入砍伐动作，同时输出明确错误，不回退到灰色几何树桩。

## 8. TreeInstance 表现接口

`TreeInstance` 保存树种 `variant` 和对应状态图集，并提供以下职责明确的接口：

- 查询是否属于可砍白名单；
- 返回本次完整奖励数量和 2 秒动作时长；
- 开始砍倒并记录倾倒方向；
- 按归一化进度切换 3 个砍倒帧；
- 取消时恢复站立状态；
- 提交后显示图集中的树桩单元；
- 刷新时恢复原始树贴图和实体/交互阻挡。

表现接口只响应控制器信号，不自行发放物品或推进时间。资源与经济提交仍由 `ToolSystem` 和 `GatheringController` 负责。

## 9. UI 反馈

- 目标剩余量在动作开始时显示 `5/5`；旧部分树显示实际剩余量；
- 圆形进度使用 2 秒树木动作时长平滑扫过；
- 成功飘字使用事务实际数量，例如“+5 木材”或旧存档的“+3 木材”；
- 树桩结果继续附带“第 N 天刷新”；
- 不可砍树点击显示“此树不可砍伐”。

## 10. 存档迁移

本次不改变资源存档版本和树木容量字段。迁移规则为：

- 仍在白名单内的旧树记录原样恢复剩余量和刷新日；
- 新纳入采集的稳定树 ID 缺少记录时使用完整容量；
- 旧资源林中不再可砍的 `round-medium` 和 `fruit` 树记录被识别并安全丢弃，不得导致整个存档加载失败；
- 非树资源记录和既有 v1→v2 迁移规则保持不变。

## 11. 测试与验收

自动测试覆盖：

- 白名单 5 个树种所有实例可砍，其他 5 个树种不可砍；
- 斧头悬停绿色/红色、移出和切换模式隐藏；
- 红色树点击不移动、不消耗并显示稳定错误；
- 新鲜树一次获得 5 木材，树直接变为 0 单位；
- 旧部分树只获得剩余数量；
- 一次动作只扣 8 体力、1 耐久和 10 游戏分钟；
- 背包只能容纳少于完整奖励时，移动前拒绝且无部分结算；
- 2 秒进度边界对应三张砍倒帧，倾倒方向远离角色；
- 取消恢复站立帧，成功显示手绘树桩，刷新恢复原树；
- 旧的 `round-medium`/`fruit` 资源记录不会阻断加载；
- 石材和矿石仍为 1.2 秒、单次 1 单位。

视觉捕获覆盖 1280×720、1920×1080 和 3000×2000：绿色可砍、红色不可砍、斧头根部命中、三个砍倒阶段、左右倾倒、最终树桩、`+5 木材` 和旧部分数量。逐图检查透明边缘、切帧跳动、树根锚点、斧刃接触位置、文字遮挡和树桩画风。

## 12. 完成定义

- 玩家选中斧头后能在点击前可靠区分可砍与不可砍树；
- 可砍树一次点击、2 秒后完成砍倒并获得完整剩余木材；
- 斧头与砍痕位于树根上方的真实伐木位置；
- 5 个树种各自拥有 3 个砍倒帧和对应手绘树桩；
- 所有失败和取消保持原子性；
- 旧存档安全读取，矿石和其他玩法无回归；
- 自动测试、三分辨率视觉捕获和人工 review 全部通过。
