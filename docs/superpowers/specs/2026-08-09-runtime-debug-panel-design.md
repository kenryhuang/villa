# Villa 运行时调试面板设计

**日期：** 2026-08-09

**状态：** 已确认

**范围：** Debug 构建中的角色等级、已过天数、金币、体力与库存物品编辑

## 1. 目标

为功能验证提供一个只在 Debug 构建中可用的运行时面板。测试人员无需重新开档、等待游戏时间或反复采集，即可把角色与库存调整到目标状态。

已确认的行为：

- 采用独立 `DebugPanel` 场景，不继续扩大 `hud.gd` 的职责。
- 修改只作用于当前运行状态；点击“应用”不会立即写入存档，之后若触发正常存档则按现有规则保存。
- 已过天数使用直接跳转，不逐日结算跳过的市场、NPC、作物、生产和资源刷新。
- 面板只能在 `OS.is_debug_build()` 为真时显示和执行命令。

## 2. 非目标

第一版不包含：

- 建筑生成、删除或完成施工；
- 作物状态、市场价格、NPC 状态或生产队列编辑；
- 调试命令历史、脚本控制台或预设管理；
- 自动保存调试修改；
- Release 构建中的隐藏快捷键或后门。

## 3. 入口与布局

HUD 右上角保留现有“重置存档”按钮，并增加同尺寸“调试”按钮。两个按钮放入统一的横向容器，避免覆盖市场与通知入口。

点击“调试”后打开居中模态面板。面板使用当前经济 UI 的扁平化风格：圆角外框、细边线、紧凑间距；内部 Tab 标题大小一致，选中 Tab 与内容面板视觉连接。

```text
┌ 调试数据                                      [×] ┐
├ [角色状态] [资源库存] ───────────────────────────┤
│                                                   │
│  当前 Tab 内容                                    │
│                                                   │
├ 状态／校验错误                  [刷新] [取消] [应用] ┤
└───────────────────────────────────────────────────┘
```

面板目标尺寸约为视口的 58%×72%，并限制最大宽度，避免遮住全部 HUD。Esc、关闭按钮和“取消”均直接关闭，不应用未提交输入。

### 3.1 角色状态 Tab

角色状态采用两列对齐表单：

| 字段 | 控件 | 范围与语义 |
|---|---|---|
| 等级 | `SpinBox` | 1～`PlayerState.LEVEL_THRESHOLDS.size()` |
| 已过天数 | `SpinBox` | 0～经济系统安全日期上限；游戏第一天对应 0 |
| 金币 | `SpinBox` | 0～安全整数上限 |
| 当前体力 | `SpinBox` | 0～最大体力 |

设置等级时同时把经验值调整到该等级的最低阈值，确保等级与经验条一致。最大等级使用最后一个阈值。

### 3.2 资源库存 Tab

资源页读取 `GameData.get_all_items()`，因此新增物品会自动出现在面板中。顶部提供名称搜索和分类筛选；列表按“分类、显示名称、ID”稳定排序。

每行显示：

- 中文名称；
- 内部物品 ID，使用较弱的次级文字；
- 当前编辑数量；
- 数量 `SpinBox`，范围为 0～该物品单堆叠上限乘以背包槽位数。

数量 0 表示完全移除该物品。列表使用虚拟化或可滚动容器，不扩大整个模态面板。搜索和筛选只影响显示，不丢弃未提交编辑。

## 4. 组件与职责

### 4.1 `DebugPanel`

建议文件：

- `scenes/ui/debug_panel.tscn`
- `scripts/ui/debug_panel.gd`

职责：

- 展示由外部注入的只读快照；
- 管理表单、搜索、分类、未提交草稿与本地格式校验；
- 发出 `apply_requested(draft)`；
- 显示应用成功或失败信息；
- 不直接读取或修改 `GameState`、`SeasonSystem` 或 `InventorySystem`。

### 4.2 `DebugStateEditor`

建议文件：`scripts/debug/debug_state_editor.gd`。

该组件只在 Debug 构建中由 `Main` 创建并注入权威系统引用。它提供：

```text
configure(...systems) -> bool
snapshot() -> Dictionary
validate(draft) -> Dictionary
apply(draft) -> Dictionary
```

职责：

- 从权威系统构建面板快照；
- 验证等级、日期、金币、体力、物品 ID、数量与背包容量；
- 原子应用角色、日期和库存修改；
- 在任何步骤失败时恢复应用前快照；
- 发出已有 EventBus 信号，使 HUD、背包和经济界面刷新。

### 4.3 `Main` 与 HUD

`Main` 只负责 Debug 组件的创建、依赖注入和信号转发。HUD 只增加面板入口信号与按钮可见性配置，不承担状态编辑逻辑。

## 5. 数据应用规则

### 5.1 原子验证

点击“应用”先完成全部预检，再修改任何状态：

1. 所有数字必须为范围内整数。
2. 所有物品 ID 必须仍存在于 `GameData`。
3. 每个物品数量必须能拆分为合法堆叠。
4. 非零物品所需槽位总数不得超过当前 `InventorySystem.max_slots`。
5. 日期必须位于经济系统安全日期范围。

验证失败时不应用任何字段，并在底部显示具体原因，例如“资源需要 24 个背包槽位，当前只有 20 个”。

### 5.2 等级、经验、金币和体力

- `player_state.level` 写入目标等级。
- `player_state.exp` 写入该等级的最低经验阈值。
- `GameState.gold` 写入目标金币。
- 当前体力写入 0～`max_stamina` 的已验证值。
- 成功后发出 `level_changed`、`exp_gained(0)`、`gold_changed` 和 `stamina_changed`。

### 5.3 已过天数

面板字段表示已完整过去的天数：

```text
target_total_days = elapsed_days + 1
current_day = elapsed_days % 7 + 1
current_season = floor(elapsed_days / 7) % 4
```

小时和分钟保持不变。直接跳转不调用 `DailySimulationSystem.run_day()`，不补算市场历史、NPC 行为、作物成长、资源重生或生产时间。

为防止下一次自然跨日出现游标错位，应用时同步：

- `DailySimulationSystem.last_simulated_day`；
- `MarketSystem.last_settled_day`；
- `NpcEconomySystem.sync_daily_cursor()`；
- `ProductionSystem.sync_daily_cursor()`；
- 世界资源节点的日期游标，同时保留当前资源剩余量和耗尽状态。

所有游标同步完成后再发布一次日期刷新信号。由于每日模拟游标已等于目标日，该信号只刷新界面和日期相关提示，不执行目标日结算。

### 5.4 库存替换

资源编辑采用完整目标库存，而不是逐项增减：

1. 按稳定物品 ID 顺序把数量拆分为合法堆叠。
2. 未使用的背包槽补为空字典。
3. 仍存在的快捷栏物品映射到该物品的新首个槽位。
4. 已被清零的快捷栏物品解除映射。
5. 一次调用 `InventorySystem.restore_state()` 替换状态。

应用后发出各物品的增减差额事件，并刷新 HUD 材料计数、建造可用性、种植快捷栏和背包界面。

## 6. 交互反馈与错误处理

- 打开面板时自动获取最新快照。
- “刷新”丢弃草稿并重新读取当前运行状态，面板保持打开。
- 有未提交修改时，在标题旁显示“未应用”。
- 应用成功后保留面板并重新读取快照，底部短暂显示“调试数据已应用；尚未写入存档”。
- 应用失败时保留输入，聚焦第一个无效字段。
- 系统未配置、日期同步失败或库存恢复失败时回滚全部字段并显示错误，不允许部分成功。
- 打开调试面板时不暂停游戏；编辑中的草稿不会随运行状态自动变化，点击“刷新”才能更新。

## 7. 安全边界

- HUD 按钮在非 Debug 构建不可见。
- `DebugStateEditor.configure()` 和 `apply()` 在非 Debug 构建直接返回失败。
- Release 场景可以包含面板资源，但 `Main` 不实例化、不连接，也不存在可触发的输入路径。
- 面板不直接调用 `SaveManager.save_game()`。
- 日志只记录字段类型与结果，不输出完整存档或用户路径。

## 8. 测试与验收

按 TDD 顺序实现。自动测试至少覆盖：

1. Debug 面板场景可实例化，两个 Tab、搜索、列表、表单和应用按钮存在。
2. HUD 只在允许时显示“调试”入口并只发出一次打开请求。
3. 快照正确读取等级、已过天数、金币、体力和全部物品数量。
4. 等级写入同时修正经验阈值，并更新 HUD。
5. 已过天数 0、跨季节和跨年度映射正确。
6. 日期直接跳转同步每日模拟、市场、NPC、生产和资源游标，但不调用逐日结算。
7. 合法库存按最大堆叠拆分，数量 0 移除物品，快捷栏映射保持或解除正确。
8. 超容量、未知物品、负数、越界等级和越界日期全部拒绝，且任何权威状态都不变化。
9. 应用成功不会调用保存接口。
10. Release 条件下入口隐藏且编辑器拒绝应用。

视觉验证覆盖 1920×1080、1280×720 和项目默认大视口，确保：

- 面板居中且不超出视口；
- 表单标签、输入框和按钮基线对齐；
- 资源长名称与内部 ID 不重叠；
- 列表滚动时底部操作栏保持可见；
- 面板关闭后 HUD 与世界交互恢复正常。

## 9. 验收标准

- Debug 构建可从 HUD 一步打开面板。
- 能在一次应用中设置等级、已过天数、金币、体力及任意合法库存组合。
- 应用后 HUD、背包和相关系统立即显示新状态。
- 日期跳转不产生跳过日期的市场、NPC、作物、生产或资源结算。
- 任何失败都不产生部分修改。
- 点击应用不会立即改写当前存档。
- 非 Debug 构建没有可用入口，也不能通过脚本调用成功应用。
