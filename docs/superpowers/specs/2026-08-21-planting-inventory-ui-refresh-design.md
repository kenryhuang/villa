# 播种库存事件 UI 刷新优化设计

## 背景

玩家每次播种都会从背包扣除一颗种子并发布 `item_removed`。当前多个已实例化但不可见的 UI 仍响应该事件，重建种子列表、市场快照、订单、合同及相关控件。诊断显示作物首阶段视觉的载入与实例化只占十几毫秒；持续卡顿主要来自库存事件触发的隐藏 UI 工作，且市场页的延迟刷新最重。

## 目标

- 播种路径不再同步或在紧随其后的帧中重建不可见 UI。
- 当前可见的相关面板仍能及时反映库存变化。
- 隐藏面板重新打开或切换到对应页签时显示最新权威数据。
- 保持播种事务、种子扣除顺序、`item_removed` 和控制器 `inventory_changed` 的现有语义。

## 非目标

- 不异步化作物场景或贴图加载。
- 不改变库存系统、播种提交和回滚逻辑。
- 不重构经济中心的页面结构。
- 不以固定毫秒阈值作为自动化测试条件。

## 方案

采用“隐藏时标脏、可见时合并刷新、进入时强制刷新”的策略。

### 刷新状态

受库存事件影响的面板维护一个轻量刷新状态：

- 面板不可见时，事件处理器只记录待刷新状态，不创建控件、不查询完整快照。
- 面板可见时，同一帧内的多次事件通过一次 deferred 调用合并为一次刷新。
- 面板打开、重新显示或所属页签被选中时，读取权威系统并刷新，随后清除待刷新状态。

### 涉及组件

- `SeedSelectorPanel`：关闭状态下不重建种子行；下次 `open_for_cell` 时刷新完整列表。打开状态下库存事件合并刷新。
- `MarketPanel`：不可见时跳过权威快照重建；所属页面重新显示时刷新。
- `OrderPanel` 与 `ContractPanel`：不可见时只标脏；重新显示或被选为当前页面时刷新。
- `TradePanel`：沿用同一刷新门控规则，避免隐藏交易页处理与当前交易无关的播种扣减。
- `ShopUI`：作为页面切换入口，在打开窗口和切换页签时显式刷新当前页面，保证隐藏期间的数据变化不会造成陈旧显示。

已经具备隐藏门控的服务页、建筑生产页和建筑状态页保持现状，仅通过回归测试确认未退化。背包界面已有 `_is_open` 判断，也保持现状。

## 数据流

1. 播种成功并提交作物视觉。
2. 控制器发布一条种子 `item_removed`，并保留现有 HUD/快捷栏通知。
3. 不可见面板仅记录待刷新；当前可见面板排队一次合并刷新。
4. 当前操作帧结束，不执行隐藏面板的控件树重建。
5. 玩家以后打开经济中心、种子选择器或切换页签时，该页从权威库存和经济系统重新构建内容。

## 正确性与失败处理

- UI 的刷新标记不是业务状态；权威状态始终来自库存、市场、订单和合同系统。
- 面板离开场景树时取消待执行的刷新状态，避免延迟回调访问已释放节点。
- 多个事件到达时只保留一个刷新请求；刷新失败或依赖尚未配置时不修改业务数据，并在下一次显示时再次读取。
- 不阻断或吞掉 `item_removed`，因此 HUD、存档相关状态和非 UI 消费者保持原行为。

## 测试策略

先增加失败测试，再修改实现：

- 关闭的种子面板收到种子减少事件时不重建行；重新打开后数量正确。
- 隐藏的市场、订单、合同和交易页面收到库存事件时不执行完整刷新。
- 页面重新显示或被选中后读取最新库存及权威快照。
- 可见面板在同一帧收到多个事件时只刷新一次。
- Main 播种集成测试验证作物与库存立即提交，同时隐藏 UI 没有在播种调用或紧随帧中重建。
- 运行种子选择、经济 UI、操作模式、作物经济及核心回归套件，确认事件语义未被改变。

## 验收标准

- 每次播种立即完成，不再出现由隐藏 UI 引起的数秒停顿。
- 播种后种子数量、作物视觉和 HUD 数量正确。
- 打开任何受影响页面时内容与权威状态一致。
- 自动化测试不依赖机器性能计时，而是验证不必要刷新没有发生。
