# 作物收割、入仓与复耕设计

## 目标

在现有种植生命周期之上补齐玩家可感知、可验证的收割闭环：玩家在 P 种植模式中点击成熟作物完成收割，产物进入农场中央仓库，一年生作物所在土地恢复为可再次播种的耕地，多年生作物保留植株并进入下一轮生长。

本次改动以现有原子收割事务为基础，不重写已存在的产量计算、仓库或作物生命周期系统。重点是完善收割交互、消息反馈、视觉刷新和覆盖全部实际作物配置的回归测试。

## 已有基础

当前实现已经具备以下能力：

- `FarmingSystem.preview_harvest()` 只为成熟作物生成确定性收割预览，预览包含产物、经验和收割后的地块快照。
- `PlayerActionController._harvest()` 协调 `FarmStorageSystem` 与 `FarmingSystem` 的原子事务。
- 农产品进入 `FarmStorageSystem`，种子、工具和其他普通物品仍由随身背包管理。
- 仓库容量不足会在变更作物前拒绝事务，并给出 `storage_capacity` 与 `missing_capacity`。
- 一年生作物收割后变为 `FARMLAND`；`annual_regrow`、`bush`、`tree` 和 `vine` 保持 `PLANTED` 并重置到再生进度。
- 仓库变更事件已经能够驱动仓库界面刷新。

因此本次设计不建立第二条收割路径，也不允许 UI 直接修改作物或仓库数据。

## 收割交互

收割遵循以下规则：

1. 玩家进入 P 种植模式。
2. 鼠标指向成熟作物时，地块呈现可操作高亮，并显示临时提示“点击收割”。
3. 玩家左键点击该地块，`PlayerActionController.perform_cell_action()` 优先执行成熟作物收割，不要求选择镰刀，也不受当前锄头或种子槽位影响。
4. 鼠标移开后临时提示自动消失。
5. 未成熟作物不产生收获，也不改变土地、作物、仓库或经验状态。

收割优先级必须保持高于同一地块上的锄地和播种动作，避免玩家选中种子时误把成熟植株覆盖掉。

## 收割后的生命周期

| 生命周期类型 | 收割后地块状态 | 收割后作物 | 后续行为 |
| --- | --- | --- | --- |
| `annual` | `FARMLAND` | 清除 | 保持已耕视觉，可直接再次播种 |
| `annual_regrow` | `PLANTED` | 保留 | 回到再生进度，继续生长 |
| `bush` | `PLANTED` | 保留 | 回到再生进度，继续生长 |
| `tree` | `PLANTED` | 保留 | 回到再生进度，继续生长 |
| `vine` | `PLANTED` | 保留 | 回到再生进度，继续生长 |

多年生与可再生作物沿用 `CropData.regrow_days` 和当前 `FarmingSystem.preview_harvest()` 的进度计算，不新增隐藏的固定生长天数。每次成功收割只增加一次 `harvest_count`。

## 原子事务流程

一次收割按照以下顺序执行：

1. `FarmingSystem` 根据当前地块生成收割预览，包括实际产量、经验、收割后状态和原始快照。
2. `PlayerActionController` 规范化产物映射，并通过 `FarmStorageSystem.get_missing_capacity()` 预检完整产量。
3. 容量充足时开启仓库原子事务并暂存全部产物。
4. 准备并应用 FarmingSystem 收割事务，在同一事务中更新地块、作物生命周期、经验和视觉所依据的状态。
5. 两侧事务都成功封装且可发布后，再一起进入提交状态并发布事件。
6. 提交成功后清除上一次操作失败信息，并基于已提交预览发布成功反馈。
7. 任一准备、应用、封装或提交点前检查失败时，回滚仓库、作物与经验快照，不发送成功消息。

不允许拆分成“先清除作物，再尝试入仓”的顺序流程。任何失败都必须满足：产物没有增加、作物没有消失、土地没有变化、经验没有增加、成功事件没有发布。

## 仓库容量

收获的全部产物统一进入农场中央仓库。一次收割不可部分入仓：即使仓库只能容纳部分产量，也必须阻止整个收割。

容量不足时保留现有稳定失败原因：

```text
reason = storage_capacity
missing_capacity = 本次完整入仓仍缺少的数量容量
```

这里的容量按物品数量计算，不称为“背包格子”或“仓库格子”。

## 玩家反馈

所有持久提示进入右侧消息面板，不在 HUD 顶部额外显示文本。

成功收割消息使用作物的本地化显示名称与实际入仓数量：

```text
收获胡萝卜 ×3，已入仓
```

如果一次预览未来包含多种产物，消息按稳定顺序列出所有“名称 ×数量”，不得只显示第一项。

仓库容量不足时显示：

```text
仓库容量不足，还需 2 容量
```

其他事务失败显示通用失败信息，但不得声称已经入仓。未成熟作物的普通悬停和点击不持续写入消息流，避免产生通知噪声；可操作提示只作为鼠标悬停临时提示存在。

## 视觉与界面刷新

- 一年生作物成功收割后立即移除作物视觉，保留已耕地块视觉。
- 多年生与可再生作物成功收割后立即刷新到对应的再生阶段视觉，不保留成熟外观。
- 回滚后恢复收割前视觉，不能只恢复数据而留下错误模型。
- `FarmStorageSystem` 只在事务成功提交后发布数量与容量事件。
- 仓库界面处于打开状态时，通过既有事件订阅立即刷新数量和已用容量；关闭状态下不需要创建额外 UI 实例。
- 收割成功与失败消息通过既有 HUD 消息流入口发布，保持消息面板的滚动、折叠和透明度行为不变。

## 数据与存档

本次不增加新的存档字段。收割后的 `GridCell`、`CropInstance`、仓库数量、`harvest_count` 和生长进度继续通过现有存档结构持久化。

加载后必须满足：

- 已收割的一年生地块仍是可播种的 `FARMLAND`，不存在作物实例。
- 已收割的可再生作物保留正确的生命周期、再生进度与收割次数。
- 已入仓产物数量与收割提交后的数量一致。

## 测试与验收

自动化测试至少覆盖：

- P 模式下，无论当前选择锄头还是种子，点击成熟作物都优先收割。
- 成熟一年生作物按预览产量进入中央仓库，不进入背包；经验只增加一次；地块变为 `FARMLAND` 且作物为空。
- `annual_regrow`、`bush`、`tree`、`vine` 收割后产物入仓，地块保持 `PLANTED`，植株进入正确再生进度且 `harvest_count` 增加一次。
- 未成熟作物不可收割，所有权威状态保持不变。
- 容量刚好足够时允许完整收割；少一个容量时阻止完整收割，并准确返回 `missing_capacity`。
- 注入仓库暂存失败、作物应用失败及封装失败时，仓库、作物、土地、经验、事件和视觉全部回滚。
- 成功消息包含正确显示名称与实际产量；容量失败消息包含准确缺口；失败时不发布成功消息。
- 仓库界面打开时随成功提交刷新，失败事务不触发虚假刷新。
- 保存并加载一年生收割结果和可再生作物收割结果后，状态保持一致。
- 遍历所有实际 `CropData`，验证生命周期类型属于支持集合、`crop_id` 可路由到农场仓库、产量有效且成熟作物可以生成非空收割预览。

手工验收流程：进入 P 模式，分别收割一种成熟一年生作物和一种成熟多年生作物，确认右侧消息、仓库数量、地块视觉和再次播种/再生行为；随后填满仓库重试，确认作物完整保留且提示准确。

## 不在本次范围

- 新增镰刀、收割动画、粒子、音效或角色寻路。
- 自动收割、范围收割或批量收割。
- 修改产量平衡、品质系统、售价或经验数值。
- 修改仓库基础容量或建筑加成公式。
- 为作物增加新的生长阶段或重新制作美术素材。
- 改变 N 调试推进生长的职责。
