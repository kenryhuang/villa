# 建造材料与失败反馈设计

## 1. 目标

为主游戏建造流程补齐清晰、统一的资源与失败反馈：

- 顶部始终显示木材、石头、铁和玻璃的当前数量。
- 建造快捷栏提供完整成本与材料缺口信息。
- 材料不足时，建筑按钮对鼠标和数字快捷键都不可选。
- 放置失败时显示具体中文原因。
- debug 构建记录可检索的失败日志，正式发布版本不输出。
- 预览颜色、按钮状态、Toast 和日志使用同一套放置规则。

本次不改变建筑成本、占地尺寸、允许建造的格子状态、施工阶段或存档格式。

## 2. 当前问题

当前 HUD 没有展示四种建造材料的具体库存。建筑快捷栏 tooltip 能显示成本，但快捷卡材料不足时只将图标变灰，没有真正禁用按钮。`BuildingSystem.can_place()` 只返回布尔值，调用方无法区分越界、道路、占用、无效地形或材料不足。

因此玩家无法可靠判断：

- 当前持有多少建造材料。
- 某种建筑需要哪些材料。
- 建筑按钮为什么变灰。
- 红色预览具体被什么条件阻止。
- 连续建造为什么突然失败。

## 3. 设计原则

### 3.1 单一规则来源

`BuildingSystem` 是放置规则的唯一事实来源。HUD、玩家控制器和日志系统不复制边界、地块状态或材料判断。

### 3.2 结构化失败信息

失败原因使用稳定的英文代码传递，中文文案在诊断结果中生成并供 HUD 展示。测试以代码和结构化字段为主，不依赖完整中文文案。

### 3.3 操作触发反馈

预览移动只更新颜色和诊断缓存，不打印日志或反复弹 Toast。只有实际点击放置或尝试通过快捷键选择不可用建筑时，才触发玩家提示与 debug 日志。

## 4. 放置诊断

`BuildingSystem` 新增 `diagnose_placement(building, gx, gz)` 结构化放置诊断接口。诊断结果使用字典，至少包含：

```gdscript
{
    "allowed": false,
    "code": "road",
    "message": "无法建造谷仓：目标区域包含道路",
    "building_id": "barn",
    "grid": Vector2i(12, 8),
    "missing_resources": {},
    "blocked_cell": {
        "grid": Vector2i(13, 8),
        "state": GridCell.State.ROAD,
    },
}
```

材料不足时，`missing_resources` 按材料 ID 记录需求量、持有量和缺口：

```gdscript
{
    "wood": {
        "required": 100,
        "available": 42,
        "missing": 58,
    },
}
```

新增 `try_place_building(building, gx, gz)` 事务接口，返回：

```gdscript
{
    "placed": false,
    "instance": null,
    "diagnostic": placement_diagnostic,
}
```

现有 `can_place()` API 保留，并改为返回诊断结果中的 `allowed`。现有 `place_building()` API 也保留，并作为兼容包装调用 `try_place_building()` 后继续返回 `BuildingInstance` 或 `null`。事务接口在提交前重新诊断，防止预览与点击之间状态发生变化。

### 4.1 失败代码

| 代码 | 含义 | 玩家文案示例 |
|---|---|---|
| `invalid_building` | 建筑 ID、数据或场景无效 | 无法建造：建筑数据无效 |
| `system_unavailable` | 网格、经济系统或容器未配置 | 建造系统尚未就绪 |
| `out_of_bounds` | footprint 超出地图 | 无法建造谷仓：目标区域超出地图范围 |
| `invalid_terrain` | 占地格高度不是有限值 | 无法建造谷仓：目标地形无效 |
| `road` | footprint 包含道路 | 无法建造谷仓：目标区域包含道路 |
| `occupied` | footprint 包含已有建筑 | 无法建造谷仓：这里已经有建筑 |
| `planted` | footprint 包含作物 | 无法建造谷仓：地块上仍有作物 |
| `water` | footprint 包含水域 | 无法建造谷仓：水域不能建造 |
| `decoration` | footprint 被装饰占用 | 无法建造谷仓：目标区域被装饰占用 |
| `invalid_cell_state` | 其他不可建造格子状态 | 无法建造谷仓：该地块不能建造 |
| `insufficient_resources` | 一种或多种材料不足 | 无法建造谷仓：木材还缺 58 |
| `grid_commit_failed` | 提交时网格修改失败 | 建造提交失败，请重试 |
| `resource_commit_failed` | 提交时材料扣除失败 | 建造提交失败，请重试 |

诊断顺序为：

1. 建筑数据和系统依赖。
2. footprint 边界。
3. 地形高度。
4. 地块状态。
5. 材料。

提交阶段失败不属于预览诊断，由 `try_place_building()` 生成相应提交失败结果并保持现有原子回滚。

## 5. 系统职责与数据流

### 5.1 BuildingSystem

- 解析建筑数据。
- 生成放置诊断。
- 提供材料缺口数据。
- 保持 `can_place()` 与诊断结果一致。
- 在提交前重新验证。
- 提交失败时保留原子回滚，并生成明确失败结果。
- 保持旧的 `place_building()` 返回值契约。

预览移动仍使用现有信号，不承担玩家提示职责。`BuildingSystem` 不直接触发玩家 Toast，避免程序化放置或存档恢复产生界面反馈。

### 5.2 PlayerActionController

- 建造模式选择建筑前检查材料。
- 材料不足时拒绝鼠标和数字快捷键选择。
- 地图点击通过 `try_place_building()` 获得实例和最新诊断。
- 发出统一的 `build_feedback_requested(message, details)` 信号。
- 仅在 `OS.is_debug_build()` 为真且用户实际操作失败时打印日志。
- 成功放置后决定是否恢复连续预览。

### 5.3 HUD

- 监听库存物品增减事件。
- 刷新顶部材料数量。
- 刷新建筑按钮的禁用和灰化状态。
- 刷新建筑 tooltip 与选中成本信息条。
- 监听 `build_feedback_requested` 并显示 Toast。
- 不实现放置规则。

## 6. 顶部材料栏

在现有顶部状态栏下方增加独立材料条，不缩小当前体力、金币、等级、经验、季节和时间显示。

材料条始终显示：

```text
[木材图标 250] [石头图标 150] [铁图标 50] [玻璃图标 50]
```

规则：

- 顺序固定为木材、石头、铁、玻璃。
- 只显示本地图标与数值，不显示材料名称。
- 不依赖系统 Emoji 字体。
- 图标 tooltip 显示材料中文名称。
- 数量为零时仍显示该材料。
- 库存增加、移除、载入或重置后立即刷新。

## 7. 建筑成本展示

采用“选中信息条 + 悬停明细”方案。

### 7.1 快捷卡

- 卡片只显示建筑图标和建筑名称。
- hover tooltip 显示建筑名称、占地和完整材料成本。
- 每项成本显示材料图标、需求量、当前持有量和缺口。
- 材料不足时 tooltip 仍然可用。

### 7.2 选中成本信息条

建造模式下，选中建筑后在快捷栏上方显示：

```text
谷仓  占地 2×2  [木材图标 100/250] [石头图标 50/150]
```

- 数量顺序为“需求/持有”。
- 充足项使用正常米白色。
- 不足项使用红色。
- 退出建造模式或取消选择时隐藏。
- 当前建筑因材料不足被取消连续建造时隐藏。

## 8. 建筑按钮禁用

材料不足时：

- `Button.disabled` 为真。
- 建筑图标灰化。
- 鼠标点击不能选中。
- 数字快捷键不能选中。
- 当前模式的最后选择不能绕过材料检查重新激活。
- hover tooltip 保留完整成本和缺口说明。
- 快捷键尝试选择时显示材料不足 Toast。

材料重新满足成本后，按钮自动恢复可用。

## 9. 失败 Toast

Toast 位于底部成本信息条上方，避免遮挡鼠标目标和建筑预览。

行为：

- 显示约 2.5 秒。
- 重复失败刷新同一个 Toast 的文案和倒计时。
- 不创建 Toast 队列。
- 使用暖红背景、浅色文字和清晰边框。
- 地图点击失败显示具体位置或材料原因。
- 禁用按钮的鼠标点击不触发选择；玩家通过 tooltip 查看原因。
- 快捷键尝试选择禁用建筑时显示材料不足原因。

## 10. 连续建造

成功放置后重新计算同类建筑的材料可用性：

- 材料仍足够时，保持选择并恢复同类预览。
- 材料不足时：
  - 退出预览。
  - 取消当前建筑选择。
  - 立即禁用并灰化对应按钮。
  - 隐藏成本信息条。
  - 显示 `材料不足，已结束连续建造`。

网格位置无效不会取消连续建造；玩家可移动到其他位置继续尝试。

## 11. Debug 日志

仅当 `OS.is_debug_build()` 为真时打印。

地图放置失败：

```text
[BuildRejected] building=barn grid=(12,8) code=road blocked=(13,8)
```

快捷键选择失败：

```text
[BuildSelectionRejected] building=barn code=insufficient_resources missing={wood:58}
```

约束：

- 预览移动不打印。
- 同一次用户操作只打印一行。
- 日志使用英文失败代码、建筑 ID、网格坐标和结构化缺口。
- 正式发布版本不打印。

## 12. 测试与验收

### 12.1 BuildingSystem

- 每个失败代码都有直接测试。
- `can_place()` 与诊断结果的 `allowed` 一致。
- 材料不足包含需求量、持有量和缺口。
- footprint 中不同阻塞状态返回稳定的首要原因。
- 成功与失败提交保持现有原子性。
- 预览移动不产生失败日志。

### 12.2 PlayerActionController

- 鼠标与数字快捷键都不能选择材料不足建筑。
- 快捷键选择失败发出一次反馈信号。
- 放置失败发出一次具体反馈。
- 材料仍足够时继续同类预览。
- 材料不足时结束连续建造并取消选择。

### 12.3 HUD

- 顶部存在四个材料图标和四个数值。
- 顶部材料名称不以可见文字显示。
- 库存事件实时更新数值。
- 建筑按钮根据材料正确禁用和恢复。
- 禁用按钮仍有完整 tooltip。
- 成本信息条正确显示占地和“需求/持有”。
- 不足项颜色正确。
- Toast 重复触发时复用同一个节点并刷新倒计时。

### 12.4 集成与视觉

- 现有建造系统、HUD 和主游戏集成测试保持通过。
- 新游戏初始材料显示为木材 250、石头 150、铁 50、玻璃 50。
- 成功放置只扣除一次成本，顶部数量同步变化。
- 截图验证顶部材料条、成本信息条、禁用建筑和失败 Toast 在 1280×720 下清晰可读且互不遮挡。

## 13. 不在本次范围

- 修改建筑造价或效果。
- 新增建筑解锁、等级、季节或玩家距离条件。
- 改变坡度、碰撞、道路或 footprint 规则。
- 增加 Toast 历史记录或消息队列。
- 修改库存与建筑存档格式。
