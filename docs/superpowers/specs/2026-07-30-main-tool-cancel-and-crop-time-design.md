# 主场景工具取消与作物时间推进设计

## 目标

- 玩家按 `Esc` 后取消当前工具，鼠标下的单格预览立即消失。
- 再次按 `1` 到 `6` 或点击快捷栏后，重新选择工具并恢复预览。
- 主游戏中一个完整游戏日（06:00 到次日 06:00）耗时 5 分钟。
- 调试版本可按 `N` 推进到下一天，用于快速验证作物生长。
- 保留浇水提供 1.5 倍生长进度的既有设计；因此浇水作物可能跳过一个中间外观阶段。

## 工具选择状态

`PlayerActionController` 使用 `-1` 表示未选择工具。`deselect_slot()` 负责：

1. 将选择状态设为 `-1`；
2. 清除 `GridSystem` 的当前高亮；
3. 发出 `selection_changed(-1, "未选择工具")`。

`Esc` 的优先级是：

1. 如果正在预览建筑，先退出建筑预览；
2. 否则如果选择了工具，取消工具；
3. 没有可取消状态时不消费输入。

未选择工具时，控制器不执行地块操作，也不产生地块预览。成熟作物仍需先选择任意工具或种子后才显示可交互提示，避免 `Esc` 后继续残留格子。

HUD 接受 `-1`：所有快捷栏按钮恢复未按下状态，说明文字显示“未选择工具”。

## 时间与调试推进

从 06:00 到次日 06:00 共 1080 游戏分钟。为了让一日耗时 300 秒，
`SeasonSystem.MINUTES_PER_REAL_SECOND` 设置为 `1080 / 300 = 3.6`。

`advance_to_next_day()` 计算到下一次 06:00 所需的分钟数，并复用
`advance_game_minutes()`。这样日期、季节、时间、作物、经济与自动存档继续走同一条事件链。

主场景仅在调试构建中响应 `N`，调用 `SeasonSystem.advance_to_next_day()`。
发布构建不会暴露该快捷键。

## 作物生长

作物继续只在 `EventBus.day_changed` 时推进：

- 未浇水：增加 `1.0`；
- 当天浇水：增加 `1.5`；
- 谷物成熟阈值：`3.0`；
- 每次推进后清除当天浇水状态。

因此未浇水谷物需要三个日期推进；持续浇水的谷物可在两个日期推进后成熟，
并允许跳过一个中间模型，这是确认保留的加速行为。

## 验证

- 单元测试覆盖取消/重新选择、未选择时不执行地块动作、HUD 的 `-1` 状态。
- 时间测试覆盖 5 分钟日长常量、跨日事件与 `advance_to_next_day()`。
- 运行完整测试、Godot 编辑器解析检查和主场景短时无窗口运行。
