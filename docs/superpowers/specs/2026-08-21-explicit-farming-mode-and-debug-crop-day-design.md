# 显式种植模式与调试作物推进设计

## 目标

修复以下三个相互关联的运行时问题：

1. 进入游戏时不再自动弹出种子选择窗口。
2. 进入游戏时只显示模式入口；按 `P` 后才显示六个种植快捷项，且切换模式本身不打开种子窗口。
3. 调试键 `N` 只推进一天日期和作物生长，不运行生产、NPC、市场、订单或自动存档，避免同步跨日链造成卡顿。

## 已确认交互

- 初始状态为未选择操作模式。
- 初始 HUD 保留模式入口，隐藏种植和建造快捷栏。
- 按 `P` 进入种植模式并显示六个种植快捷项。
- 按 `P` 不选择任何工具或种子槽，也不打开种子窗口。
- 只有在种植模式下点击第六项或按数字 `6`，才打开种子选择窗口。
- 自动发现或恢复种子选择只更新所选种子数据，不改变当前模式或槽位。
- `N` 是仅供调试构建使用的作物推进键，不代表正式游戏的一天结算。

## 根因

`PlayerActionController.set_selected_plant_item_id()` 当前同时承担两项职责：保存种子选择，以及调用 `select_slot(SEED_SLOT)` 激活第六槽。槽位激活又会发出 `seed_selection_requested`，因此新游戏自动映射种子和 P 模式恢复槽位都会意外打开种子窗口。打开窗口时会同步创建种子行并加载作物贴图，形成明显卡顿。

`N` 当前调用 `SeasonSystem.advance_to_next_day()`，后者同步广播正式 `day_changed`。该信号会在同一帧执行农业、生产、NPC、经济、市场、资源刷新和 JSON 存档。已有的通知合并只能减少部分 UI 刷新，不能消除整条同步结算链。

## 设计

### 1. 显式未选择模式

在 `PlayerActionController.ActionMode` 中增加 `NONE`，并将控制器初始模式设为 `NONE`。`switch_mode()` 仍只接受玩家可进入的 `FARMING` 和 `BUILDING`，因此 `NONE` 只作为启动和取消前的内部状态，不成为第三种可选菜单项。

未选择模式下：

- 数字快捷键不选择槽位。
- 地块操作和建筑操作不执行。
- HUD 隐藏快捷栏和建筑分类栏。
- P/B 分别进入种植/建造模式，并由 HUD 重建相应快捷栏。

进入种植模式时恢复 `_last_farming_slot`。启动值保持 `-1`，所以首次按 P 只展示菜单。后续从建造模式返回种植模式时可以恢复之前明确选择的普通工具或种子槽，但模式恢复不得重新触发槽位的一次性 UI 副作用。

### 2. 分离种子数据选择与槽位激活

`set_selected_plant_item_id()` 只验证并保存种子 ID、发出 `plant_selection_changed`，不再调用 `select_slot()`。

种子窗口只由玩家明确激活第六槽触发：

- 点击 HUD 第六项；或
- 在种植模式下按数字 `6`。

恢复模式只恢复选中外观和种植行为，不重新发出 `seed_selection_requested`。为此，模式恢复与显式槽位激活使用不同路径：恢复路径应用当前工具/建筑状态但不打开选择型 UI；显式路径保留第六槽弹窗行为。

### 3. 轻量调试作物日

`SeasonSystem` 提供可选择是否广播正式日结事件的下一日推进能力。正式游戏继续使用默认行为并广播 `day_changed`；调试 N 路径关闭该广播，但仍更新时间、日期、季节及相应轻量显示信号。

`Main` 的调试 N 处理顺序为：

1. 将日历推进到下一天，但不发出正式 `day_changed`。
2. 直接调用一次 `FarmingSystem.on_day_changed(total_days)` 推进作物。
3. 通过现有时间/季节显示刷新 HUD 日期。

该路径不得调用 `DailySimulationSystem.run_day()`，也不得改变它的经济结算游标，否则之后的正式日结会与市场游标失配。该路径同样不得调用 `SaveManager.save_game()`。

## 状态与事件流

```text
启动
  -> ActionMode.NONE
  -> 自动恢复/选择种子 ID（无槽位副作用）
  -> HUD 仅显示模式入口

按 P
  -> ActionMode.FARMING
  -> HUD 显示六个快捷项
  -> 不发出 seed_selection_requested

点击 6 / 数字 6
  -> 显式激活 SEED_SLOT
  -> 发出 seed_selection_requested
  -> 打开种子窗口

按 N（仅调试构建）
  -> 日历 +1 天，不发正式 day_changed
  -> FarmingSystem 推进作物一次
  -> HUD 刷新日期
```

## 错误与边界处理

- 非调试构建继续忽略 N。
- N 遇到缺失的季节系统或农业系统时不执行部分推进。
- 连续按键和键盘 echo 继续被忽略。
- 未选择模式下数字键不被消费，避免隐藏菜单仍能操作。
- 种子库存为空时仍允许显式打开种子窗口，由现有空状态负责提示。
- 加载旧存档时可以恢复所选种子 ID，但不会在加载期间弹窗或自动进入种植模式。

## 测试策略

采用回归测试先行：

- 控制器初始模式为 `NONE`，初始槽位为 `-1`。
- 设置或自动映射种子不会切换模式、选择第六槽或发出窗口请求。
- 首次切换到种植模式不发出种子窗口请求。
- 显式选择第六槽恰好发出一次种子窗口请求。
- HUD 在 `NONE` 下没有快捷项，进入种植模式后显示六项。
- 主场景初始化后种子窗口保持隐藏。
- 调试 N 将日期和作物生长各推进一次。
- 调试 N 不调用正式每日模拟与自动存档。
- 正式跨日路径仍执行原有 `day_changed` 行为。

定向测试通过后，再运行种子选择器、玩家操作控制器、季节系统和主场景农业集成测试。现有主游戏全集成套件存在与本任务无关的基线失败，应分别记录，不能把它们误报为本次回归。

## 非目标

- 不优化正式每日经济结算耗时。
- 不改变正常时间流逝触发的一天结算和自动存档。
- 不重做种子选择窗口的贴图加载或布局。
- 不改变 P/B 以外的模式快捷键设计。
