# 主游戏操作模式与建造快捷栏设计

日期：2026-07-30  
状态：设计已确认

## 1. 背景

主游戏当前只有固定的六格工具/种子快捷栏：

- `1–6` 由 `PlayerActionController` 解释为工具或谷物种子。
- 鼠标移动时显示单格地块反馈，左键执行种植相关动作。
- `BuildUI` 使用 `B` 打开全屏建筑列表，选择后再进入建造预览。

独立的 `building_system_verification.tscn` 已验证：

- 九类建筑的完成态模型。
- 地基、骨架、半成品和成品施工过程。
- 多格 footprint。
- 有效位置的绿色预览和无效位置的红色预览。
- 资源校验、原子扣费、移除和网格恢复。

本次不重新实现 `BuildingSystem` 或重新制作建筑模型，而是将验证场景中的建筑选择、预览和连续放置体验迁移到主游戏，并为种植与建造建立统一的底部模式快捷栏。

## 2. 目标

- 底部快捷栏左侧增加一个始终可见的模式按钮。
- 鼠标悬停模式按钮时，向上显示种植/建造模式菜单。
- `P` 切换种植模式，`B` 切换建造模式。
- 模式切换后，右侧整排选择按钮随模式替换。
- 种植模式保留现有六项工具/种子和单格鼠标交互。
- 建造模式显示九类建筑，支持数字键和鼠标选择。
- 建筑选择后显示跟随鼠标的半透明模型与 footprint 阴影。
- 左键在有效位置开始施工；无效位置无副作用。
- 成功放置后保持同一建筑选择，支持连续建造。
- UI 图像延续当前手绘 2.5D 建模风格。

## 3. 非目标

- 不增加新的建筑类型。
- 不改变建筑造价、footprint、施工时间或设施效果。
- 不增加建筑旋转、移动、升级或批量拆除。
- 不改变斧头、镐和鱼竿尚未完整接入世界目标的现状。
- 不持久化当前操作模式或当前选择。
- 不重做已验证的建筑、施工阶段和谷物模型。

## 4. 方案选择

采用扩展现有 `PlayerActionController` 的方案。它继续作为模式、选中项和世界鼠标交互的唯一状态源；HUD 只负责显示状态并把鼠标点击发送给控制器。

不新增第二个模式控制器，避免 HUD、玩家动作和建筑预览之间出现重复状态。原 `BuildUI` 保留为场景资源，但不再在主游戏中消费全局 `B` 输入或承担主建造入口。

```text
模式按钮 / P / B
        ↓
PlayerActionController.switch_mode()
        ↓
HUD 重建当前模式的按钮行
        ↓
数字键 / 鼠标按钮
        ↓
PlayerActionController.select_mode_slot()
        ↓
鼠标移动更新 GridSystem 或 BuildingSystem 预览
        ↓
左键执行地块动作或放置建筑
```

## 5. 模式状态

### 5.1 模式定义

控制器新增两个模式：

```gdscript
enum ActionMode {
    FARMING,
    BUILDING,
}
```

公开状态与信号：

```gdscript
signal mode_changed(mode: ActionMode)
signal palette_changed(mode: ActionMode, selected_index: int)

func switch_mode(mode: ActionMode) -> bool
func get_action_mode() -> ActionMode
func select_mode_slot(index: int) -> bool
func get_mode_selected_slot(mode: ActionMode) -> int
func cancel_current_selection() -> bool
```

`selection_changed(index, label)` 继续用于 HUD 当前项目说明和兼容现有测试。

### 5.2 每个模式独立记忆

- 首次进入种植模式时默认选择锄头，索引为 `0`。
- 首次进入建造模式时默认选择谷仓，索引为 `0`。
- `_last_farming_slot` 和 `_last_building_slot` 分别记忆两个模式最后一次有效选择。
- 模式切换恢复目标模式的上次选择。
- `Esc` 将当前模式的活动选择设为 `-1`，但不覆盖记忆值。
- 取消后再次点击任意按钮恢复该选择；切换到另一个模式再切回时恢复此前记忆项。

模式与选择不写入存档。新启动始终从种植模式和锄头开始。

## 6. 输入规则

### 6.1 快捷键

- `P`：切换到种植模式并恢复该模式上次选择。
- `B`：切换到建造模式并恢复该模式上次选择。
- 种植模式中的 `1–6`：选择六项工具/种子。
- 建造模式中的 `1–9`：选择九类建筑。
- `Esc`：取消当前选择和阴影，保留当前模式。
- 鼠标左键：执行当前模式的世界动作。
- 鼠标右键：本次不绑定。

数字键和鼠标按钮必须调用同一个 `select_mode_slot()`，不允许 UI 自行维护另一份选择。

### 6.2 输入所有权

`PlayerActionController` 统一处理 `P`、`B`、数字键、`Esc` 和世界左键。主场景中的旧 `BuildUI` 不再响应 `B`，避免一次按键同时打开全屏面板和切换底部快捷栏。

当鼠标位于 HUD、模式菜单或快捷按钮上方时，世界射线和左键动作均不执行。

## 7. 底部 HUD

### 7.1 布局

采用已确认的方案 A：

```text
                  ┌──────────────┐
                  │ 种植模式  P  │
                  │ 建造模式  B  │
                  └──────────────┘
┌──────┐ ┌────┐ ┌────┐ ┌────┐ ...
│ 模式 │ │ 1  │ │ 2  │ │ 3  │
└──────┘ └────┘ └────┘ └────┘
```

- 模式按钮固定在快捷按钮行左侧。
- 模式按钮显示当前模式图像和名称。
- 鼠标进入模式按钮时，菜单向上展开。
- 指针从按钮移动到菜单时菜单保持打开。
- 指针离开按钮和菜单后短暂延迟关闭，避免跨越边缘时闪退。
- 菜单选项支持鼠标点击；`P/B` 快捷键与菜单点击结果完全一致。
- 模式切换后，只替换右侧快捷按钮，不移动整个底栏中心。

### 7.2 自适应尺寸

- 种植模式生成六个按钮。
- 建造模式生成九个按钮。
- 按钮保留图像、数字和短名称。
- 建造栏使用较紧凑的按钮宽度和间距，在 `1280 × 720` 窗口下九个建筑按钮和一个模式按钮必须完整可见。
- 整排以窗口底部中心为锚点。
- 不引入横向滚动或分页；九类建筑始终一排可见。

### 7.3 当前状态

- 当前模式按钮使用暖金色边框。
- 当前选择按钮显示金色高亮。
- 未选择时所有快捷按钮恢复普通状态，说明文字显示“未选择工具”或“未选择建筑”。
- 建筑资源不足时按钮降低亮度，但仍可点击和预览。
- 建筑说明文字显示名称、footprint、造价；资源不足时追加缺失材料。

## 9. 种植交互

种植模式继续沿用现有逻辑：

1. 鼠标射线定位地形网格。
2. 当前选择有效时显示单格阴影。
3. 在玩家交互距离内且动作有效时显示绿色。
4. 超出距离、地块状态不匹配或缺少种子时显示红色。
5. 左键调用现有工具、播种或收获流程。
6. 动作完成后保持选择，支持连续操作。

切换到建造模式或按 `Esc` 时调用 `GridSystem.clear_highlights()`。

## 10. 建造交互

### 10.1 选择与预览

选择建筑时：

1. 用固定的建筑 ID 顺序解析 `BuildingData`。
2. 调用 `BuildingSystem.enter_preview_mode(building_id)`。
3. 鼠标射线定位地面，并调用 `update_preview_position()`。
4. 显示现有半透明建筑模型和全部 footprint 标记。
5. `can_place()` 为真时模型和 footprint 为绿色，否则为红色。

预览不受玩家 `2.5m` 工具距离限制，保持现有全地图建造行为。

### 10.2 有效性

以下任一条件不满足时预览为红色：

- footprint 超出网格。
- 任一格不属于可建造状态。
- 任一格已有建筑或其他阻塞。
- 任一格无法获得有限地形高度。
- 资源不足。
- 建筑数据或场景无效。

红色预览左键点击返回失败：

- 不修改网格。
- 不扣资源。
- 不创建建筑。
- 不退出预览。

### 10.3 放置与连续建造

绿色预览左键点击：

1. 调用 `place_selected_building()`。
2. 复用 `BuildingSystem` 的网格快照和资源原子事务。
3. 创建的 `BuildingInstance` 从 `FOUNDATION` 开始施工。
4. 发出既有建造和施工事件。
5. 记录已选择建筑 ID。
6. 立即重新进入同类建筑预览。
7. 下一帧把新预览更新到当前鼠标位置。

如果剩余资源不足，新预览继续存在但显示红色。玩家可移动、切换建筑、按 `Esc` 或切换模式。

## 11. 预览清理

- 从建造切换到种植：调用 `BuildingSystem.exit_preview_mode()`，然后恢复种植单格预览。
- 从种植切换到建造：清除 `GridSystem` 单格高亮，然后创建建筑预览。
- 建造模式按 `Esc`：退出建筑预览并将活动选择设为 `-1`。
- 种植模式按 `Esc`：清除单格高亮并将活动选择设为 `-1`。
- 控制器离开场景树时清理两类预览，避免残留节点。

任何时刻只允许出现一种世界预览。

## 12. 资源与错误反馈

- `BuildingSystem.can_place()` 继续作为建造有效性的权威判断。
- `EconomySystem.has_resources()` 用于按钮灰度和红色预览。
- `EconomySystem.spend_resources()` 只在全部网格写入准备成功后执行。
- 放置事务失败时由现有快照回滚已修改格。
- UI 不提前扣除材料。
- 无效建筑 ID、缺失场景或缺失图像不得导致脚本错误；建筑选择失败时保持无选择状态并显示简短原因。
- 图标加载失败时按钮保留数字和文字，因此仍可操作。

## 13. 现有组件调整

### `PlayerActionController`

- 增加模式状态、模式内记忆和建造 ID 映射。
- 将数字键映射改为依赖当前模式。
- 将 `P/B`、`Esc`、选择和世界动作统一处理。
- 放置成功后恢复同类连续预览。

### `VillaHud`

- 增加模式按钮和向上展开菜单。
- 根据模式动态生成六个或九个按钮。
- 从控制器读取模式和选择，不自行保存权威状态。
- 显示图像、数字、名称、数量和建造资源状态。

### `BuildUI`

- 保留场景与建筑列表能力。
- 主游戏中禁用其全局 `B` 输入，避免和新模式系统冲突。

### `BuildingSystem`

- 继续使用现有预览、footprint、有效性、放置和施工接口。
- 只在测试发现公开接口不足时增加最小查询接口，不复制业务规则。

## 14. 测试与验收

### 14.1 逻辑测试

- 默认模式为种植，默认选择为锄头。
- `P/B` 切换模式并恢复各自最后选择。
- 种植模式只接受 `1–6`，建造模式只接受 `1–9`。
- 数字键与鼠标按钮调用同一选择接口。
- `Esc` 清除活动选择但保留模式记忆。
- 模式切换清除旧预览。
- HUD 在种植模式生成六个按钮。
- HUD 在建造模式生成九个按钮。
- 模式菜单点击与快捷键产生相同状态。
- 缺失图标时按钮仍显示数字和名称。

### 14.2 主场景集成测试

- `P` 后选择锄头，鼠标显示单格地块阴影。
- `B` 后选择谷仓，鼠标显示与 footprint 一致的建筑预览。
- 有效位置显示绿色，无效或资源不足位置显示红色。
- 红色位置左键不修改网格、不扣资源。
- 绿色位置左键创建 `FOUNDATION` 阶段建筑并扣费一次。
- 成功放置后仍保持谷仓选择，并出现下一个谷仓预览。
- 切换回种植模式后建筑预览消失。
- `Esc` 后所有世界预览消失。

### 14.3 视觉与运行验证

- 五个工具图标透明背景、轮廓清楚，并匹配现有手绘风格。
- 9 个建筑按钮在 `1280 × 720` 窗口下一排完整显示。
- 模式菜单从按钮向上展开，不被世界输入穿透。
- `building_system_verification.tscn` 的既有视觉契约继续通过。
- Godot 全量测试、编辑器解析和主场景实际运行无新增错误。
