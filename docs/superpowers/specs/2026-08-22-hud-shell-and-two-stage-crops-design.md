# HUD 壳层与两阶段作物视觉重建设计

## 背景

当前 HUD 的状态、操作和提示分散在多个区域：

- 种植模式与建造模式虽然已有键盘快捷键和弹出菜单，但真实鼠标路径不可可靠使用。
- 建造反馈、操作提示、紧急经营摘要、经营 Toast 和调试信息分别占据屏幕不同位置。
- 种子选择器使用密集七列表格，小字号与弱层级使文字难以辨认。
- 番茄、土豆、玫瑰和薰衣草沿用四阶段、多变体资产结构；现有 PNG 视觉与谷物的手绘质量不一致，并制造了大量当前版本不需要的中间资产。

本次采用完整 HUD 展示框架重写，而不是只修补现有控件位置。业务系统、成长规则和存档数据继续作为权威来源。

## 目标

- 建立统一 HUD 壳层，明确顶部状态、右侧消息流、底部操作和模态面板的固定职责。
- 让玩家可以用鼠标一击切换种植模式和建造模式，同时保留 P/B 快捷键。
- 让普通提示、失败原因、经营提醒和调试信息只通过右侧消息流实时显示。
- 提供清晰、可收起且不过度遮挡游戏画面的消息流。
- 将种子选择器改为高对比、两列、整卡可点击的种子卡片。
- 将番茄、土豆、玫瑰和薰衣草压缩为种子态与成熟态两套手绘 PNG 视觉。
- 保持现有成长天数、成熟判定、浇水、收获、经济和存档语义。

## 非目标

- 不修改谷物及其余十种作物的阶段资产。
- 不改变作物成长阶段、成长速度或存档格式。
- 不为目标作物制作中间生长动画、随机外观变体或精细摇摆动画。
- 不重写经济通知的权威记录、目标跳转和存档逻辑。
- 不在本轮增加手柄专用导航。
- 不把实时 HUD 消息写入长期存档；只有现有经济通知继续持久化。

## 总体架构

### HUD 壳层

保留稳定入口 res://scenes/ui/hud.tscn，但将其内部重组为统一的 HudShell。外部仍通过 VillaHud 的兼容接口配置 HUD，避免 Main、测试和已有业务调用同时失效。

HUD 壳层包含四个明确区域：

1. 顶部状态区：体力、金币、等级、季节、日期、时间和材料。
2. 右侧消息区：统一实时消息流及其向上折叠标题栏。
3. 底部操作区：常驻模式按钮、当前模式动作栏和建造分类/成本信息。
4. 模态层：种子选择器、建筑锁定说明等需要暂停游戏的界面。

壳层只负责布局和展示，不直接修改库存、经济、作物或建造状态。

### HudMessageBus

新增一个由 Main 持有并显式注入的 HudMessageBus 节点。它不作为新的 Autoload，避免扩大全局状态；需要发布消息的系统通过配置引用、Main 路由或 HUD 兼容接口进入消息总线。

每条消息包含：

- 稳定的会话内消息 ID。
- 来源，如 farming、building、economy 或 debug。
- 级别：info、success、warning、error、debug。
- 清晰的正文。
- 会话内排序时间和可选的游戏时间显示。
- 可选的 target_type 与 target_id，用于打开现有通知中心中的业务目标。
- 合并后的出现次数。

消息总线最多保留当前游戏会话最近 100 条。来源、级别、正文和目标完全相同的消息在 1 秒内重复出现时合并到原记录并增加次数；不同正文或不同目标不得合并。

### 组件边界

- HudMessageStream：订阅消息总线，创建和更新可视消息卡，维护滚动、折叠与未读状态。
- HudActionDock：显示两个常驻模式按钮和当前模式动作槽，只通过 PlayerActionController 切换模式和选择动作。
- SeedSelectorPanel：继续作为独立模态 CanvasLayer，但使用共享 HUD 主题和种子卡片场景。
- EconomyNotificationSystem：继续拥有持久经营记录；新增记录时同步发布一条 HUD 消息，历史和跳转仍由通知中心负责。
- 现有 show_build_feedback()、操作提示和调试入口在迁移期间只作为兼容适配器，将结构化消息提交给消息总线，不再显示独立 Toast。

## 布局与视觉

### 顶部状态区

- 顶部状态栏保留当前主要信息，统一为深绿色半透明底、金色细边框和高对比浅色文字。
- 右侧为消息区预留固定安全宽度，顶部状态栏不得进入该区域。
- 材料行位于顶部状态栏下方左侧；市场、背包等入口不得与消息区重叠。

### 右侧消息流

展开态：

- 固定在屏幕右侧，顶部边缘与顶部状态 HUD 对齐，并在底部操作区上方结束。
- 整体面板背景不透明度为约 45%，允许明显看到背后的游戏画面。
- 单条消息使用约 60% 深色底、彩色级别条和文字阴影，以保证任何地形背景上都清晰。
- 最新消息从底部进入，旧消息向上滚动。
- 玩家停留在最新位置时自动跟随；玩家向上滚动后暂停自动跟随，并显示“回到最新”提示。

向上收起态：

- 整个纵向面板向上折叠。
- 只保留右上角横向标题栏，其高度、圆角和垂直位置与顶部状态 HUD 一致。
- 标题栏显示“消息流”、未读数量和向下展开按钮。
- 新消息不得自动展开面板，只更新未读数量。
- 展开并回到最新位置后清除实时消息未读数。

消息颜色：

- 普通信息使用中性浅色级别条。
- 成功使用绿色。
- 警告使用黄色。
- 错误使用红色。
- 调试使用蓝紫色并带“[调试]”前缀。

### 底部操作区

- “种植 P”和“建造 B”作为常驻分段按钮，位于动作槽左侧。
- 鼠标单击立即调用与 P/B 相同的 switch_mode() 入口，不使用弹出菜单。
- 当前模式使用金色高亮，非当前模式保持深色。
- P/B 与数字快捷键以次级小字显示。
- 切换模式后动作栏立即显示该模式上一次选择，并保持现有建造预览退出/进入规则。

### 种子选择器

- 使用居中深绿色高不透明度面板、金色边框和高对比浅色文字。
- 1280 像素及以上宽度使用两列种子卡片；窄屏回落为一列滚动列表。
- 卡片突出约 68 像素种子图、21 像素加粗名称、金色数量和清晰选择按钮。
- 成熟天数、季节和环境使用至少 15 像素的次级高对比文字。
- 可播种状态使用绿色，不可播种原因使用红色；禁用卡降低整体亮度但不得降低原因文字可读性。
- 整张可用卡片均可点击；当前选择使用金色描边。
- 选择后沿用现有流程：设置种植物品、关闭面板、释放暂停并回到地块操作。
- Esc、标题栏关闭按钮和底部关闭操作都必须释放同一个模态所有权。

## 消息数据流

1. 业务系统完成或拒绝一次操作。
2. 发布者向 HudMessageBus 提交结构化消息；业务提交不得等待 UI。
3. 消息总线验证消息、执行 1 秒重复合并并更新会话缓冲区。
4. HudMessageStream 收到新增或合并事件：
   - 展开且位于最新位置时立即显示并继续跟随。
   - 展开但查看旧记录时保留滚动位置并增加新消息提示。
   - 收起时只增加标题栏未读数。
5. 带经营目标的消息可以通过“历史记录”进入现有通知中心并复用其跳转逻辑。

旧的底部建造 Toast、操作 Toast、右上紧急摘要和独立经营 Toast 不再作为实时提示出口。它们对应的生产者必须迁移到消息总线，避免同一消息重复显示。

## 两阶段作物资产

### 范围与数量

目标作物为番茄 tomato、土豆 potato、玫瑰 rose 和薰衣草 lavender。

每种作物只保留：

- 种子态：一张正面 PNG、一张背面 PNG。
- 成熟态：一张正面 PNG、一张背面 PNG。

总计 16 张源 PNG：4 种作物 × 2 个视觉阶段 × 2 个方向。每阶段只保留 variant_0，不制作 variant_1 和 variant_2。

### 美术规范

- 透明背景，1024×1024。
- 使用谷物 painted 资产的柔和手绘笔触、自然明暗、暖色高光和清晰外轮廓。
- 物体底部锚点与谷物一致，避免切换阶段时平移或跳高。
- 正面与背面的可视质量、占图比例和地面接触点一致。
- 种子态表现为土壤表面的真实种子组合，不使用细线、纯色几何体或成熟植株缩小图。
- 成熟态通过轮廓和主色在游戏相机距离下立即区分作物。
- 种子选择器复用种子态正面 PNG 作为图标，不再制作独立种子图标。

### 阶段映射

游戏内部继续保留现有四级成长进度与成熟判定。目标作物的视觉映射为：

- 内部阶段 0、1、2：复用种子态场景。
- 内部阶段 3：使用成熟态场景。

CropData.stage_scenes 与 stage_textures 继续保持四个逻辑位置，但前三个位置指向同一份种子态资源，最后一个位置指向成熟态资源。这样旧存档中的成长进度无需迁移。

目标作物最终只保留两个阶段场景。确认仓库中无引用后，移除旧的中间阶段场景、80 张多余 PNG 及不再被场景引用的程序化材质。删除范围不得包含谷物或其他作物。

## 失败处理

- 空正文或未知级别的 HUD 消息被拒绝并记录调试错误，但不得阻断业务操作。
- HUD 暂时不在场景树时，消息仍保存在消息总线；HUD 重新配置后从最近记录恢复显示。
- 消息目标无效时，消息仍可阅读，点击跳转失败只追加一条错误消息，不修改业务状态。
- 模式控制器未配置时，模式按钮保持禁用并显示明确工具提示。
- 种子卡片依赖尚未配置时保持关闭，不获取模态所有权。
- 目标作物缺少 PNG 或场景引用时，资产测试必须失败；运行时使用统一安全占位图并向调试消息流报告资源路径，不再静默展示错误的程序化模型。

## 测试策略

所有行为修改遵循测试先行。

### HUD 与模式

- 使用真实 InputEventMouseButton 点击种植和建造按钮，验证控制器模式、按钮高亮和动作栏同步变化。
- 验证 P/B 键盘路径仍调用相同控制器入口。
- 验证旧模式弹出菜单不存在，鼠标切换不需要第二次点击。
- 验证 1280×720 和 1920×1080 下顶部、右侧和底部安全区互不重叠。

### 消息总线与消息流

- 验证每种消息级别的结构、颜色语义和顺序。
- 验证 100 条上限和 1 秒内相同消息合并；不同来源、正文或目标不合并。
- 验证查看旧记录时不跳动、回到最新后恢复自动跟随。
- 验证纵向展开、向上折叠、同高标题栏、未读累计和重新展开。
- 验证收起时新消息不会自动展开。
- 验证建造反馈、操作提示、经营提醒和调试输出只出现于统一消息流，旧 Toast 不再重复显示。
- 验证 HUD 离开并重新进入场景树后从消息总线恢复并保持唯一信号连接。

### 种子选择器

- 验证两列卡片、窄屏一列回退、最小字号和高对比状态。
- 使用真实鼠标事件点击卡片正文与按钮，验证两者选择同一种子。
- 验证禁用卡无法选择且原因清晰。
- 验证选择、Esc 和关闭按钮都正确释放暂停。
- 保留隐藏刷新门控回归，避免库存事件重新引入播种卡顿。

### 作物视觉

- 验证四种目标作物各只有两个唯一视觉场景和四张源 PNG。
- 验证 16 张 PNG 均为 1024×1024、含透明通道且非空。
- 验证四级逻辑映射为种子、种子、种子、成熟。
- 验证阶段 0 到 2 不创建重复资产，阶段 3 正确切换成熟视觉。
- 验证旧存档的阶段 0、1、2、3 均可加载且成熟判定不变。
- 使用视觉捕获确认正反面、地面锚点、占图比例和游戏相机下辨识度。

## 验收标准

- 鼠标可一击切换种植和建造模式，P/B 保持可用。
- 屏幕中央和底部不再出现分散临时提示；实时提示统一进入右侧消息流。
- 消息流展开时能看清背后画面，收起时与顶部 HUD 同高且不占用右侧纵向区域。
- 消息文字在明暗地形上均清晰，调试消息可辨识但不抢占主操作。
- 种子面板的名称、数量、条件和不可播种原因无需悬停即可阅读。
- 番茄、土豆、玫瑰和薰衣草使用谷物风格的两阶段 PNG 视觉，共 16 张源 PNG。
- 作物成长、浇水、收获、经济与存档行为保持兼容。
- 新增自动化测试通过；与本次范围无关的既有失败单独记录，不得被误报为本次成功。
