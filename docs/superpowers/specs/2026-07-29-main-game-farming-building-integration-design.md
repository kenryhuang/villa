# 主游戏种植与建造系统集成设计

日期：2026-07-29  
状态：设计已确认，等待实施

## 1. 背景

`detailed-design.md` 中的以下系统已经分别完成实现或视觉验证：

- 1.1 全局 Autoload
- 1.2 GridSystem
- 1.3 FarmingSystem
- 1.4 BuildingSystem

主场景已经创建并连接其中的大部分系统，但还没有形成完整的玩家操作闭环：

- `PlayerController` 和 `main.gd` 都会处理鼠标左键，可能重复消费输入。
- 玩家可以锄地和浇水，但不能从主场景选择种子、播种或点击收获。
- 已验证的谷物四阶段模型尚未注册为主游戏作物。
- 建造预览和放置由 `main.gd` 直接处理，与玩家操作分散在不同脚本。
- 工具会在动作有效性确定前扣除体力。
- `E` 同时被用作镜头右转和世界交互。

本次集成的目标是在现有主游戏场景内连接这些系统，使玩家可以通过统一的鼠标交互完成种植、收获和建造，同时保留已验证的模型、网格规则、成长规则和施工过程。

## 2. 范围

### 2.1 本次包含

- 在主游戏中接入网格选取和地块反馈。
- 玩家使用锄头开垦荒地。
- 玩家选择谷物种子并在耕地播种。
- 玩家使用水壶浇水。
- 玩家点击成熟作物收获。
- 玩家打开建造菜单、预览建筑并点击放置。
- 放置后的建筑自动经过地基、骨架、半成品和成品阶段。
- 快捷栏支持鼠标点击和数字键选择。
- 种植、收获、工具和建造的资源消耗具有原子性。
- 存档恢复后重建作物与建筑视觉。
- 为主场景增加自动化和视觉验收。

### 2.2 本次不包含

- 新作物种类及其独立美术。
- 种子商店和平衡性调整。
- 建筑拆除、旋转或移动。
- 农田范围扩建。
- 动物、加工、制造或自动化设施效果。
- NPC AI 与种植、建造协作。

## 3. 总体架构

新增 `PlayerActionController`，作为 Player 的子节点，统一处理世界内动作。`main.gd` 负责依赖注入，不再直接响应建造鼠标点击。

主场景中的职责划分如下：

```text
Main
├── 初始化和连接系统
├── 注册作物数据
├── 加载或创建游戏状态
└── 刷新 UI

Player
├── PlayerController
│   ├── 移动
│   ├── 碰撞
│   └── 体力自然恢复
└── PlayerActionController
    ├── 鼠标射线
    ├── 目标与距离判断
    ├── 当前工具/种子选择
    ├── 地块高亮
    ├── 世界交互
    ├── 种植与收获
    └── 建造预览与放置
```

`PlayerActionController` 由 `main.gd` 注入以下引用：

- `PlayerController`
- 当前 `Camera3D`
- `GridSystem`
- `FarmingSystem`
- `BuildingSystem`
- `ToolSystem`
- `InventorySystem`

该控制器不直接修改背包、地块或建筑内部数据，而是调用对应系统的公开接口。

## 4. 统一左键交互

### 4.1 动作优先级

每次左键点击只允许执行一个动作，优先级固定为：

1. 正在建造：放置当前预览建筑。
2. 点击 NPC、成品建筑或收集品：调用目标交互。
3. 点击成熟作物：收获。
4. 当前选择为种子且点击空耕地：播种。
5. 当前选择为工具且点击有效地块：使用工具。
6. 其他情况：不改变游戏状态，仅显示不可操作反馈。

建造模式具有最高优先级，以避免放置建筑时同时锄地、浇水或收获。

### 4.2 射线与距离

- 对 NPC、建筑和收集品先执行物理射线检测。
- 对地块和作物使用相机射线与地形/网格的交点。
- 工具、播种、浇水和收获限制在玩家水平距离 `2.5m` 内。
- 建造保持当前全地图预览与放置范围，不受 `2.5m` 限制。
- 鼠标移动时持续更新当前地块和建造预览，不在每帧修改游戏状态。

### 4.3 输入映射

- 鼠标左键：统一世界交互。
- `1–6`：选择快捷栏。
- 鼠标点击快捷栏：选择对应槽位。
- `B`：打开或关闭建造菜单。
- `Esc`：取消建造预览或关闭当前界面。
- `Q/E`：继续用于镜头旋转。
- `E` 不再触发世界交互。
- 鼠标右键暂不绑定主游戏动作。

## 5. 快捷栏和选择状态

主游戏底部快捷栏固定为六格：

| 槽位 | 内容 | 世界点击动作 |
|---|---|---|
| 1 | 锄头 | 荒地开垦为耕地 |
| 2 | 浇水壶 | 给耕地或作物浇水 |
| 3 | 斧头 | 对可砍伐目标使用 |
| 4 | 镐 | 对可采矿目标使用 |
| 5 | 鱼竿 | 对可钓鱼区域使用 |
| 6 | 谷物种子 | 在空耕地播种 |

快捷栏需要显示：

- 槽位编号。
- 工具或种子名称。
- 第六格的种子数量。
- 当前选择的高亮状态。

数字键和鼠标点击必须经过同一个选择接口，避免 UI 显示状态与实际动作状态不一致。进入新游戏或载入存档后默认选择锄头；当前选择不需要持久化。

## 6. 种植流程

### 6.1 谷物数据

主游戏新增并注册：

- `grain_seed`：谷物种子物品。
- `grain`：谷物收获物。
- `grain` 作物数据。

作物沿用已经视觉验证的四阶段场景：

1. 种子
2. 幼苗
3. 生长
4. 成熟

成长规则保持验证程序中的设置：

- `growth_days = 3`
- 当天浇水增长 `1.5`
- 当天未浇水增长 `1.0`
- 当前季节不适宜时不增长，温室地块除外

### 6.2 状态转换

```text
WASTELAND
  └─ 锄头成功 → FARMLAND

FARMLAND
  └─ 谷物种子成功 → PLANTED

PLANTED
  ├─ 每日推进 → 更新成长值和阶段模型
  └─ 成熟后点击 → FARMLAND + grain
```

播种只有在以下条件全部成立时才成功：

- 当前选择是种子。
- 玩家拥有至少一颗对应种子。
- 目标在作用距离内。
- 目标地块为 `FARMLAND`。
- 地块没有现存作物。
- 当前季节允许种植，或目标位于温室。

播种事务先预检全部条件，再暂扣一颗种子并调用 `FarmingSystem.plant()`；如果种植失败，立即退回种子，保证背包和网格一致。

### 6.3 收获

成熟作物的点击优先于当前快捷栏选择。收获成功后：

- 清理当前阶段模型。
- 地块恢复为 `FARMLAND`。
- `grain` 加入背包。
- 经验加入 `GameState`。
- 发出已有收获事件。
- HUD 和快捷栏刷新。

未成熟作物被点击时不改变状态，可通过提示或高亮表达当前阶段和成长进度。

## 7. 工具动作

工具系统调整为“先验证动作、成功后扣体力”：

1. 判断目标类型和动作是否可执行。
2. 检查体力。
3. 执行系统状态修改。
4. 只有执行成功才扣除体力并发出事件。

这可以避免以下错误：

- 对耕地重复使用锄头仍扣体力。
- 对无效地块浇水仍扣体力。
- 建造模式点击同时消耗工具体力。

本次只完整验收锄头和浇水壶。斧头、镐和鱼竿保留现有入口，后续再接入真实世界目标。

## 8. 建造流程

### 8.1 选择和预览

`BuildUI` 继续负责展示建筑列表和选择建筑。选择后：

- `BuildingSystem.enter_preview_mode()` 创建预览。
- `PlayerActionController` 根据鼠标地块持续更新预览。
- 现有占地格标记显示建筑 footprint。
- 有效位置为绿色，无效位置为红色。

### 8.2 放置与施工

点击有效位置后：

1. 再次验证 footprint、地形和材料。
2. 原子扣除建材。
3. 将占用地块切换为 `BUILDING`。
4. 创建建筑实例。
5. 从 `FOUNDATION` 开始施工。
6. 自动推进到 `FRAME`、`HALF_BUILT` 和 `COMPLETE`。

沿用现有施工时长：

- `1×1`：3 秒
- `2×2`：4 秒
- `3×3` 及更大：5 秒

建筑完成前不开放成品交互区域；完成后恢复建筑碰撞、交互和镜头遮挡行为。

### 8.3 初始资源

新存档提供足够的谷物种子和基础建材，使玩家可以立即完成一次完整种植流程，并至少验证两种建筑。该数值属于当前开发阶段的起始配置，后续由经济平衡任务重新调整。

## 9. 地块视觉反馈

`GridSystem` 继续负责实际高亮网格，`PlayerActionController` 只决定颜色：

| 颜色 | 含义 |
|---|---|
| 绿色 | 当前选择可以作用于该地块 |
| 红色 | 当前选择不可作用于该地块 |
| 金色 | 成熟作物，点击可收获 |
| 蓝色 | 当前水壶可浇水 |

离开地图、鼠标进入 UI 或没有有效交点时清除高亮。进入建造模式后，普通单格高亮让位给建筑 footprint 预览。

## 10. 初始化与存档

主场景初始化顺序调整为：

1. 创建系统节点。
2. 连接网格、种植、经济、建造和工具依赖。
3. 注册谷物物品和作物数据。
4. 尝试读取存档。
5. 如果没有存档，创建初始背包和快捷栏。
6. 恢复作物与建筑状态。
7. 重建作物和建筑视觉。
8. 配置 PlayerActionController。
9. 刷新 HUD、快捷栏和其他 UI。

需要恢复的数据：

- 变化后的地块状态。
- 已种作物、成长值和当天浇水状态。
- 建筑位置、占地和施工阶段。
- 背包物品和快捷栏映射。

加载旧存档时，如果不存在 `grain_seed` 或快捷栏第六格，允许使用默认映射补齐，但不能重复发放整个新游戏初始物资。

## 11. 错误处理与一致性

- 无效目标不消耗体力、种子或建材。
- 播种失败不残留作物实例或模型。
- 建造失败不残留占地状态、预览或扣除材料。
- 背包已满导致收获物无法加入时，不先清除作物；收获必须保持可重试。
- UI 拦截的鼠标点击不得穿透到世界。
- 建造模式退出时必须清除 footprint 和建筑预览。
- 场景卸载或重新加载时断开重复信号连接。

## 12. 测试与视觉验收

### 12.1 单元测试

为 `PlayerActionController` 增加确定性测试，覆盖：

- 建造优先于所有地块动作。
- 交互对象优先于地块动作。
- 成熟收获优先于当前工具或种子。
- 种子仅作用于空耕地。
- 工具仅作用于对应有效目标。
- 距离外的种植、浇水和收获被拒绝。
- 数字键和鼠标快捷栏选择产生相同状态。

### 12.2 系统集成测试

覆盖完整种植流程：

1. 获取荒地。
2. 锄地。
3. 选择谷物种子。
4. 播种并验证种子减少。
5. 浇水。
6. 推进日期并验证模型阶段变化。
7. 成熟后点击收获。
8. 验证谷物、经验、地块状态和模型清理。

覆盖完整建造流程：

1. 进入建筑预览。
2. 检查有效和无效 footprint。
3. 点击放置。
4. 验证材料扣除和地块占用。
5. 验证四个施工阶段。
6. 验证成品交互与碰撞恢复。

### 12.3 主场景验收

- 启动真实 `main.tscn`，确认没有 GDScript 解析错误或运行时错误。
- 验证主场景中的系统引用全部存在且指向同一套实例。
- 验证玩家移动、镜头、NPC 和原地图内容没有回归。
- 捕获主游戏画面，至少同时包含：
  - 已开垦农田
  - 一个或多个谷物成长阶段
  - 成熟谷物
  - 一个施工中的建筑
  - 一个已完成建筑
- 对截图进行人工视觉检查，确认模型风格、地形贴合、遮挡和比例正确。
