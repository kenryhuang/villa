# 建筑外围制品与点击收取设计

**日期：** 2026-08-08
**状态：** 已确认
**适用范围：** 所有持有 `ProducerState.outputs` 的已建成建筑
**修订：** 补充读档后信号重连与明确的成功入库动画

## 1. 背景

生产完成后，建筑目前通过 `BuildingInstance` 上的 `Label3D` 显示“收”字。该标签没有碰撞体和点击处理，位置还可能落在建筑交互区域之外。玩家点击它不会触发收取；射线命中建筑时，只会沿现有 `interacted` 信号打开建筑经济面板。

本功能移除“收”字，将待收制品以手绘 2D 货堆摆在建筑外围。玩家点击某一货堆，即可把该建筑内对应种类的全部制品收进玩家资产库。

## 2. 目标

- 生产完成后不再显示“收”字。
- 根据建筑的真实待收产物，在外围为每种制品展示一个货堆。
- 每种制品对应一个独立可点击货堆。
- 点击货堆只收取该货堆对应的制品种类。
- 制品数量越多，货堆外观越丰满；场景中不常驻显示数字。
- 悬停货堆时显示物品名称和准确数量。
- 继续使用现有生产系统的容量检查、事务回滚、事件和资产库写入逻辑。
- 存档仍只保存经济数据，不保存派生的视觉节点。

## 3. 非目标

- 不把每个制品单位拆成独立世界掉落物。
- 不改变生产配方、产量、耗时或建筑输出容量。
- 不取消建筑经济面板中的生产、队列和库存信息。
- 不修改“满”和“修”的异常状态提示。
- 不允许在活跃的建造放置操作中点击货堆收取。

## 4. 适用建筑

适用条件以建筑是否持有非空的 `ProducerState.outputs` 为准，而不是硬编码建筑名单。该规则自然覆盖：

- 加工建筑：石窑、工作台、熔炉、风车、食品工坊、纺织机。
- 资源建筑：伐木场、采石场、矿场。
- 被动产出建筑：蜂房、鸡舍及以后接入 `ProducerState.outputs` 的建筑。

建筑必须已建成、有效且未处于预览模式，才显示并启用外围货堆。

## 5. 设计方案

采用“每种制品一个独立货堆”的方案。货堆是 `ProducerState.outputs` 的视觉投影，不持有权威经济状态。

未采用的方案：

- 装饰货堆、点击整座建筑收取：不能满足点击哪一堆就收取哪一种。
- 每单位生成一个掉落物：会造成场景杂乱、节点过多并扩大存档复杂度。

## 6. 组件结构

### 6.1 `BuildingOutputDisplay`

由 `BuildingInstance` 持有，职责仅包括：

- 接收当前输出表和数量容量。
- 为每种输出创建、更新或移除一个 `BuildingOutputPile`。
- 按稳定规则排列货堆。
- 控制建筑预览、施工、隐藏或停用时的可见性。
- 将子货堆的收取请求转发给建筑实例。

该组件不直接依赖或修改 `InventorySystem`、`ProductionSystem` 或存档。

### 6.2 `BuildingOutputPile`

一个货堆代表一种 `item_id`，包含：

- 地面锚定的 `Sprite3D`。
- 独立 `Area3D` 与碰撞形状。
- 当前展示数量和容量占比。
- 悬停描边、提示和点击反馈。
- `collection_requested(item_id)` 信号。

货堆不直接把物品写入资产库，也不自行删除权威输出。

### 6.3 `BuildingInstance`

建筑实例负责：

- 创建并配置 `BuildingOutputDisplay`。
- 提供 `sync_output_display(outputs, quantity_capacity)` 接口。
- 转发 `output_collection_requested(building, item_id)`。
- 彻底取消 `collect` 类型的文字指示器。
- 继续支持 `full` 和 `maintenance` 指示器。

### 6.4 编排层

`Main` 连接建筑的 `output_collection_requested` 信号，并调用：

```gdscript
production_system.collect_outputs(building, inventory_system, item_id)
```

视觉组件不持有全局系统引用。收取仍由 `ProductionSystem` 作为权威业务入口。

## 7. 数据流

### 7.1 生产完成

1. `ProductionSystem` 将制品加入 `ProducerState.outputs`。
2. 系统发出既有的 `production_output_changed` 事件。
3. `ProductionSystem.refresh_indicator()` 同步建筑的输出展示。
4. `BuildingOutputDisplay` 对比当前货堆与输出表。
5. 新种类淡入、已有种类更新丰满程度、归零种类淡出并移除。

### 7.2 点击收取

1. 玩家射线命中 `BuildingOutputPile` 的独立交互区域。
2. 货堆发出建筑和 `item_id` 对应的收取请求。
3. `Main` 调用现有 `collect_outputs()`。
4. `InventorySystem.preflight_add_items()` 检查资产库容量。
5. 成功时，生产系统以现有事务流程写入资产库并从 `outputs` 扣除该种物品。
6. 既有事件刷新 HUD、经济面板和外围货堆。
7. 失败时，权威数据保持不变，货堆播放失败反馈。

一次点击收取该建筑内该种制品的全部数量，不逐单位收取，也不影响其他种类。

## 8. 视觉设计

### 8.1 风格

所有货堆使用透明背景、手绘 2D、地面锚定素材，颜色、轮廓粗细和光照方向与现有手绘建筑一致。不使用灰色占位几何体作为最终表现。

采用可复用的制品家族，并通过颜色和局部细节区分具体物品：

1. 原木与木板。
2. 石材与砖块。
3. 矿石、煤炭与水晶。
4. 金属锭、机械零件与工具。
5. 麻袋、面粉与饲料。
6. 玻璃罐、玻璃瓶及瓶装制品。
7. 布料与绳索。
8. 食品与篮筐。
9. 箱子、家具与大型制品。
10. 蜂蜜、鸡蛋及精细制品。

必须为所有可能进入 `ProducerState.outputs` 的物品配置视觉家族。缺少显式配置时使用手绘通用木箱兜底，并在开发版本产生一次警告。

### 8.2 丰满程度

货堆有三个稳定外观等级：

- 少量：占数量容量的 1%–33%。
- 中量：34%–66%。
- 大量：67%–100%。

如果建筑没有数量容量配置，则以该物品当前数量使用离散阈值：1 为少量、2–3 为中量、4 以上为大量。货堆切换等级时底部锚点必须保持固定，不能发生跳动。

### 8.3 石窑示例

- 木炭：黑褐色不规则炭块堆。
- 石砖：浅灰色规整砖堆。
- 砖块：红褐色烧制砖堆。

## 9. 外围布局

每种非零输出都必须拥有一个可点击货堆，显示数量不得硬编码为三种。当前矿场基础产物种类容量为 4，三级仓储升级后最高为 7；布局必须覆盖该上限，不能把超出前三种的制品隐藏到面板中。

输出种类先按 `item_id` 稳定排序，再分配确定性外围锚点：

1. 右前方。
2. 左前方。
3. 右侧方。
4. 左侧方。
5. 右前外侧。
6. 左前外侧。
7. 正前外侧。

一至四种使用建筑紧邻外围锚点；五至七种使用第二圈外侧锚点，并将货堆统一缩放到最低 75%，避免遮挡。锚点根据建筑占地尺寸、货堆数量和固定外围间距计算，不使用世界坐标或逐建筑临时偏移。货堆应位于建筑交互体之外，但仍靠近占地边缘。

布局必须满足：

- 不遮挡建筑主体、主要入口和活动动画。
- 不与建筑碰撞体重叠。
- 相同输出在刷新和存档加载后保持相同位置。
- `Sprite3D` 使用 Billboard，以适配当前锁定方向的相机。
- Sprite 底部落在地面，使用稳定排序偏移，避免与建筑层闪烁。

## 10. 悬停与点击反馈

### 10.1 悬停

- 货堆出现柔和绿色描边。
- 播放轻微上浮或呼吸动画。
- 临时显示“石砖 ×4”形式的名称与准确数量。
- 鼠标移开后立即恢复，不保留常驻数字。

### 10.2 成功收取

- 只有 `ProductionSystem.collect_outputs()` 成功提交后才开始播放动画。
- 货堆在约 0.45 秒内原地上浮、缩小并淡出，动画期间立即停用点击，避免重复收取。
- 货堆上方同步显示绿色“物品名称 +数量”，随货堆上浮并淡出，明确表示制品已经进入资产库。
- HUD 继续使用现有资产增加反馈。
- 若该物品仍有剩余，则按照最新数量级别重建或更新货堆。

### 10.3 失败收取

资产库容量不足或事务失败时：

- 不改变 `ProducerState.outputs`。
- 不播放成功动画。
- 货堆短暂左右晃动并显示红色描边。
- HUD 显示“资产库空间不足”或对应事务失败信息。

## 11. 输入、距离与优先级

- 货堆使用播放器现有射线查询可命中的独立交互层。
- 货堆碰撞形状贴合可见范围，避免点击透明区域。
- 正常游戏/农场模式允许悬停和收取。
- 活跃的建筑放置模式保持最高优先级，不触发货堆交互。
- 玩家必须位于现有 `interaction_range` 内。
- 距离不足时不得静默失败，应短暂提示“距离太远”。
- 点击建筑空白区域继续打开原有建筑经济面板。

## 12. 状态指示器

`ProductionSystem.refresh_indicator()` 不再为非空输出设置 `collect`。

- 普通待收输出：只显示外围货堆。
- 输出仓储已满：货堆显示最大丰满程度，同时保留红色“满”。
- 维护逾期：保留“修”。
- 没有待收输出：不显示货堆。

建筑活动动画的既有启停规则保持不变。

## 13. 保存与加载

不保存下列派生状态：

- 货堆节点。
- 货堆位置。
- 悬停、描边或动画进度。
- 视觉丰满等级。

存档继续只保存现有 `producer_state.outputs`。加载建筑并恢复 `ProducerState` 后，注册流程调用输出展示同步，按权威输出重建货堆。因此不需要存档格式迁移。

`SaveManager` 为保证读档事务原子性，以不发送公开建筑放置信号的方式恢复建筑。读档成功后的编排层必须重新扫描全部已恢复建筑，并幂等连接 `interacted` 与 `output_collection_requested`；不能依赖读档前的初始扫描。连接失败或遗漏时，货堆虽然能由生产系统重建，但点击请求无法抵达资产库。

## 14. 兼容性与失败边界

- 建筑未完成、处于预览、已停用或即将移除时，货堆不可见且没有碰撞。
- 建筑移除时一并释放其派生货堆，不留下可交互孤儿节点。
- 输出事件重复到达时，同步必须幂等，不重复生成同一 `item_id` 的货堆。
- 未知或无效 `item_id` 不生成可收取节点，并在开发版本产生一次警告。
- 收取请求到达时如果建筑、货堆或对应输出已失效，按 `nothing_to_collect` 处理，不修改资产库。

## 16. 测试与验收

### 16.1 单元测试

- 输出表为空时不生成货堆。
- 每个 `item_id` 最多存在一个货堆。
- 一至七种输出都能稳定占用各自外围锚点。
- 输出归零后货堆移除。
- 数量占比正确映射到少、中、大三个外观等级。
- 建筑预览、施工和停用状态禁用货堆及碰撞。
- 所有生产输出物品均有显式视觉家族或通用兜底。

### 16.2 业务测试

- 点击某一货堆只收取对应种类。
- 成功收取正确写入玩家资产库并清除建筑对应输出。
- 其他输出种类保持不变。
- 资产库容量不足时源和目标均不变。
- 事务失败时完整回滚。
- 收取成功后继续准备被输出容量阻塞的已完成任务。
- 成功动画携带实际收取前的物品名称和数量，并在动画开始时禁用再次点击。

### 16.3 集成测试

- 石窑完成木炭后不再显示“收”，外围出现木炭货堆。
- 石窑同时持有木炭、石砖和砖块时显示三堆。
- 点击石砖货堆只收取石砖。
- 点击建筑主体仍打开生产面板。
- 距离不足时显示反馈且不收取。
- “满”和“修”仍正确显示。
- 存档重载后货堆根据 `outputs` 正确重建。
- 真实 `SaveManager.load_game()` 恢复的既有建筑会重新连接收取信号；点击恢复后的货堆能写入资产库并清除输出。
- 成功收取后显示绿色“名称 +数量”，货堆上浮、缩小、淡出并最终释放。
- 加工、资源和被动产出建筑采用相同规则。
- 现有生产、经济、建筑及主游戏集成测试全部通过。

## 17. 完成标准

功能完成必须同时满足：

1. 游戏中不再出现生产完成“收”字。
2. 所有持有待收输出的建筑都能显示风格统一的外围货堆。
3. 点击货堆能可靠地把对应种类的全部制品写入资产库。
4. 容量不足、距离不足和事务失败都有明确反馈且不丢失数据。
5. 保存加载不需要迁移并能正确重建视觉状态。
6. 自动化测试和实际石窑交互验证均通过。
