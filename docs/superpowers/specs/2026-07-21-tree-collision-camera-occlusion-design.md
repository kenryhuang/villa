# Tree Collision and Camera Occlusion Design

## Goal

Prevent the player, NPCs, and projectiles from passing through tree trunks while keeping navigation around the canopy natural. When a tree visually blocks the camera's view of the player, fade that tree smoothly to 30% opacity and restore it when it no longer blocks the view.

## Scope

This change covers the 28 runtime trees generated by `VegetationBuilder`, actor/projectile collision masks, and camera-to-player occlusion detection. It does not add pathfinding, tree destruction, resource gathering, wind animation, or new vegetation art.

## Collision Layers

The project will use these explicit 3D physics layers:

| Layer value | Purpose |
| --- | --- |
| `1` | Terrain and other static world geometry |
| `2` | Player |
| `4` | NPCs |
| `8` | Projectiles |
| `16` | Physical tree-trunk obstacles |
| `32` | Camera-only tree-canopy occlusion areas |

Actor masks change as follows:

- Player mask: `21` (`terrain + NPC + tree trunk`).
- NPC mask: `19` (`terrain + player + tree trunk`).
- Projectile mask: `21` (`terrain + NPC + tree trunk`).
- Tree obstacles use layer `16`, mask `0`.
- Camera occlusion areas use layer `32`, mask `0`; they are queryable but do not produce physical contacts.

The aiming ray remains on terrain layer `1`, so clicking through a tree still selects the ground rather than the tree canopy.

## Tree Runtime Structure

Each generated placement becomes a `TreeInstance` Node3D at the sampled terrain position instead of a standalone Sprite3D.

```text
TreeInstance
├── Sprite3D
├── TrunkBody (StaticBody3D, layer 16)
│   └── CollisionShape3D (CylinderShape3D)
└── CameraOccluder (Area3D, layer 32)
    └── CollisionShape3D (CapsuleShape3D)
```

The sprite remains a camera-facing billboard. It is positioned locally at half the authored tree height and retains the existing explicit width/height scaling.

The trunk cylinder is intentionally smaller than the painted canopy and root patch. Its radius is `clamp(clearance × 0.36, 0.24, 0.46)` world units. Its height is `clamp(tree height × 0.42, 0.65, 1.10)` world units, covering only the lower trunk. This prevents walking through the trunk without making the whole tree crown feel like an invisible wall.

The camera occlusion capsule covers the visible trunk and canopy. Its radius is `tree width × 0.46`; its total height is the greater of `tree height × 0.90` and twice that radius. It is separate from the physical cylinder so camera detection can use the full painted tree silhouette without affecting actor movement.

## Camera Occlusion

`CameraRig` casts a ray from the active Camera3D position to the player's upper body every frame using only layer `32` and `collide_with_areas=true`. The query repeats while excluding previous hits so multiple aligned trees can fade simultaneously, with a maximum of eight hits per frame.

Each hit resolves to its owning `TreeInstance`. Hit trees receive an occluded target opacity of `0.30`; all other registered trees receive `1.0`. Opacity uses exponential interpolation with rate `10.0`, completing the visibly significant part of the transition in about `0.2` seconds. The transition runs on the tree instance rather than CameraRig so rendering state remains encapsulated.

Tree sprites use an alpha mode that supports smooth whole-sprite opacity while preserving transparent leaf edges. A faded tree must not write an opaque canopy into the depth buffer and hide the player.

If the camera has no valid target, leaves the scene tree, or a query returns no hits, all trees restore toward full opacity. Freed tree instances are ignored safely.

## Interfaces

`TreeInstance` provides:

- `configure(tree_data: Dictionary, texture: Texture2D, terrain_height: float) -> void`
- `set_camera_occluded(value: bool) -> void`
- `get_trunk_radius() -> float`
- static deterministic helpers for collision dimensions and opacity stepping.

`VegetationBuilder` continues to expose `build(terrain, route) -> int`, but it creates 28 `TreeInstance` roots and registers their occlusion areas.

`CameraRig` continues to expose its existing movement/orbit interface. Occlusion detection is internal and requires no changes to Player.

## Testing

Automated checks will cover:

- Trunk radius remains within the `0.24–0.46` limits for small and large variants.
- Opacity moves toward `0.30` when occluded and back toward `1.0` when clear.
- A built world produces 28 tree roots, each with one layer-16 trunk body and one layer-32 occlusion area.
- Player, NPC, and projectile masks include layer `16` while retaining their previous contacts.
- Translating or rotating the camera does not leave a previously faded tree permanently transparent.
- The complete test suite and headless main-scene launch remain clean.

Visual acceptance will exercise walking into trunks from multiple angles, moving behind a tree, placing two trees along the camera ray, rotating with Q/E and middle drag, zooming, and moving away until opacity fully restores.

## Success Criteria

- The player cannot cross any painted tree trunk or stand inside it.
- NPCs and projectiles respect the same trunk obstacles.
- Canopies do not create oversized invisible movement barriers.
- Every tree between camera and player fades smoothly to 30% and restores smoothly.
- Trees not obstructing the player remain fully opaque.
- No alpha halos, depth-order popping, permanent faded state, parse errors, or missing resources occur.
