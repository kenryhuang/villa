# Villa 建造与生产产业链连接设计

**日期：** 2026-08-06

**状态：** 已实现

**上位设计：** `docs/superpowers/specs/2026-08-01-dynamic-economy-system-design.md`

**范围：** 原材料采集、建筑目录、蓝图解锁、建筑造价、施工完成、建筑生产、成品收取、市场出口与存档兼容

## 1. 目标

把已经存在但入口分散的采集、建造、生产和经济能力连接为一条完整、可发现、可持续的玩家产业链：

> 手动采集原料 → 建造基础设施 → 制作加工建材 → 解锁并建造高级设施 → 生产成品 → 收取后继续建造或进入市场、订单和合同。

本次采用“补齐现有纵向链”的方案。保留现有 `InventorySystem`、`BuildingSystem`、`BuildingInstance`、`ProductionSystem`、`EconomyProgressionSystem`、市场和存档系统作为权威状态来源，只新增或修复连接层，不引入第二套库存、生产队列或物流状态。

## 2. 已确认决策

- 建造栏展示当前定义的全部 17 种建筑。
- 未解锁建筑保留在建造栏中并灰显，不从列表隐藏。
- 点击未解锁建筑显示具体条件，并可前往经济中心的服务/蓝图页定位对应项目。
- 点击“开始生产”时直接从玩家背包原子扣除全部原料。
- 成品进入建筑输出仓，由玩家手动收取到背包。
- 基础建筑主要消耗原材料，高级建筑逐步消耗木板、石砖、砖块、玻璃、铁锭、钢材、机械零件等加工品。
- 一次接通当前全部建筑和全部配方，同时修复缺失原料来源、旧物品 ID、不可达配方与建造依赖死锁。
- 前期以玩家手动采集为主；伐木场和采石场在一级产业阶段解锁，矿场在二级产业阶段解锁。

## 3. 当前实现审查

### 3.1 已经可复用的能力

- `BuildingSystem` 已能预检资源、原子扣除造价、占用网格并生成施工中的建筑。
- `BuildingInstance` 已能按帧推进施工，完成前禁止打开经济面板，完成后提供交互信号。
- `ProductionSystem` 已能预检配方、从背包原子扣料、推进队列、处理仓满与维护暂停，并把成品写入建筑输出仓。
- `BuildingEconomyUI` 已区分加工建筑面板与被动生产建筑面板。
- `RecipeDatabase` 已定义工作台、石窑、熔炉、风车、食品工坊、纺织机和厨房配方。
- `EconomyProgressionSystem` 已支持蓝图、配方、升级和维护服务。
- 市场、订单、合同、通知和存档已能处理多数原料与加工品。

### 3.2 当前断点

- HUD 建造栏由 `PlayerActionController.BUILDING_IDS` 和 `VillaHud.BUILDING_NAMES` 两套 9 项数组硬编码，8 种已定义建筑无法从主要建造入口选择。
- `BuildUI` 能枚举全部建筑，但不使用与 HUD 一致的蓝图状态，两个入口可能产生不一致结果。
- 石窑造价包含黏土，熔炉造价包含自身才能生产的铁锭，存在启动门槛或循环依赖。
- 路灯造价仍使用旧物品 ID `iron`，而当前采集与加工链使用 `iron_ore` 和 `iron_ingot`。
- 世界资源目录不再生成黏土和沙子，但砖块与玻璃配方仍需要它们。
- `glass_jar` 和 `glass_bottle` 是食品配方输入，却没有玩家可执行的制作配方。
- 面包与蜂蜜蛋糕绑定到不存在的 `kitchen` 建筑，无法由玩家生产。
- 多个高阶工作台配方没有对应解锁服务，理论上存在但正常流程不可达。
- 伐木场、采石场、食品工坊等建筑未被完整纳入蓝图分级，导致“显示全部建筑”时锁定规则不统一。

## 4. 系统边界与权威来源

### 4.1 静态定义

`GameData.BUILDINGS` 是建筑目录的唯一静态来源。每个建筑定义补充：

- `category`：`basic`、`production`、`farming`、`resource`、`decoration`；
- `palette_order`：分类内稳定排序；
- `cost`：最终建造造价；
- 现有名称、描述、占地、效果、生产站和效果配置继续保留。

`BuildingData.from_dictionary()` 接收分类和排序字段。未知分类回退到 `basic`，缺少排序时按建筑 ID 稳定排序，同时仅警告一次。

### 4.2 解锁状态

`EconomyProgressionSystem` 是蓝图和配方解锁的唯一权威来源：

- 所有 17 种建筑都能返回明确的 `unlocked`、`locked_reason` 和可选 `service_id`；
- 零级建筑在新游戏时直接解锁；
- 一级、二级建筑通过服务页购买蓝图；
- 装饰建筑也使用明确规则，不再依赖“未被管理即默认可建造”的隐式行为；
- 购买建筑蓝图时，继续自动解锁该生产站中不高于蓝图等级的配方；
- 超过建筑蓝图等级的配方通过配方服务解锁。

### 4.3 库存与事务

`InventorySystem` 是玩家物品数量的唯一来源。建造栏和生产面板只读取库存进行预览：

- 建造扣料只能由 `BuildingSystem` 在成功落地时提交；
- 配方扣料只能由 `ProductionSystem.start_recipe()` 提交；
- 输出收取只能由 `ProductionSystem.collect_outputs()` 提交；
- UI 不直接增删物品；
- 任一提交失败都回滚库存、快捷栏映射、队列或网格状态，并只发送一次最终结果事件。

### 4.4 建造目录视图

增加一个无持久化状态的建筑目录查询层，供 HUD、`BuildUI` 和测试共同使用。每个条目包含：

```gdscript
{
    "building_id": "furnace",
    "display_name": "熔炉",
    "category": "production",
    "palette_order": 20,
    "blueprint_unlocked": false,
    "lock_reason": "需要一级熔炉蓝图",
    "unlock_service_id": "blueprint_furnace",
    "cost": {"stone_brick": 25, "brick": 15, "charcoal": 10},
    "resource_report": {...},
    "state": "locked"
}
```

合法 `state` 只有：

- `locked`：蓝图未解锁；
- `missing_resources`：已解锁但材料不足；
- `ready`：已解锁且材料充足；
- `invalid`：静态数据、场景或服务映射损坏。

## 6. 原材料来源

### 6.1 保留的采集来源

| 原料 | 来源 | 规则 |
|---|---|---|
| 木材 | 可砍伐树木 | 单次点击完成整棵树采集，3 秒动画，获得木材×5 |
| 纤维 | 可砍伐树木的副产物、市场 | 每棵可砍伐树额外获得纤维×1；木材产量仍严格为 5 |
| 石材 | 普通矿点 | 单次点击采完，沿用 3 秒采矿动画 |
| 煤、铜矿、铁矿 | 普通矿区 | 沿用当前资源点、工具耐久与刷新规则 |
| 银矿、金矿、水晶 | 稀有矿区 | 沿用当前较低容量和较长刷新时间 |

### 6.2 补齐的资源点

重新把黏土和沙子作为当前版本资源，而不是恢复旧的随机奖励模型：

| 资源 | 数量与区域 | 单点产量 | 刷新 | 工具 | 视觉 |
|---|---|---:|---:|---|---|
| 黏土 | 河岸 2 个固定点 | 4 | 3 天 | 镐 | 固定底座的暖褐色土团，3 帧耗尽 |
| 沙子 | 河岸 2 个固定点 | 4 | 3 天 | 镐 | 固定底座的浅黄色砂岩堆，3 帧耗尽 |

两者复用现有一次性采矿事务、绿色/红色圆环、3 秒三帧淡出淡入和存档格式。新增资源使用新的稳定 ID；旧存档缺少这些记录时按满容量补齐，不覆盖现有资源状态。

### 6.3 市场专属与补充来源

- 盐保留为市场专属基础商品，使食品加工仍需要与区域经济发生联系。
- 所有常见原料继续允许从市场购买，避免资源刷新期间完全卡死。
- 伐木场每日产出木材×3，并每 2 天额外产出纤维×1。
- 采石场每日产出石材×3，并每 3 天额外产出煤×1。
- 矿场继续按深度产出铜矿、铁矿、煤、银矿、金矿和水晶，不产出加工后的金属锭。

### 8.1 无循环依赖约束

- 熔炉不得消耗铁锭、钢材、玻璃或其他只能由熔炉首次生产的物品。
- 工作台和石窑不得消耗任何加工品作为首次建造条件。
- 任何蓝图服务的材料成本不得要求该蓝图建筑才能首次生产的物品。
- 高级建筑可以要求同级中更早可建造的设施产物，例如采石场要求熔炉支持的农具链。
- 自动化建筑不能成为其自身蓝图服务材料的唯一来源。

实现中增加静态依赖图测试，从开局原料集合出发迭代解锁，必须最终覆盖全部建筑与配方。

## 9. 建造栏 UI

### 9.1 布局

建造模式继续位于 HUD 底部，但从单层 9 项快捷栏改为两层结构：

1. 分类栏：基础、生产、农业、资源、装饰；
2. 当前分类的建筑卡片栏，每组最多 4 个卡片。

由于各组最多 4 个建筑，1920×1080 和 1280×720 下都不需要把 17 张卡片压缩到同一行。3000×2000 下保持同样的卡片最大宽度，不无限拉伸。

### 9.2 操作

- `B`：进入或退出建造模式；
- 鼠标点击分类标签：切换分类；
- 建造模式下 `Q/E`：切换上一个或下一个建造分类，不恢复相机旋转；
- 数字键 `1–4`：选择当前分类对应建筑；
- `Esc` 或右键：取消当前预览；
- 放置成功后保留建筑选择；资源不再足够时退出预览并显示缺口。

### 9.3 卡片状态

| 状态 | 表现 | 点击结果 |
|---|---|---|
| 可建造 | 正常彩色，绿色细描边 | 进入建筑预览 |
| 材料不足 | 保留彩色，材料数字变红，卡片为暖红描边 | 不进入预览，显示逐项缺口 |
| 未解锁 | 降饱和灰显，右上角锁图标 | 打开锁定详情 |
| 数据异常 | 暗红占位卡与警告图标 | 显示“建筑数据不可用”，不改变状态 |

锁定详情包含建筑用途、最终造价、日期/等级门槛、金币和服务材料，并提供“前往解锁”。按钮调用 `Main.open_economy_tab("services", service_id)`，由服务面板定位并高亮对应条目。

### 9.4 建造成本条

选中已解锁建筑后，沿用 HUD 底部成本条，但改为遍历真实造价中的全部物品，不再只支持木材、石材、旧铁和玻璃：

- 显示物品图标、需要量和拥有量；
- 数量足够为米白色，不足为红色；
- 找不到专用图标时使用物品名称首字占位，不阻塞建造；
- 背包变化、服务解锁或调试重置后立即刷新。

## 10. 施工与建筑激活

建造提交继续由 `BuildingSystem.try_place_building()` 完成：

1. 重新检查蓝图、网格和完整造价；
2. 预创建建筑实例与网格快照；
3. 原子扣除造价并占用网格；
4. 成功后生成初始施工框架；
5. 失败时回滚库存、快捷栏映射、网格和实例。

施工帧、10 秒最大单帧时长、锤子动画、淡出淡入和完成后锤子消失沿用现有实现。施工中建筑：

- 不能启动配方；
- 不产生被动产出和范围效果；
- 不打开生产面板；
- 点击只显示施工进度；
- 完成后自动注册到 `ProductionSystem`，无需重新加载场景。

## 11. 生产与收取 UI

### 11.1 加工建筑

完整建成的工作台、石窑、风车、熔炉、食品工坊和纺织机继续使用三栏面板：

- 左栏：该生产站的全部配方；
- 中栏：当前生产队列与剩余游戏时间；
- 右栏：建筑输出仓与逐项/全部收取；
- 下方详情：输入、输出、批次数量、最大批次、工期、市场估值和失败原因。

点击开始生产时：

1. 校验建筑完成、维护、配方解锁、站点匹配、队列空间和完整原料；
2. 一次性从玩家背包扣除当前批次全部输入；
3. 新任务为空队列时立即运行，否则进入等待；
4. 游戏时间推进 `remaining_minutes`；
5. 完成后尝试写入建筑输出仓；仓满时保持完成待入库状态，不丢失产品；
6. 玩家收取时先校验背包容量，再原子转移。

首版不增加取消、退款、拖拽排序、独立输入仓或建筑间自动物流。

### 11.2 被动建筑

- 蜂箱、鸡舍、伐木场、采石场和矿场按日结算产出到各自输出仓；
- 鸡舍仍需预先投入动物饲料；
- 水车、温室、谷仓继续显示范围、容量或状态信息；
- 被动输出仓满时暂停新增产出并发送合并通知；
- 收取成功后解除仓满状态。

### 11.3 世界反馈

- 配方完成：沿用经济通知，并在建筑右上方显示小型“可收取”包裹图标；
- 输出仓满：包裹图标增加红色描边；
- 维护暂停：显示扳手图标；
- 图标只表达状态，不接管点击区域；点击建筑仍打开统一建筑面板。

## 12. 市场、订单与再投入

- 所有加工品继续进入有限库存市场，使用当前动态价格和滑点规则；
- 玩家收取后可以直接在市场出售，或交付订单与合同；
- 建造预检只读取玩家背包，不直接读取建筑输出仓；玩家必须先收取成品才能用于建造；
- 建筑造价中的成品也保持可交易，因此玩家可以选择自己生产或从市场购买；
- 盐作为市场专属输入，确保食品产业与市场保持联系；
- NPC 生产和需求继续使用同一物品 ID，不为玩家链创建专用副本。

## 13. 存档与迁移

### 13.1 不需要持久化的内容

- 建筑分类、排序、造价和服务映射是静态数据；
- 建造栏当前分类和临时锁定详情不写入存档；
- 建筑目录视图随 UI 打开实时重建。

### 13.2 继续持久化的内容

- 已放置建筑、施工阶段和位置；
- `ProducerState` 中的队列、输入、输出、容量和站点；
- 蓝图、配方、升级和维护状态；
- 世界资源剩余量与刷新日；
- 玩家库存、市场、订单和合同状态。

### 13.3 兼容策略

- 进程存档版本升级时保留已有蓝图和配方；
- 新的零级建筑自动补为已解锁；
- 扫描旧存档中已经放置的建筑并补解锁对应蓝图，禁止出现“已有建筑但建造栏仍锁定”的状态；
- 已在运行或等待的旧队列继续执行，即使新版本调整了解锁分组；
- 新增黏土和沙子资源点在旧存档中按满容量补齐，现有资源记录不重置；
- 已经支付造价的建筑不追收新材料，也不退还差额；
- 旧 `iron` 库存继续按现有迁移规则转为 `iron_ingot`，所有新造价禁止再引用 `iron`。

## 14. 错误处理

- 任一建筑造价引用不存在的物品时，启动校验报错并将卡片标为 `invalid`。
- 任一配方输入或输出引用不存在的物品时，启动校验报错并禁止该配方开始。
- 任一生产站没有建筑、任一建筑没有场景、任一受管蓝图没有服务 ID 时，测试失败；运行时显示明确中文提示而不是静默失败。
- 解锁跳转目标不存在时，锁定详情仍显示条件，但“前往解锁”按钮禁用并记录一次警告。
- 建造或生产提交期间背包发生变化时，以提交时的第二次权威预检为准。
- 输出收取空间不足时保留建筑仓库原状态并列出缺少的背包格数或可容纳数量。
- UI 图标缺失时使用文字占位，不阻塞逻辑。

### 15.1 静态数据测试

- 建筑目录恰好包含 17 个唯一建筑 ID，分类和排序稳定。
- 每个建筑造价物品都存在且数量为正。
- 不再有建筑造价引用旧 `iron`。

- 从开局原料集合执行依赖闭包后，全部建筑与配方可达，不存在循环死锁。

### 15.2 系统测试

- 未解锁、缺料和可建造三种预检都不产生副作用。
- 建造提交只扣除一次完整造价；任一步失败完整回滚。
- 施工中的加工建筑拒绝生产，完成后立即允许生产。
- 开始多批次配方只生成一个权威事务，原料数量精确。
- 仓满时成品不丢失，收取后任务可以继续入库。
- 黏土和沙子使用一次性 3 秒采矿流程，刷新与保存正确。
- 每棵可砍伐树仍获得木材×5，并额外获得纤维×1。

### 15.3 UI 集成测试

- 五个分类合计显示全部 17 个建筑，无重复、无遗漏。
- 数字键选择当前分类建筑；建造模式下 `Q/E` 只切分类，不旋转相机。
- 锁定建筑灰显，点击后显示条件并能定位服务页。
- 缺料建筑显示逐项缺口且不进入预览。
- 服务购买后不重开场景即可刷新卡片并允许建造。
- 配方锁定行能定位对应服务；没有服务的错误数据不会崩溃。
- 1280×720、1920×1080、3000×2000 下分类栏、最多四张建筑卡、成本条和锁定详情均在视口内，且不与右上角经济操作区重叠。

### 15.4 完整纵向验收

使用新游戏真实系统完成以下自动化流程：

1. 砍树和采矿，把木材、纤维、石材、煤、黏土和沙子写入真实背包；
2. 建造工作台和石窑，推进施工至完成；
3. 制作木板、绳索、木炭、石砖和砖块并收取；
4. 通过服务页解锁熔炉并建造；
5. 熔炼玻璃、铜锭、铁锭，并制作玻璃罐和玻璃瓶；
6. 解锁并建造风车、鸡舍、伐木场、采石场；
7. 生产面粉、饲料和农具，收取鸡蛋与自动资源；
8. 解锁并建造食品工坊、纺织机、温室和矿场；
9. 生产至少一种高级食品、一种纺织品和一种机械制品；
10. 将成品用于高级建造、市场出售与订单交付；
11. 保存并重载，确认建筑、施工、队列、输出、解锁、世界资源和市场状态一致。

## 16. 非目标

本次不实现：

- 建筑之间的自动运输网络；
- 每栋建筑独立输入仓和搬运工；
- 生产队列取消、退款、拖拽排序；
- 工人 NPC 驻场与效率模拟；
- 新的厨房建筑；
- 新的铲子工具；
- 实时生产订单簿；
- 对现有建筑或成品进行整套新美术建模。

黏土、沙子和状态图标只制作完成玩法所需的最小风格一致视觉；其余美术升级另立设计。

## 17. 完成定义

当且仅当以下条件全部满足，本功能才视为完成：

- 玩家能从 HUD 找到全部建筑并理解锁定或缺料原因；
- 所有建筑和配方均通过正常游戏流程可达；
- 原材料、加工建材、建筑、成品与市场之间不存在断链或物品 ID 错误；

- 新旧存档不会丢失建筑、队列、输出或资源状态；
- 完整纵向验收与相关回归测试全部通过。
