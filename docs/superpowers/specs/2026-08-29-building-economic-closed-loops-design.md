# 建筑经济闭环设计

**日期：** 2026-08-29  
**范围：** 17 类现有建筑、地理资源约束、钓鱼、局部动力、自动物流、农业与工业生产链、市场出口、状态展示和存档
**目标：** 让每座建筑都具备明确的上游投入、运行条件、下游用途或成本优化作用，形成可理解、可平衡、可逐步自动化的经营闭环。

## 1. 已确认的设计决策

- 水车使用局部动力覆盖，不引入电线或全局动力点。
- 建筑采用渐进自动化：初期手动投料和收取，连接谷仓与适用动力后才能自动取料、连续生产和回仓。
- 伐木场、采石场和矿场需要轻量运营消耗，不能无限免费产出。
- 蜂箱读取附近成熟花卉；花卉不被消耗，但玩家收获后立即失去蜜源。
- 水车只能建在天然水域岸边；蜂箱可以先建造，但只有附近存在成熟花卉时才能产蜜。
- 钓鱼只允许在有效岸边鱼点进行，鱼种由水域、季节和时段共同决定，不再由鱼竿直接随机发放占位材料。
- 路灯和围栏具有轻度经济功能，不成为决定全部收益的强制网络。
- 加工建筑在正常游戏中约 30–120 秒完成一批；被动生产和资源建筑按游戏日结算。

## 2. 总体架构

每座建筑至少承担以下一种职责：

- 生产可交易或可加工商品；
- 把低价值原料加工为下游需要的材料；
- 持续消耗其他产业的产物；
- 降低人工、时间、运输或运营成本；
- 为市场、订单、建造或维护提供稳定出口。

建筑默认可以独立手动运行。局部产业网络只提供渐进优化，不让未接入网络的建筑失去基础用途。

```text
采集 / 种植 / 畜牧
        ↓
初级加工建筑
        ↓
高级加工建筑
        ↓
订单 / 市场 / 建造 / 维护
        ↑
资源建筑运营消耗

水车：局部灌溉 + 局部机械动力
谷仓：局部原料供应 + 成品回收
路灯/围栏：局部效率与运营损耗修正
```

## 3. 主要产业链

### 3.1 农业食品

```text
作物 → 风车 → 面粉 / 饲料 / 葵花油
                  ├→ 鸡舍 → 鸡蛋 / 羽毛
                  └→ 食品工坊 → 面包 / 蛋糕 / 果酱 → 市场与订单
```

### 3.2 花卉蜂业

```text
成熟花卉 ──空间距离──→ 蜂箱 → 蜂蜜 / 蜂蜡
   ├→ 食品工坊 → 蜂蜜蛋糕 / 果酱 / 花香蜂蜜
   ├→ 工作台 → 蜡烛
   └→ 花卉与纺织加工 → 香包 / 香水 / 花束
```

### 3.3 建材工业

```text
伐木场 / 采石场 → 工作台 / 石窑 → 木板 / 砖 / 木炭
矿场 → 熔炉 → 金属锭 / 钢材 / 玻璃
           └→ 工作台 → 工具 / 零件 / 灯具 / 珠宝
```

### 3.4 基础设施

```text
水井 → 初级供水
天然水域 → 岸边水车 → 自动灌溉 + 局部动力
天然水域 → 岸边鱼点 → 鱼类 / 漂流瓶 → 食品、订单与市场
谷仓 → 集中库存 + 自动物流
路灯 / 围栏 → 夜间效率 + 农牧运营优化
```

## 4. 建筑职责与闭环

| 建筑 | 输入或运行条件 | 产出或作用 | 下游闭环 |
|---|---|---|---|
| 谷仓 | 建造材料、维护；目标建筑位于半径 6 内 | 容量 +200、集中收取、自动网络原料库和成品库 | 服务农业、资源和加工建筑 |
| 温室 | 种子、耕地、水 | 8 个全年种植格，可种柠檬等温室专供作物 | 水果进入食品工坊、市场和订单 |
| 水车 | 占地可建造且至少一条占地边正交邻接天然水域、完成建造、维护有效 | 半径 4 自动灌溉并提供机械动力 | 降低农业劳动，解锁部分建筑自动化与加速 |
| 风车 | 谷物、向日葵；依靠自然风 | 面粉、动物饲料、葵花油 | 食品工坊、鸡舍、路灯或市场 |
| 鸡舍 | 动物饲料 ×1/日 | 鸡蛋 ×2/日；每 3 个有效生产日羽毛 ×1 | 食品、纺织和居民需求 |

| 工作台 | 木材、纤维、金属、蜂蜡等 | 木板、绳索、木箱、农具、零件、灯具、蜡烛、家具、珠宝 | 建造、运营消耗、照明和市场 |

| 熔炉 | 矿石、沙、煤或木炭 | 金属锭、钢材、玻璃和容器 | 工作台、建造、食品包装和奢侈品 |
| 食品工坊 | 作物、面粉、鸡蛋、蜂蜜、盐、容器 | 面包、蛋糕、果酱、腌菜、酱料、果汁、香水、花束 | 居民需求、合同、节日和高价值市场 |
| 纺织机 | 纤维、羽毛、薰衣草 | 布料、香包、枕具 | 家具、居民需求和奢侈品市场 |
| 伐木场 | 每 5 个有效生产日消耗农具 ×1 | 木材 ×3/日；每两日纤维 ×1 | 工作台、石窑、建造和纺织 |
| 采石场 | 每 4 个有效生产日消耗农具 ×1 | 石材 ×3/日；每三日煤 ×1 | 石窑、熔炉和建造 |
| 矿场 | 木板支撑 ×1/日、蜡烛 ×1/日、维护 | 铜矿、铁矿、煤、银矿；深层产金矿和水晶 | 熔炉、机械零件和珠宝 |
| 路灯 | 每三晚蜡烛 ×1，或每两晚葵花油 ×1 | 半径 4 内夜间自动生产不减速，并提供可见照明 | 持续消耗蜂蜡和向日葵产品 |
| 围栏 | 木材，损坏后维修；形成有效围护 | 降低被围护鸡舍或农业院落的运营损耗 | 鸡舍每 5 日节省 1 份饲料，并提高羽毛产出频率 |

## 5. 地理条件与空间查询

地理条件分为两类，不能混为一个“附近”布尔值：

- **建造硬约束：** 不满足时禁止落地并保持建造预览；例如水车没有贴岸、占地与树木或建筑重叠。
- **生产软约束：** 可以先建造，但不满足时进入可恢复暂停；例如蜂箱暂时没有成熟花、鱼点当天已经枯竭。

所有范围以网格为权威，不读取模型缩放或碰撞体作为业务距离。建筑占地、作物格和水格使用其稳定网格坐标；显示层只消费查询结果。

### 5.1 水车岸边约束

水车落地必须同时满足：

- 2×2 占地全部是可建造陆地，且不与作物、树木、NPC、玩家出生保护区或其他实体占位重叠；
- 占地四周至少有一个与其边缘**正交相邻**的 `WATER` 网格；仅对角接触不算临水；
- 水格必须属于地图生成或关卡配置的天然水体，水井灌溉、已浇水农田和温室水槽不能伪装成水源；
- 建造预览逐格调用与提交相同的权威校验，并显示“需要紧邻天然水域”的具体失败原因。

同一侧有多个水格时，选择离占地中心最近的水格作为 `water_anchor`；距离相同按 `gz`、`gx` 排序。当前版本没有建筑旋转，轮体视觉朝向由该锚点自动决定。水体属于静态地形，因此 `water_anchor` 是可重建派生状态，不写入存档。

### 5.2 蜂箱与花卉距离

蜂箱不要求建造时已经有花，避免季节更替后形成不可恢复的布局限制。建造预览显示半径 4 的蜜源范围；实际产蜜时重新读取权威成熟作物。

- 距离使用蜂箱占地中心到作物格中心的平面欧氏距离，`distance <= 4` 才算覆盖；
- 墙、围栏和建筑不阻断蜜源，地形高差在首版中也不参与判定；
- 只有带 `flower` 标签且处于成熟、未收获状态的作物计数；种子、幼苗和已收获空地不计数；
- 作物成熟、收获、铲除、蜂箱建成或拆除时标记局部空间索引为脏，不做逐帧全图扫描。

蜂箱面板和建造预览必须高亮当前可计入的花卉，并显示“成熟花 2/4、种类 1/2”之类的权威快照。高亮不是判定来源。

### 5.3 鱼点与可钓水域

不能对任意地面或任意水格使用鱼竿。关卡在天然水体岸边配置 `FishingSpot`，每个鱼点包含稳定 `spot_id`、玩家站位格、投竿目标水格、`water_body_id` 和 `fish_table_id`。

鱼点有效必须满足：

- 玩家站位是可通行陆地，且距离鱼点交互锚点不超过 1.5 格；
- 投竿目标是与站位岸边相邻的天然 `WATER` 网格，并属于鱼点声明的水体；
- 玩家到目标水格的投竿线不穿过建筑、树木或围栏占位；
- 玩家持有可用鱼竿，背包能为潜在产物预留一个物品单位；
- 鱼点没有处于日容量耗尽或任务锁定状态。

首版只使用关卡手工布置的 3–5 个溪谷鱼点，不根据全部水岸自动生成鱼点。这样可以稳定控制站位、镜头、产出表和任务触发，也能阻止玩家从装饰水面、狭窄水沟或水车占位中穿模钓鱼。

## 6. 水车动力

### 6.1 建立动力覆盖

建筑获得 `powered` 状态必须同时满足：

- 水车已完成建造；
- 水车邻接有效水域；
- 水车没有维护停机；
- 建筑位于水车半径 4 内。

动力不作为物品，不进入背包或市场。多座水车的加成不叠加；重叠覆盖只提供容错。

### 6.2 动力效果

| 建筑 | 动力效果 |
|---|---|
| 温室 | 自动浇水；作物采用浇水后的约 20 秒成长周期 |
| 农田 | 每个成长周期自动获得浇水状态 |
| 食品工坊 | 生产时间缩短 25%，允许自动连续生产 |
| 纺织机 | 生产时间缩短 25%，允许自动连续生产 |
| 工作台 | 生产时间缩短 20% |
| 熔炉 | 鼓风机构使生产时间缩短 20% |
| 伐木场 | 每三日额外木材 ×1 |
| 采石场 | 每三日额外石材 ×1 |
| 风车 | 无额外效果；风车拥有自己的自然动力 |
| 石窑 | 无额外效果；石窑由燃料和烧制周期约束 |
| 蜂箱、鸡舍 | 无直接加速 |

水车失去水源或维护到期时，只移除自动灌溉、动力加速和依赖动力的自动续单。已经开始的生产保留剩余时间，不销毁原料。

## 7. 谷仓自动物流

### 7.1 手动阶段

- 玩家从背包向建筑投料；
- 玩家选择配方和批量；
- 成品进入建筑输出仓；
- 玩家在建筑或谷仓手动收取。

### 7.2 自动阶段

建筑可设置一个持久化 `auto_recipe_id`，但必须满足：

- 建筑与谷仓距离不超过 6 格；
- 配方和建筑蓝图已解锁；
- 谷仓持有完整一批原料；
- 对需要机械自动化的建筑，动力有效；
- 建筑输出缓冲和谷仓存在容量；
- 建筑没有维护停机。

需要水车动力才能启用自动配方的建筑为工作台、熔炉、食品工坊和纺织机。风车以自然风作为自身动力，石窑以燃料作为运行条件，两者连接谷仓后不额外要求水车。蜂箱、鸡舍和资源建筑没有自动配方；它们连接谷仓后只自动回仓被动产物。

自动事务顺序：

```text
谷仓原料
  ↓ 原子预留并扣除一批
加工建筑生产
  ↓
建筑输出缓冲
  ↓ 原子写入
谷仓库存
```

自动链一次最多预留一批原料。缺料、断电、维护或仓满时进入明确的暂停状态；恢复条件后继续，不丢失物品，不重复产出。

建筑同时连接多个谷仓时，选择世界距离最近的有效谷仓；距离相同则按稳定建筑键排序。当前谷仓失效后才重新选择，避免每次刷新在多个仓库之间抖动。

## 8. 蜂箱与成熟花卉

有效蜜源为所有带 `flower` 标签的成熟作物，首批包括向日葵、玫瑰和薰衣草。

- 只统计成熟、未收获且位于半径 4 内的花；
- 花卉不被蜂箱消耗；
- 玩家收获花卉后，它立即停止提供蜜源；
- 同一株花最多计入两个蜂箱，避免密集蜂箱无限复用同一蜜源；
- 没有成熟花时蜂箱停止生产，而不是免费产一份蜂蜜。

| 成熟花数量 | 花卉种类 | 每两日产出 |
|---:|---:|---|
| 0 | 0 | 停止生产 |
| 1 | 1 | 蜂蜜 ×1 |
| 2–3 | 任意 | 蜂蜜 ×2 |
| 4+ | 至少 2 种 | 蜂蜜 ×2、蜂蜡 ×1 |

玩家需要在直接收花、加工花卉和保留蜜源之间做机会成本选择。

一株花被多个蜂箱覆盖时，按距离选择最近的两个蜂箱；距离相同按稳定建筑键排序。该归属只影响下一次日结计算，不持久化。

## 9. 钓鱼系统

钓鱼是天然水域资源的采集闭环，不属于建筑生产，也不复用“鱼竿使用后立即发奖励”的普通工具路径。当前 `_use_fishing_rod()` 随机给予纤维只是占位实现，必须由 `FishingSystem` 的会话和事务替换。

### 9.1 输入与交互状态

玩家选择鱼竿后，只有鼠标指向有效 `FishingSpot` 才显示可交互高亮。第一次点击开始投竿，进入以下状态机：

```text
IDLE
  ↓ 点击有效鱼点并通过预检
CASTING（投竿表现，约 0.5 秒）
  ↓
WAITING_BITE（现实时间 2–6 秒）
  ↓ 随机咬钩
BITE_WINDOW（现实时间 1.0 秒）
  ├─ 玩家再次点击 / 按交互键 → RESOLVING → 获得产物 → COOLDOWN
  └─ 超时、移动、切换工具或打开阻塞 UI → CANCELLED / FAILED → IDLE
```

等待咬钩和咬钩窗口使用游戏前台运行的现实秒，不随游戏内小时倍速变化；暂停菜单冻结计时。钓鱼会话期间屏蔽移动和其他工具动作，退出会话后统一恢复输入上下文，避免点击收杆被解释成移动。

开始投竿前依次校验鱼点、距离、鱼竿耐久和背包容量，并为一个潜在产物预留容量。投竿表现结束并进入 `WAITING_BITE` 时消耗一次鱼竿耐久；无效点击、预检失败或进入等待前的系统中断不消耗耐久。进入等待后的失败和主动取消不返还耐久。成功、失败或取消都必须释放容量预留。

### 9.2 产出表与确定性

首版溪谷水体使用以下基础鱼类；具体权重保存在数据资源，不写死在 UI：

| 产物 | 季节 | 有效时段 | 稀有度与用途 |
|---|---|---|---|
| 溪鲫 | 全年 | 06:00–22:00 | 常见；烹饪、普通订单、市场 |
| 河鲈 | 春、夏 | 06:00–10:00，16:00–20:00 | 普通；烹饪和渔夫订单 |
| 鲤鱼 | 夏、秋 | 10:00–20:00 | 普通；烹饪和市场 |
| 虹鳟 | 秋、冬 | 06:00–10:00 | 稀有；高价订单和图鉴 |
| 夜鲶 | 夏、秋 | 20:00–24:00 | 稀有；高价订单和图鉴 |
| 漂流瓶 | 全年 | 任意 | 极稀有收集品；每个故事编号只能获得一次 |

选择产物的顺序为 `water_body_id → fish_table_id → 当前季节 → 投竿时游戏小时 → 加权随机`。如果筛选后没有鱼种，鱼点不可投竿并显示“当前时段没有鱼群”，不能退回到全季节默认奖励。

随机种子由世界种子、`spot_id`、总游戏日和该鱼点当日 `cast_sequence` 组成。`cast_sequence` 在合法投竿开始时立即递增，因此失败、取消或重新读档不能重复同一次随机结果。奖励数量首版固定为 1，鱼竿升级只影响耐久或咬钩窗口，不直接增加鱼的数量。

### 9.3 鱼点容量与恢复

- 每个鱼点每天最多成功捕获 3 次；失败和主动取消不消耗鱼群容量，但已经消耗的鱼竿耐久不返还；
- 达到容量后鱼点进入 `depleted`，次日 06:00 恢复；
- 多个鱼点分别计数，同一水体不共享全局容量；
- 任务指定鱼点可以使用独立产出表，但仍遵守位置、交互和库存事务；
- 水车不会消耗鱼群，也不会提高钓鱼概率，避免基础设施成为强制钓鱼增益。

### 9.4 鱼类经济闭环

鱼类作为正式 `fish` 类物品进入背包、图鉴、市场和订单系统。首批下游为：

```text
普通鱼 ─┬→ 直接出售 / 渔夫阿水订单
        ├→ 食品工坊：烤鱼 → 居民日常与市场
        └→ 食品工坊：腌鱼 → 长期订单与高流动市场

稀有鱼 → 图鉴首次登记 / 渔夫高价合同 / 直接出售
漂流瓶 → 故事收集与探索任务，不进入普通市场
```

新增配方：任意普通鱼 ×2、盐 ×1生产烤鱼 ×2；任意普通鱼 ×2、盐 ×1、玻璃罐 ×1生产腌鱼 ×1。配方输入使用 `common_fish` 标签，由配方系统在事务开始时确定并锁定具体鱼堆，不能在生产中途替换或重复扣除。

## 10. 鸡舍与围栏

- 鸡舍每日结算前检查输出容量和饲料；仓满时不消耗饲料。
- 成功消耗动物饲料 ×1 后产鸡蛋 ×2。
- 每 3 个成功生产日额外产羽毛 ×1。
- 有效围护状态下，每累计 5 个成功生产日免除一次饲料，并把羽毛周期缩短为 2 日。
- 围护检测以鸡舍生产院落为内部区域，在院落外扩 6 格的有限边界内执行洪水填充；围栏格不可穿过。若内部可通行格无法到达边界外侧，则判定为完整围护。断裂后保留累计进度，但停止围护加成。

## 11. 水井与路灯

### 11.1 水井

- 水井在每日作物成长结算前，自动为半径 3 内最多 6 个已种植且尚未浇水的格子供水。
- 选择顺序为距离、`gz`、`gx`，确保日结和存档重放结果一致。
- 水井可以给温室种植格供水，但不会提供季节保护或机械动力。
- 多口水井不能重复浇灌同一格；水车覆盖优先，水井只补足未被水车覆盖的格子。

### 11.2 路灯

- 夜间定义为 20:00–06:00。无人操作的自动加工任务在未照明时以 75% 速度推进，照明范围内恢复到 100%。玩家手动操作和被动日结不受夜间减速影响。
- 路灯半径为 4。燃料由玩家在建筑面板指定为蜡烛或葵花油；没有燃料时熄灭。
- 仅当照明范围内至少有一座自动加工建筑在夜间运行时累计燃料消耗，避免空置路灯无意义烧料。
- 蜡烛每累计 3 个工作夜消耗 1 个，葵花油每累计 2 个工作夜消耗 1 个。切换燃料不丢失各自独立累计进度。

## 12. 资源建筑运营消耗

资源建筑遵守“先检查容量，再检查运营材料，再结算产出”的顺序。仓满、维护停机或缺少运营材料时，不扣除任何输入。

- 伐木场每 5 个成功生产日消耗农具 ×1。
- 采石场每 4 个成功生产日消耗农具 ×1。
- 矿场每天消耗木板 ×1 和蜡烛 ×1；浅层、中层、深层采用不同产出表。
- 运营计数器与产出、维护、深度和暂停状态一起保存。

## 13. 配方调整

新增或调整以下配方，以消除银矿、金矿、羽毛、柠檬等断链：

| 配方 | 建筑 | 输入 | 输出 |
|---|---|---|---|
| 银锭 | 熔炉 | 银矿 ×2、煤 ×1 | 银锭 ×1 |
| 金锭 | 熔炉 | 金矿 ×2、煤 ×1 | 金锭 ×1 |
| 珠宝 | 工作台 | 金锭 ×1、银锭 ×1、水晶 ×1 | 珠宝 ×1 |
| 枕具 | 纺织机 | 布料 ×2、羽毛 ×3 | 枕具 ×1 |
| 蜡烛 | 工作台 | 蜂蜡 ×2、纤维 ×1 | 蜡烛 ×1 |
| 花香蜂蜜 | 食品工坊 | 蜂蜜 ×2、薰衣草 ×1、玻璃罐 ×1 | 花香蜂蜜 ×1 |
| 柠檬汁 | 食品工坊 | 柠檬 ×3、蜂蜜 ×1、玻璃瓶 ×1 | 柠檬汁 ×1 |
| 烤鱼 | 食品工坊 | `common_fish` ×2、盐 ×1 | 烤鱼 ×2 |

现有珠宝配方不再直接使用金矿，确保矿石必须经过熔炉加工。新增商品必须进入物品目录、市场目录、订单候选和存档验证。

## 14. 生产节奏

- 基础材料：30–45 秒一批；
- 食品与普通农产品加工：45–75 秒一批；
- 工具、机械零件和奢侈品：75–120 秒一批；
- 蜂箱、鸡舍、伐木场、采石场和矿场：按游戏日结算；
- 同一加工建筑默认一个运行任务和一个等待任务；
- 动力加速后不得低于 20 秒一批；
- 调试面板可以推进游戏时间，但不得绕过输入、容量、动力和维护校验。
- 钓鱼等待与咬钩窗口使用现实时间，不被游戏时间推进或 Agent 调度重复结算。

## 15. 市场、订单与内部消耗

| 需求类型 | 主要消耗 |
|---|---|
| 居民日常 | 面包、鸡蛋、油、果汁、烤鱼、蜡烛、布料 |
| 建设订单 | 木板、石砖、砖块、玻璃、钢材、机械零件 |
| 农业合同 | 种子、饲料、农具、木箱 |
| 节日订单 | 花束、香水、蜂蜜蛋糕、香包、珠宝 |
| NPC 工坊 | 矿石、金属锭、木材、纤维、容器 |
| 渔夫与探索订单 | 普通鱼、季节稀有鱼、鱼类图鉴、漂流瓶 |
| 建筑运营与维护 | 木材、石材、农具、蜡烛、机械零件、金币 |

自动生产不会自动出售。玩家仍需选择市场销售、订单交付、继续加工、建造或维护。市场库存、流动量和价格冲击继续限制批量倾销。

## 16. 状态、交互与消息

点击建筑后必须显示：

- 当前输入、输出和容量；
- 当前任务与下一次完成时间；
- 动力来源和覆盖状态；
- 物流谷仓和自动配方；
- 维护、围护、蜜源、水源与运行状态；
- 当前停机原因；
- 相关覆盖范围和受益建筑。

统一停机原因：

- 缺少原料；
- 缺少饲料；
- 缺少成熟花卉；
- 没有水源；
- 未获得动力；
- 未连接谷仓；
- 输出仓已满；
- 谷仓容量不足；
- 维护到期；
- 配方未解锁。

状态变化写入右侧消息流；同类消息在短时间内合并。建筑面板显示权威状态，不以消息文本作为业务数据来源。

钓鱼提示使用鱼点上方的短时文字和图标：可投竿、等待、咬钩、脱钩、鱼点枯竭。鱼名和入库结果进入右侧消息流；无效水域提示“只能在标记的岸边鱼点钓鱼”。这些提示只展示 `FishingSystem` 状态，不能自行发放物品。

## 17. 数据与系统边界

- `GameData.BUILDINGS` 保存静态建筑类别、覆盖半径、运营规则和动力修正。
- `GameData.ITEMS` 保存鱼类、鱼产品和收集品；鱼类使用 `fish` 类别及 `common_fish`、`rare_fish` 标签。
- `RecipeDatabase` 保存加工配方、时间、输入、输出和解锁层级。
- `ProductionSystem` 负责生产任务、日结、容量、运营输入和输出事务。
- 新的 `GeographicQueryService` 负责天然水域、岸边、蜜源、谷仓、动力、照明和围栏的只读空间快照，不直接修改库存。
- 新的 `FishingSystem` 独占鱼点校验、钓鱼状态机、随机结果、每日容量和奖励事务；`ToolSystem` 只把鱼竿输入路由给它。
- `FishingSpotData` 保存稳定鱼点、水体、站位、投竿目标和产出表；场景节点只负责锚点与表现。
- `FarmingSystem` 只消费温室、浇水和花卉相关的权威覆盖结果。
- `MarketSystem` 和订单系统消费商品变化，不直接推动建筑生产。
- 建筑 UI 读取只读快照，通过现有命令接口提交投料、收取、自动配方和优先级变更。

地理查询组件应与 `ProductionSystem` 分离，避免继续扩大当前生产系统的职责。空间快照按建筑布局、作物状态、维护、水源或围栏变化重新计算，不在每帧全图扫描。钓鱼状态机只在存在活动会话时推进，空闲时不得轮询所有鱼点。

## 18. 存档与迁移

新增持久化状态包括：

- 自动配方；
- 运营日计数器；
- 资源建筑深度；
- 灯具燃料与围栏加成累计；
- 暂停原因所需的权威输入状态；
- 正在运行和等待的任务。
- 每个鱼点当天的成功捕获数、`cast_sequence`、最后重置总日和一次性漂流瓶编号。

水车、谷仓、照明、围栏和蜜源连接属于可重建派生状态，不直接写入存档。加载建筑、网格、作物、维护和生产状态后统一重算连接。

活动钓鱼会话不跨存档保存。存档前取消会话并释放背包容量预留；因为耐久只在进入等待状态时提交，已经正式投出的鱼竿耐久不返还。鱼点计数和 `cast_sequence` 必须先于存档快照更新，避免重新加载复用同一随机结果。加载后根据总游戏日判断是否重置鱼点日容量。

旧存档迁移时：

- 自动配方为空；
- 运营计数器从零开始；
- 已有建筑和输出原样保留；
- 不补扣历史运营材料；
- 不追溯生成历史产物。
- 旧存档的鱼点计数和投竿序号从零开始，已获得的漂流瓶根据现有收集品状态回填，不能重复生成。

## 19. 原子性与错误处理

- 日结先预检输出容量，再预检输入，最后一次性扣料和写入产物。
- 自动生产一次只预留一批原料。
- 写入谷仓失败时，产物保留在建筑输出缓冲。
- 任务已经开始后失去动力，只移除加速或暂停续单，不回滚已消耗原料。
- 维护到期、缺料、仓满和断水都是可恢复暂停，不删除任务。
- 同一天重复日结必须幂等。
- 保存失败或加载拒绝不得留下部分扣料、部分产物或错误网络状态。
- 水车预览与最终落地使用同一岸边校验；失败时不扣材料、不留下占位或模型。
- 钓鱼成功结算按“确认会话与鱼点容量 → 确认背包预留 → 写入鱼类 → 增加成功计数 → 释放预留”执行；任一步失败都不得生成部分奖励或多扣容量。
- 同一钓鱼会话只能结算一次；迟到的计时器、重复点击和 UI 回调通过稳定 `session_id` 拒绝。

## 20. 防止经济失控

- 蜂箱必须有成熟花才产出；
- 资源建筑必须消耗工具、支撑材料或照明；
- 动力只降低时间或劳动，不永久提高售价；
- 动力效果不叠加；
- 自动链一次只预留一批；
- 建筑输出和谷仓都有容量；
- 高利润商品依赖多级加工且市场流动量较低；
- 维护停机发生在生产前，不吞掉输入；
- 同一成熟花最多服务两个蜂箱。
- 每个鱼点每日最多成功捕获 3 次，奖励固定为 1；失败不能刷出产物。
- 鱼类季节和时段筛选无候选时禁止投竿，不用默认鱼或纤维兜底。
- 水车、路灯、蜂箱和钓鱼加成都不能叠加成额外鱼类数量。

## 21. 验收标准

### 21.1 建筑闭环

- 17 座建筑均能说明其投入、效果或产物，以及至少一个下游用途。
- 每种建筑产物都能进入加工、建造、运营、维护、订单或市场中的至少一项。
- 每种关键运营材料都存在玩家采集、建筑生产或市场购买路径。

### 21.2 地理、动力和物流

- 水车只有占地边正交邻接天然水格时可建造；对角接触、已浇水农田、水井和装饰水面均不通过。
- 水车预览和落地诊断一致，失败不扣材料且不会留下碰撞占位。
- 水车覆盖与实际灌溉、加速状态一致，断水和维护会即时撤销效果。
- 谷仓自动取料与回仓使用原子事务，失败不复制也不丢失物品。
- 重叠水车不叠加速度。

### 21.3 农业和被动生产

- 温室专供作物只能在有效温室格播种。
- 蜂箱无花不产出；成熟花数量和种类决定稳定产出。
- 鸡舍仓满不耗饲料；围护奖励按成功生产日计算。
- 收获花卉后，蜂箱下一次权威查询立即失去该蜜源。
- 半径边界上的成熟花按统一距离口径计入，边界外一格不计入；同一花最多归属两个蜂箱。

### 21.4 钓鱼

- 非鱼点、距离过远、投竿线受阻、非天然水域、背包满或鱼竿损坏时不能开始会话。
- 投竿期间玩家移动被锁定，成功、失败、取消和关闭 UI 后都能正确恢复输入。
- 季节与时段只会选出合法鱼种；没有候选时不发放任何占位物品。
- 同一会话重复回调只结算一次；满背包、取消或保存不会复制、丢失或覆盖物品。
- 每个鱼点第 3 次成功后进入枯竭，次日 06:00 恢复，重新加载不能回退计数或随机序列。
- 普通鱼能进入烤鱼、腌鱼、市场和订单；稀有鱼能进入图鉴、合同或市场；漂流瓶不可重复获取。

### 21.5 资源、配方和市场

- 资源建筑缺运营输入时停止，补充后可恢复。
- 银矿、金矿、羽毛、蜂蜡和柠檬均具有可达下游配方。
- 自动化不能绕过配方解锁、容量、维护和市场交易规则。

### 21.6 存档

- 运行中任务、输出、自动配方和运营计数器可往返保存。
- 派生网络在加载后重建，结果与加载前一致。
- 旧存档迁移不会补扣材料或凭空补产物。
- 鱼点容量、投竿序号和漂流瓶收集状态可往返保存，活动会话按规则安全取消。

## 22. 实施拆分

该设计覆盖多个可独立验收的子系统，应分五阶段实施：

1. 地理与农业闭环：统一空间查询，完成温室、蜂箱、鸡舍、水井、水车和围栏。
2. 钓鱼闭环：鱼点、会话状态机、鱼类数据、库存事务、图鉴、食品配方和订单。
3. 工业闭环：伐木场、采石场、矿场、工作台、石窑、熔炉及断链配方。
4. 自动化网络：谷仓物流、水车动力、自动配方和路灯夜间效果。
5. 市场与平衡：订单需求、运营消耗、生产时间、利润校准和完整状态 UI。

每一阶段都必须独立可玩、可保存并通过真实系统测试，不能用消息文本或模拟库存代替权威世界状态。
