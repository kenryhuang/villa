# 主游戏鼠标翻地与农田视觉设计

日期：2026-07-29  
状态：设计已确认，等待实施

## 1. 背景与问题

主游戏已经集成 `GridSystem`、`ToolSystem` 和 `PlayerActionController`，底部快捷栏也能选择锄头，但实际运行存在两个断点：

- `PlayerActionController._process()` 使用 viewport 当前鼠标坐标更新地块高亮。在 macOS Retina 和项目 3000×2000 逻辑画布缩放组合下，该坐标可能与输入事件携带的逻辑坐标不一致，鼠标所在格不会显示阴影。
- `GridSystem` 在锄地后只把单元状态从 `WASTELAND` 改为 `FARMLAND`，没有生成持久农田视觉。即使逻辑状态已经改变，玩家也看不到翻好的土地。

本次目标是打通完整视觉反馈：

```text
选择 1 锄头
  → 鼠标移动到地面
  → 当前单格显示有效/无效阴影
  → 左键点击有效格
  → 状态变为 FARMLAND
  → 显示独立的手绘翻土块
```

## 2. 范围

### 2.1 本次包含

- 使用最近一次鼠标输入事件的逻辑坐标驱动悬停和点击射线。
- 锄头模式下显示单格半透明阴影。
- 有效耕地候选显示绿色，无效候选显示红色。
- 每个 `FARMLAND` 或 `PLANTED` 单元显示独立翻土视觉。
- 翻土视觉贴合当前地形四个角的高度。
- 翻土视觉与现有手绘树木、谷物和建筑风格匹配。
- 播种后保留翻土底座，收获后继续保留。
- 存档加载和系统状态恢复后重建翻土视觉。
- 自动化覆盖真实鼠标坐标、阴影、状态转换和视觉生命周期。

### 2.2 本次不包含

- 相邻农田自动合并为连续大田。
- 农田边缘智能拼接或自动生成围栏。
- 多种土壤类型、肥力、湿度贴图或季节换色。
- 修改作物成长速度、收获数量或工具体力数值。
- 新增拖拽连续翻地。

## 3. 交互设计

### 3.1 鼠标坐标来源

`PlayerActionController` 保存最近一次 `InputEventMouseMotion` 或 `InputEventMouseButton` 的 `position`。同一坐标同时用于：

- `_process()` 中的悬停射线。
- 左键点击时的动作射线。
- 建造预览的位置更新。

只有在尚未收到鼠标事件时，才回退到 `Viewport.get_mouse_position()`。这保证 macOS Retina、窗口缩放和 3000×2000 逻辑画布下使用同一坐标空间。

### 3.2 锄头悬停

当前选择槽位 `1` 时：

- 鼠标指向角色水平距离 `2.5m` 内的 `WASTELAND`，显示绿色单格阴影。
- 鼠标指向道路、建筑、水面、装饰、已耕地、坡度过大或范围外单元，显示红色单格阴影。
- 鼠标移出地形、悬停在 UI 上或当前界面阻止世界交互时，隐藏阴影。
- 阴影只覆盖当前目标格，不显示完整地图网格。

阴影材质沿用无光照半透明风格，并启用无深度遮挡，使其在草地和道路纹理上保持清晰。

### 3.3 点击翻地

左键点击使用与悬停相同的目标坐标和有效性规则。成功时：

1. `ToolSystem` 验证锄头、目标状态和体力。
2. `GridSystem` 将目标从 `WASTELAND` 转为 `FARMLAND`。
3. `GridSystem` 创建或更新该格的翻土视觉。
4. 成功后扣除体力并发出已有事件。
5. 悬停阴影继续显示在该格，但变为红色，表达不能重复锄地。

失败时不改变地块、不扣体力，也不创建翻土视觉。

## 4. 农田视觉

### 4.1 视觉方案

采用已经确认的方案 A：每个农田格独立生成一个贴合地形的手绘翻土块。

每个翻土块包含：

- 一张与现有资产色彩和笔触一致的手绘土壤贴图。
- 棕色泥土主体，避免过饱和或写实照片质感。
- 三至四条方向统一的深色沟垄。
- 轻微明暗和土块变化，避免纯色方块感。
- 清楚但不过硬的单格边界，保证玩家能识别操作范围。

贴图作为独立 PNG 资源保存，使用透明或柔化边缘；不使用来自外部游戏的素材。

### 4.2 地形贴合网格

`GridSystem` 根据单元四角坐标生成两个三角形。四个顶点分别读取 `TerrainBuilder.get_height_at()`，并在地形上方增加很小的高度偏移，避免闪烁。

翻土节点统一放在 `GridCells/FarmlandVisuals` 容器下，按网格键命名：

```text
FarmlandVisual_16_14
```

节点记录 `gx`、`gz` 元数据，便于测试、存档恢复和精确删除。视觉只负责表现，不保存权威游戏状态。

### 4.3 生命周期

`GridSystem` 每次状态变化后同步对应单元视觉：

| 单元状态 | 翻土视觉 |
|---|---|
| `WASTELAND` | 不显示 |
| `FARMLAND` | 显示 |
| `PLANTED` | 显示，作物模型位于其上 |
| `BUILDING` | 不显示 |
| `ROAD` / `WATER` / `DECORATION` | 不显示 |

以下入口都必须执行同一套视觉同步：

- `set_cell_state()`
- `plant_crop()`
- `harvest_crop()`
- `from_dict()`
- 建筑拆除或取消后恢复原地块状态

加载存档后执行一次全量重建，确保视觉与逻辑状态一致。

## 5. 组件职责

### `PlayerActionController`

- 保存输入事件的逻辑坐标。
- 用统一坐标更新悬停和执行左键动作。
- 根据当前工具和目标状态选择阴影颜色。
- 不直接创建农田模型。

### `GridSystem`

- 维护权威单元状态。
- 创建、更新和删除翻土视觉。
- 提供按单元查询翻土视觉的接口，供测试和后续系统使用。
- 在加载与状态恢复后重建视觉。

### `ToolSystem`

- 保持“动作成功后才扣体力”的事务规则。
- 通过 `GridSystem.set_cell_state()` 完成翻地，不绕过视觉同步入口。

### 美术资源

- 新增一张手绘翻土 PNG。
- 导入设置使用透明边缘、线性色彩和适合 2.5D 视角的过滤方式。
- 色相、明度、边缘柔度与现有地形、树木和谷物资产进行视觉对照。

## 6. 验证设计

### 6.1 输入回归

真实实例化 `main.tscn`，选取角色范围内可耕格，将该格投影到屏幕坐标，并发送鼠标移动与左键事件：

- 鼠标移动后，`CellHighlight` 可见。
- 阴影元数据指向预期 `gx/gz`。
- 点击后目标状态为 `FARMLAND`。
- 点击使用事件坐标，不依赖 viewport 中可能陈旧的鼠标位置。

### 6.2 农田视觉回归

- `WASTELAND → FARMLAND` 后生成且仅生成一个翻土节点。
- 重复同步不会重复创建节点。
- `FARMLAND → PLANTED` 后翻土节点仍存在。
- 收获回到 `FARMLAND` 后翻土节点仍存在。
- 变为 `BUILDING` 或 `WASTELAND` 后翻土节点移除。
- 存档数据恢复后，所有 `FARMLAND` 和 `PLANTED` 单元重新生成视觉。

### 6.3 视觉验收

生成主场景截图，至少展示：

- 鼠标悬停的绿色单格阴影。
- 一个刚翻好的空农田格。
- 一个带谷物幼苗的农田格。
- 草地、树木或建筑作为风格参照。

验收标准：

- 翻土块在 2.5D 摄像机角度下清晰可读。
- 不悬空、不穿入地形、不明显闪烁。
- 颜色和笔触与现有场景协调。
- 独立格边界清楚，但不呈现现代 UI 方框感。

## 7. 完成标准

- 选择槽位 `1` 后，角色附近鼠标格显示有效或无效阴影。
- 左键点击有效格能立即看到翻好的土地。
- 选择槽位 `6` 后能在该格播种，翻土底座保留。
- 成熟作物点击收获后，地块仍保持翻好状态。
- 窗口缩放和 macOS Retina 环境不再使悬停与点击落到不同格。
- 网格、种植、建造、主玩法和全量测试均无新增失败。
