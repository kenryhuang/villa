# Kodu Godot 迁移设计

## 目标

将 `/Users/huanggui/workspace/kodu` 中的 Babylon.js 2.5D 网页原型迁移到 `/Users/huanggui/UnrealEngine/villa` 的 Godot 4.7 工程，形成面向 macOS 桌面的可玩原型。首版包含地形、道路、树木、玩家、NPC、跳跃、鼠标瞄准投射物、碰撞、HUD，以及可旋转和缩放的正交跟随镜头。

本阶段不加入建造、资源生产、存档、正式角色动画或音效。迁移完成后的下一阶段将在这套原生 Godot 架构上开发建造经营系统。

## 技术约束

- Godot 版本：4.7。
- 目标平台：macOS 桌面。
- 渲染器：GL Compatibility，沿用现有项目设置。
- 3D 物理：Jolt Physics，沿用现有项目设置。
- 脚本语言：GDScript。
- 原网页项目保持不变；只复制需要复用的 PNG 素材。
- 不引入第三方 Godot 插件。
- 世界、角色、镜头和 UI 使用独立场景或职责单一的脚本，避免复制原项目的千行集中式世界脚本。

## 总体架构

主场景采用以下结构：

```text
Main
├── World
│   ├── Terrain
│   ├── Road
│   ├── Vegetation
│   └── Obstacles
├── Actors
│   ├── Player
│   └── NPCs
├── Projectiles
├── CameraRig
└── HUD
```

### Main

`Main` 负责创建和连接主要场景、维护全局游戏状态，以及把玩家/NPC/投射物状态同步给 HUD。它不实现地形网格、角色移动或伤害算法。

### World

`World` 负责从高度图创建地形、根据控制点创建道路、按照确定性规则布置 atlas 树木，并提供地形高度查询、地图边界和障碍物信息。

地形与道路生成逻辑拆分为纯计算函数和 Godot Mesh 构造两部分，使道路采样、树木净距和高度查询能够在无窗口测试中验证。

### Player

玩家根节点使用 `CharacterBody3D`。玩家脚本负责：

- 按当前镜头水平朝向转换 `WASD`/方向键输入。
- 地面移动、重力、跳跃和地图边界限制。
- 朝向瞄准位置。
- 维护 5 点生命值和射击冷却。
- 发出 `fire_requested(origin, direction)` 与 `health_changed(value)` 信号。

首版玩家外观使用蓝色胶囊体。

### NPC

NPC 使用独立的 `CharacterBody3D` 场景。NPC 脚本负责追踪玩家、生命值、受击闪烁、击退速度衰减和死亡。死亡时发出 `defeated` 信号，由主场景更新计数并释放实例。

首版生成 3 个红色胶囊体 NPC。

### Projectile

投射物使用 `Area3D`，包含可见 Mesh、`CollisionShape3D` 和存活计时。它沿发射方向移动，在命中 NPC 或障碍后造成伤害并释放；超过存活时间也会自动释放。

### CameraRig

镜头使用 `Camera3D` 的正交投影，并始终围绕玩家跟随。镜头支持：

- 中键水平拖动旋转。
- `Q/E` 键盘旋转。
- 滚轮缩放。
- 平滑跟随玩家。
- 对正交尺寸、俯仰角和缩放范围进行限制。

首版不提供解除跟随或自由平移。

### HUD

HUD 使用 Godot `Control` 节点，显示玩家生命值、状态、NPC 数量、活动投射物数量和操作提示。HUD 通过信号或主场景状态更新，不直接查询角色内部节点。

## 场景表现

### 地形

复用 `public/assets/terrain/heightmap-valley.png`，从同一份高度采样生成约 `36 × 28` 世界单位、96 级细分的 `ArrayMesh` 地形，以及对应的 `HeightMapShape3D` 碰撞。高度范围保持接近网页 Demo 的 `-0.12` 到 `0.9`。

草地优先复用 `grass-seamless-blended.png`。若纹理缺失，使用纯绿色 `StandardMaterial3D` 回退并打印明确错误。

### 道路

复用网页 Demo 的 9 个主道路控制点。道路使用 Catmull-Rom 曲线采样，沿地形法线生成带宽度和中间隆起的 Ribbon Mesh。材质使用现有无缝道路纹理；纹理缺失时回退为土色材质。

道路输入少于两个控制点时停止生成道路并输出错误，但其他场景继续启动。

### 植被

复用 `public/assets/vegetation/atlas/` 中的 10 种树木 PNG。树木使用启用 Billboard 的 `Sprite3D`，确保镜头旋转后仍朝向相机；纹理边缘使用透明裁剪。散布保持固定随机种子、28 棵目标数量、道路净距、中心出生区净距和树木间最小间距。

若在最大尝试次数内无法放满 28 棵树，记录警告并保留已经成功生成的树木。

### 光照

使用环境光与一盏定向光恢复网页 Demo 的明亮微缩景观感。地形接收阴影，玩家、NPC 和树木根据实际视觉效果选择投射阴影。首版不制作昼夜循环。

## 输入与操作

| 行为 | 输入 |
| --- | --- |
| 玩家移动 | `WASD` 或方向键 |
| 跳跃 | `Space` |
| 瞄准 | 鼠标位置投影到地形/水平面 |
| 开火 | 鼠标左键 |
| 镜头拖动旋转 | 鼠标中键拖动 |
| 镜头键盘旋转 | `Q/E` |
| 镜头缩放 | 鼠标滚轮 |

玩家移动方向按照当前镜头的水平前向和右向计算。镜头始终跟随玩家。

## 物理层

使用明确的物理层和掩码区分：

1. 世界地形与静态障碍。
2. 玩家。
3. NPC。
4. 玩家投射物。

地形提供可行走碰撞；玩家和 NPC 使用胶囊碰撞体。投射物只检测 NPC 与世界障碍，避免命中发射者。

## 数据流

1. `CameraRig` 提供当前水平前向和右向。
2. `Player` 读取 Input Map，将输入转换为相对镜头的移动，并在冷却允许时发出开火请求。
3. `Main` 接收开火请求，在 `Projectiles` 容器中实例化投射物。
4. `Projectile` 命中 NPC 后调用伤害接口并释放。
5. `NPC` 更新生命值、击退和反馈，死亡时发出信号。
6. `Main` 汇总玩家、NPC 和投射物状态，并更新 HUD。

## 错误处理与清理

- 缺少纹理时打印资源路径和回退行为，场景仍可启动。
- 高度图无法读取时终止 World 初始化，并让 Main 显示可理解的错误信息。
- 道路或树木部分生成失败不阻止玩家、NPC 和 HUD 初始化。
- 运行时生成的 Mesh、材质、投射物和信号连接随节点退出树自动释放。
- 关闭主场景后不得残留运行进程或重复输入连接。

## 测试与验收

### 自动化测试

不引入第三方测试插件。纯逻辑测试由 `tests/run_tests.gd` 统一执行，测试文件扩展 `RefCounted` 并返回失败计数；命令使用 `godot --headless --path /Users/huanggui/UnrealEngine/villa --script tests/run_tests.gd`，任一断言失败时以非零退出码结束。

- 树木散布对相同种子产生相同结果。
- 树木不会进入道路净距、出生区净距或其他树木间距。
- Catmull-Rom 道路采样包含起点、终点并产生连续中间点。
- 镜头正交尺寸始终限制在规定范围。
- 伤害不会让生命值低于零，死亡信号只发出一次。
- 投射物超过存活时间后释放。
- `godot --headless --path /Users/huanggui/UnrealEngine/villa --editor --quit` 无解析或导入错误。
- 主场景可在 headless 模式启动并正常退出。

### macOS 人工验收

- 项目打开后可直接运行主场景。
- 地形、道路和 28 棵树正常显示。
- 玩家可相对镜头方向移动并跳跃。
- 中键、`Q/E` 和滚轮能够旋转或缩放镜头，镜头持续跟随玩家。
- 鼠标左键能够向地面瞄准点发射投射物。
- NPC 能追踪玩家、受击、击退并死亡。
- HUD 数量和生命值随运行状态更新。
- 调整窗口大小不会破坏 HUD 或镜头构图。
