# 手动伐木与露天采矿设计

日期：2026-08-04  
状态：已批准  
范围：产业链第 1 阶段

> 2026-08-04 伐木增量已落地，详细资格表与美术约束见 `2026-08-04-single-click-tree-felling-design.md`。发生冲突时，树木采用该增量：仅五种树可砍、一次 3 秒获得全部剩余木材（新树 5），矿石继续采用本文的 1.2 秒/1 单位规则。

## 1. 目标

把当前以市场买卖为主的资源获取方式扩展为可玩的手动采集闭环：

`发现资源 → 点击目标 → 自动靠近 → 自动换工具 → 采集本次产出 → 进入背包 → 建造或出售`

本阶段覆盖手动伐木、手动露天采矿、自动寻路、单次采集、资源容量与刷新、存档、动作与 UI 反馈，以及木材、石材和矿石对现有背包、建造成本和市场的接入。

本阶段不实现矿洞探索、自动连续采集、动作队列、种植系统改造、自动生产建筑、熔炼加工或物流。这些能力分别进入后续独立设计。

## 2. 玩家操作

玩家点击可采集资源后，系统依次执行：

1. 取消当前未提交的移动或采集指令。
2. 在移动前检查目标、背包、体力和工具状态。
3. 自动切换到对应工具：树木使用斧头，矿物使用镐。
4. 寻找资源周围最近的可达交互位置。
5. 沿路径自动移动。
6. 到达后再次检查目标、背包、体力、耐久和距离。
7. 面向资源播放目标动作：矿石 1.2 秒，树木 3 秒。
8. 原子提交本次完整产出、体力、耐久和资源变化。
9. 推进 10 分钟游戏时间，显示结果并停止。

矿石每次点击获得 1 单位；可砍树每次点击获得其全部剩余木材，新树为 5。两类动作完成后都停止，不支持自动连续采集或动作队列。

下列操作立即取消旧指令：

- WASD 手动移动；
- 点击另一个资源；
- 点击地面；
- 切换工具、操作模式或建造模式；
- 按 `Esc`；
- 目标失效、采空或变得不可达。

如果事务尚未提交，取消不得减少资源、扣除体力或耐久、增加物品或追加动作时间。自动切换后的工具保持选中。

## 3. 架构

### 3.1 GatheringController

新增独立采集控制器，状态为：

```text
IDLE
  → PREFLIGHT
  → PATHFINDING
  → MOVING
  → ARRIVAL_RECHECK
  → ACTING
  → COMMITTING
  → COMPLETED
  → IDLE
```

任意进行中状态都可进入 `CANCELLED` 或 `FAILED`，释放目标、路径、时间锁和视觉提示后返回 `IDLE`。

控制器只协调流程，不直接改写背包、资源节点、体力或工具耐久。

### 3.2 GridPathfinder

新增独立寻路服务，使用现有 36×28 `GridSystem` 创建 `AStarGrid2D`。

可通行格：荒地、道路、农田、已种植土地。  
不可通行格：水域、建筑、装饰阻挡、活跃资源节点、地图外区域。

允许八方向移动，但禁止从两个阻挡格之间斜穿。资源节点自身所在格不可通过；路径终点从节点周围满足交互距离的可通行格中选择，以路径代价最低者为准。

`GridSystem` 提供导航修订号。建筑占用、资源激活状态或阻挡变化后增加修订号。移动期间若路径失效或角色 0.5 秒没有取得有效进展，重新寻路一次；第二次仍失败则报告不可达。

A* 只在导航修订变化后重建，不允许每帧重建。

### 3.3 PlayerController

玩家移动脚本新增：

```gdscript
start_auto_path(points: Array[Vector3]) -> bool
stop_auto_movement(reason: String) -> void
has_auto_movement() -> bool
```

并发送：

```gdscript
signal manual_movement_requested
signal auto_path_finished
signal auto_path_blocked
```

自动移动使用普通速度，不自动奔跑；沿路径点平滑转向，在终点减速并面向资源。玩家脚本不知道资源类型，也不修改经济状态。

### 3.4 ToolSystem

工具系统新增：

```gdscript
preview_gather_unit(target: Node) -> Dictionary
commit_gather_unit(target: Node) -> Dictionary
```

返回结果包含：

```text
allowed, reason, tool_id, item_id, quantity,
stamina_cost, durability_cost,
remaining_before, remaining_after
```

原有 `use_tool_on()` 保持兼容，并委托新接口执行采集事务。

### 3.5 GatheringFeedback

新增独立表现层，监听采集控制器信号，负责目标环、路径提示、环形进度、工具提示、产出飘字、剩余量和失败原因。表现层不得决定采集是否成功。

## 4. 寻路规则

点击资源时，寻路器不会把资源位置当作终点，而会枚举其周围候选格：

- 候选点到资源实际碰撞体的平面距离不超过玩家交互范围；
- 候选格可通行；
- 候选格从玩家当前位置可达；
- 路径代价相同时，优先资源正面位置；
- 目标资源自身作为阻挡保留，不能穿过目标到达另一侧。

活动树木、矿脉和装饰树向路径系统注册动态阻挡。资源采空变为树桩或碎石时解除实体阻挡；刷新时重新注册。

建筑放置或拆除、资源刷新、世界加载都会更新导航修订号。进行中的指令在到达前重新核对修订号。

## 5. 原子采集事务

移动前和到达后都必须验证：

- 目标存在、激活且未采空；
- 自动选择的工具正确；
- 工具耐久大于 0；
- 玩家体力足够；
- 背包可完整容纳 1 单位；
- 目标仍在交互范围内；
- 预览产出恰好为对应物品 1 单位。

提交前保存背包、资源节点、玩家体力和工具耐久快照。任何步骤失败都完整回滚且不发送部分事件。

成功提交必须恰好发生一次：

- 节点剩余量减去预检数量；
- 背包对应物品增加同一数量；
- 扣除当前工具的体力消耗；
- 工具耐久 `-1`；
- 发送一次物品、体力、耐久和采集完成事件；
- 推进 10 分钟动作时间。

同步重入或快速重复点击不能使同一动作提交两次。

## 6. 时间

自动行走期间世界时间正常流逝。进入目标动作（矿石 1.2 秒、树木 3 秒）时，控制器通过拥有者式锁暂停自动时钟；动作成功后释放锁并一次性推进 10 分钟，取消或失败只释放锁。

`SeasonSystem` 新增：

```gdscript
acquire_action_clock_lock(owner: Object) -> bool
release_action_clock_lock(owner: Object) -> bool
clear_invalid_action_clock_locks() -> void
```

同一拥有者不可重复加锁。控制器退出树、读取存档、切换场景或发生异常时都必须释放或清理失效锁。10 分钟通过已有 `time_changed` 事件推进生产队列。

## 7. 资源数据

节点运行状态包含：

```text
resource_id
resource_type
item_id
required_tool
max_units
remaining_units
respawn_days
respawn_day
world_position
visual_stage
state_version
```

资源数值：

| 资源 | 容量 | 刷新 | 工具 | 单次产出 |
|---|---:|---:|---|---:|
| 树木 | 5 | 3 天 | 斧头 | 木材 ×1 |
| 石材 | 4 | 3 天 | 镐 | 石材 ×1 |
| 煤、铜、铁 | 3 | 4 天 | 镐 | 对应资源 ×1 |
| 银、金、水晶 | 2 | 7 天 | 镐 | 对应资源 ×1 |

所有矿脉改为所见即所得，不再从通用岩石概率附带矿物。

## 8. 世界分布

资源位置由固定世界种子生成并使用稳定 `resource_id`。

资源林区：10–14 棵可砍树。住宅、道路、农田边缘和装饰区树木不注册为采集目标。  
普通矿区：石材 4、煤 2、铜 2、铁 2。  
偏远稀有矿区：银、金、水晶各 1。

节点位置和状态进入存档，读取后不随机换位。资源区不是主要建造区域，资源节点的动态阻挡不永久改写农田或建筑状态。

## 9. 耗尽与视觉阶段

树木：

- 5–4：完整树形；
- 3–2：增加斧痕和受损表现；
- 1：明显斧痕；
- 0：倒下并替换为树桩；
- 刷新日恢复完整树木。

矿脉：

- 满容量：完整模型；
- 约 2/3：缩小并出现裂纹；
- 约 1/3：进一步缩小；
- 0：替换为碎石底座；
- 刷新日恢复完整模型。

采空时 `respawn_day = 当前总天数 + respawn_days`。刷新只由 `DailySimulationSystem` 推进，同日重复结算不得重复刷新。

## 10. 动画

新增可替换的 `ToolSwingVisual`，使用与建筑一致的手绘 2D 斧头和镐子，工具柄末端作为旋转圆心。

矿石工具动作总长 1.2 秒；树木使用 3 秒目标进度，斧头从树木左侧以 0.72 秒周期向右下方快速挥动，三张砍倒帧之间采用 0.20 秒交叉淡入淡出：

- 预备 0.25 秒；
- 下挥 0.30 秒；
- 命中停顿 0.15 秒；
- 回收 0.50 秒。

命中时树木切换缺口、倾斜、近倒地三帧并产生木屑，矿石震动并产生碎石。树木结束后显示同树种手绘树桩；事务只在完整动作结束时提交，取消时工具平滑返回、恢复原树且不产出。

当前胶囊玩家通过独立工具视觉完成表现。未来角色模型只需监听相同采集状态信号。

## 11. UI

采用平衡反馈方案：

- 点击后显示资源底部目标环和简短虚线路径；
- HUD 自动高亮斧头或镐；
- 角色附近显示“自动装备斧头/镐”；
- 采集中在资源上方显示无刻度环形进度；
- 显示资源名称和剩余量，例如“铁矿石 2/3”；
- 成功后按实际数量显示“+5 木材”“+3 木材”或“+1 铁矿石”；
- 斧头槽悬停树木时，可砍为绿色环、不可砍为红色环；红色点击提示“此树不可砍伐”；
- 采空时显示刷新日；
- 错误提示使用图标加文字，不只依靠颜色。

失败文案包括：背包已满、体力不足、斧头已损坏、镐已损坏、资源已采空、无法到达、目标已失效、此树不可砍伐。

## 12. 存档迁移

资源状态升级为 `state_version: 2`。

旧 `hits_remaining` 按旧容量比例转换为 `remaining_units`：满状态迁移为新满容量，部分状态按比例向上取整，0 保持采空并保留合法刷新日。旧概率奖励表不再进入运行状态。

旧存档缺少的新矿脉使用当前不可变目录默认状态，不得继承加载前另一存档的动态状态。迁移失败时资源、背包、时间和工具状态保持原样。

进行中的路径和动画不保存。保存只记录最后一次成功提交的状态，加载后控制器为空闲状态。

## 13. 经济与建造集成

所有产物先进入现有 `InventorySystem`：

- 木材和石材直接满足建筑成本；
- 矿石可以通过现有市集出售；
- 后续熔炉、工作台和生产建筑消费相同物品 ID；
- 建造诊断实时读取采集后的库存；
- 市场只在玩家主动出售时收到原材料。

本阶段不把产物自动传送到市场、仓库或生产建筑。

## 14. 异常处理

必须正确处理：

- 移动期间目标采空或移除；
- 路径被新建筑阻挡；
- 移动期间背包填满、体力或耐久变化；
- 动画期间切换模式、保存、加载或释放节点；
- 动作跨越日界；
- 快速重复点击同一节点；
- 快速交替点击树木和矿石；
- 同帧手动移动与采集点击。

不得出现部分产出、重复扣费、重复事件或未释放时间锁。

## 15. 测试与验收

### 单元测试

- `GridPathfinder` 绕过水域与建筑、禁止穿角、选择最近交互格、响应导航修订、明确拒绝不可达目标。
- `GatheringController` 覆盖完整状态转换、最新指令覆盖、WASD 取消、到达后二次验证、动画取消和锁释放。
- `ToolSystem` 验证预检数量（矿石 1、树木全部剩余量）、正确自动工具、原子提交、逐阶段失败回滚和同步重入保护。
- `ResourceNode` 验证容量、视觉阶段、精确刷新日、同日幂等、序列化和旧数据迁移。
- `SeasonSystem` 验证锁拥有者、重复锁拒绝、取消释放和成功精确推进 10 分钟。

### 集成测试

真实主场景必须证明：

- 点击远处树木后自动绕过建筑；
- 到达后自动装备斧头；
- 树木在 2 秒时仍未提交，3 秒后一次获得 5 木材并停止；
- 体力、耐久和时间只变化一次；
- 矿石执行相同流程；
- 建造诊断立即识别新增木材或石材；
- 市集可以出售采集所得矿石；
- 保存加载保持剩余量和刷新日。

### 视觉验证

在 1280×720、1920×1080 和 3000×2000 下捕获：树木目标与路径、绿/红资格环、左侧根部斧头、三张砍倒帧、帧间淡入淡出、固定向右倒向、`+5 木材`、手绘树桩、矿脉阶段、碎石、背包已满和不可达提示。

### 性能与清理

- 36×28 单次寻路无可感知卡顿；
- 不每帧重建 A*；
- 资源视觉只在剩余量或日期变化时更新；
- 测试结束后无残留节点、信号连接或时间锁。
