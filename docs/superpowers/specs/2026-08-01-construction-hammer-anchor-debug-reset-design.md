# 施工锤子定位与调试重置设计

## 目标

- 将施工锤子稳定显示在建筑画面右下角的地基接触区域，避免镜头旋转后进入建筑中部。
- 将一次完整敲击周期从 `0.9` 秒缩短为 `0.6` 秒。
- 在 Debug 构建的 HUD 右上角提供无需确认的一键重置入口。
- 重置后删除当前 `slot 0` 存档并重新进入新游戏状态，恢复初始资源且不保留建筑。

## 锤子定位与动画

继续由 `ConstructionFeedback` 管理锤子。锤子不再依赖固定的世界空间右前方偏移，而是以建筑底部中心为基准，通过自定义 billboard shader 应用镜头平面内的右下角偏移。这样镜头围绕建筑旋转时，锤子仍保持在建筑画面的右下角。

锤柄末端仍是旋转圆心，手绘锤子贴图和现有落锤、冲击停顿、回弹曲线保持不变。`STRIKE_PERIOD` 改为 `0.6` 秒。锤头冲击帧应落在右下方地基边缘，而非建筑主体中部或远离建筑。

进度圆的现有位置和行为不在本次调整范围内。

## Debug 重置入口

`VillaHud` 增加右上角“重置存档”按钮和 `debug_reset_requested` 信号。按钮只在 `OS.is_debug_build()` 为真时可见；Release 构建不显示，也不能通过该按钮发起重置。

点击按钮立即发出信号，不显示二次确认。`Main` 监听该信号并负责：

1. 退出可能进行中的建造预览或动作状态，避免重载前继续提交操作。
2. 调用 `SaveManager.delete_save(0)` 删除当前存档；存档不存在也视为可继续重置。
3. 重新加载当前主场景。
4. 因 `slot 0` 已不存在，现有新游戏初始化流程恢复初始资源，并创建无玩家建筑的新场景。

重新加载意味着当前存档中的其他进度也回到新游戏基线，这与“清空当前存档”一致。其他存档槽不受影响。

## 边界与失败处理

- 重置只允许从 Debug HUD 发起；核心重置处理函数仍验证 Debug 构建，避免非 Debug 调用绕过 UI。
- 删除不存在的 `slot 0` 不阻止重载。
- 若场景重载失败，输出明确错误；不伪造成功提示。
- 不增加快捷键，不增加确认对话框，不更改其他存档槽。

## 测试与验收

- 组件测试断言敲击周期为 `0.6` 秒，并验证相同时间增量下动画相位使用新周期。
- 组件或 shader 契约测试断言锤子使用镜头平面内的屏幕偏移参数。
- 建筑视觉截图在默认镜头和至少一个旋转镜头下检查：锤头冲击点位于建筑右下角地基。
- HUD 测试验证 Debug 重置按钮、信号连接和 Release 隐藏逻辑。
- 主场景集成测试验证重置会删除 `slot 0`、触发重新加载，并在初始化后获得新游戏资源与零建筑。
- 完整运行建筑、主玩法、种植和网格回归测试。
