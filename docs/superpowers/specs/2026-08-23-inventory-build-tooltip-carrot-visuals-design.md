# 背包入口、建造悬停提示与胡萝卜两阶段视觉设计

## 背景

上一轮 HUD 重构保留了背包场景与 `I/Tab` 键盘逻辑，但遗漏了 HUD 上的鼠标入口，因此玩家无法从可见界面发现或打开背包。建造模式的建筑名称、占地与材料需求仍通过底部 `BuildCostBar` 常驻显示，与“提示统一收口、减少 HUD 遮挡”的方向不一致。

建筑成功放置后，`BuildingSystem` 已退出预览，但 `PlayerActionController` 为支持连续建造会再次选择同一建筑并重新进入预览，导致建筑阴影继续跟随鼠标。胡萝卜也没有纳入上一轮两阶段手绘资产替换，当前种子贴图是细线状旧资产，成熟贴图和程序化兜底模型均与谷物手绘风格不一致。

## 目标

- 为背包提供清晰、可点击的 HUD 入口，同时保留 `I/Tab` 快捷键。
- 移除建造详情常驻信息条，将名称、占地和材料需求放入建筑图标的鼠标悬停提示。
- 成功放置一栋建筑后立即清除建筑选择与预览阴影；玩家仍停留在建造模式。
- 将胡萝卜替换为与谷物一致的两阶段手绘 PNG 视觉。
- 保持库存、建造事务、作物成长、存档和经济语义不变。

## 非目标

- 不重做背包内容布局或农场仓库页签。
- 不改变建造分类、建筑造价、解锁条件或放置校验。
- 不增加连续建造开关；本轮统一采用单次选择、单次放置。
- 不修改胡萝卜成长天数、成熟判定、收获产量或季节规则。
- 不重做其他作物资产。

## 交互设计

### 背包入口

在 HUD 的顶部功能入口区增加“背包 I”按钮，与市场和通知入口并列。单击后由 HUD 发出背包请求，`Main` 负责关闭互斥模态窗口并打开背包；再次单击或按 `I/Tab` 可关闭背包。`Escape` 继续关闭背包。

按钮仅负责请求打开界面，不直接读取或修改库存。背包内容继续由现有 `InventoryUI` 和权威 `InventorySystem` 提供。

### 建造悬停提示

删除底部 HUD 的 `BuildCostBar` 及其运行时刷新逻辑。建筑动作图标继续常驻底部动作栏，每个图标的悬停提示包含：

- 建筑名称。
- 占地尺寸。
- 每种材料的“当前数量/需求数量”。
- 材料不足时的缺口数量。
- 蓝图未解锁或数据无效时的明确原因。

提示使用 Godot 控件的标准 tooltip 行为：鼠标进入图标后显示，离开后自动消失。失败操作、调试信息和其他运行时消息仍只进入右侧消息面板；悬停说明不是运行时事件，不写入消息流。

### 单次建造

成功放置建筑后，控制器执行以下状态转换：

1. 建造事务成功并返回建筑实例。
2. 刷新库存与动作栏材料数量。
3. 退出建筑预览。
4. 将当前建筑选择清为 `-1`。
5. 发出选择和动作栏更新信号，使所有建筑图标恢复未选中状态。

动作模式保持为建造模式，建筑分类保持不变。玩家若要继续建造，需要再次选择一个建筑图标。放置失败时保持当前选择和预览，以便玩家移动到合法位置后重试；失败原因进入右侧消息面板。

## 胡萝卜两阶段视觉

胡萝卜只保留两个唯一视觉阶段：

- 种子态：土壤表面的真实胡萝卜种子组合，不使用细线、纯色几何体或成熟胡萝卜缩小图。
- 成熟态：一簇可辨识的成熟胡萝卜，重点表现自然展开的羽状叶片、土面附近可见的橙色根肩和手绘明暗。

每个阶段包含一张正面 PNG 和一张背面 PNG，共四张源 PNG。规格与谷物 painted 资产一致：透明背景、1024×1024、柔和手绘笔触、暖色高光、清晰轮廓、统一地面锚点和相近的画面占比。

逻辑阶段映射保持四个位置：

- 阶段 0、1、2：复用胡萝卜种子态场景。
- 阶段 3：使用胡萝卜成熟态场景。

只保留 `variant_0`。确认无引用后，删除胡萝卜的 `variant_1/2`、中间阶段场景及不再使用的程序化材质和兜底网格定义。旧存档中的阶段值不迁移，载入后按上述视觉映射显示。

## 组件与数据流

- `VillaHud`：显示背包入口，发出背包请求；创建建筑按钮的 tooltip；不再维护建造详情条。
- `Main`：接收背包请求，协调互斥模态窗口；继续持有 HUD 消息总线。
- `InventoryUI`：继续负责打开、关闭、快捷键和背包/仓库内容刷新。
- `PlayerActionController`：在成功放置后清除建筑选择，不再自动恢复同一建筑预览。
- `BuildingSystem`：继续作为放置校验和事务提交的权威来源，成功后退出预览。
- `CropData/CropSpriteCluster`：继续按逻辑阶段加载胡萝卜场景和正反面 PNG。

背包点击数据流为：HUD 按钮 → HUD 信号 → Main 关闭互斥模态 → InventoryUI 打开。

建造数据流为：悬停图标读取现有建筑定义与库存快照 → tooltip 显示；点击图标选择建筑 → 鼠标放置 → BuildingSystem 提交 → 控制器清除选择与预览 → HUD 刷新。

## 失败处理

- 背包依赖未配置时按钮请求不得修改游戏状态，并向调试输出报告配置问题。
- 打开背包前关闭其他互斥模态，避免鼠标输入和暂停所有权冲突。
- 建筑放置失败时不得清除选择；具体失败原因继续进入消息面板。
- 胡萝卜 PNG 或场景缺失时资产测试失败；运行时保留统一安全兜底并报告缺失路径，不能静默显示旧程序化模型。
- 生成的新 PNG 必须通过尺寸、透明通道、非空像素和场景引用检查。

## 测试策略

所有行为修改遵循测试先行：

- 使用真实鼠标点击 HUD 背包按钮，验证背包打开、再次点击关闭、互斥模态关闭及 `I/Tab/Escape` 仍可用。
- 验证 HUD 场景不再包含 `BuildCostBar`，建筑图标 tooltip 包含名称、占地、材料数量和不可用原因。
- 验证成功放置后仍处于建造模式，但选择为 `-1`、图标无高亮且预览关闭。
- 验证放置失败后选择和预览保持，允许移动后重试。
- 验证胡萝卜只有种子态与成熟态两个唯一场景、四张源 PNG 和单一变体。
- 验证胡萝卜逻辑阶段映射为种子、种子、种子、成熟，并兼容阶段 0–3 的旧存档数据。
- 使用视觉捕获检查胡萝卜正反面、透明背景、地面锚点、占图比例和游戏相机距离下的辨识度。

## 验收标准

- 玩家能从可见 HUD 用鼠标打开背包，键盘入口保持可用。
- 建造名称、占地和材料需求不再常驻遮挡画面，只在悬停建筑图标时出现。
- 成功放置后建筑图标恢复未选中，预览阴影立即消失；失败放置仍可直接重试。
- 胡萝卜种子和成熟植株均为谷物风格的手绘 PNG，不显示细线种子或旧程序化模型。
- 新增自动化测试通过；与本轮无关的既有失败单独记录。
