# 施工锤击与圆形进度反馈设计

## 目标

调整建筑施工反馈，使锤子在建筑右前方底座执行真实的向下敲击动作，并在建筑右上角增加一个无刻度、半透明的圆形施工进度盘。新反馈沿用现有 10 秒一帧、30 秒完工规则，不改变建筑状态机、碰撞、交互、存档或切帧淡出淡入。

## 已确认视觉

- 锤击位置采用方案 A：建筑右前方底座。
- 锤子使用与建筑素材一致的手绘 2D 透明 PNG，不使用扁平 SVG 或实体 3D 网格。
- 锤柄末端是固定旋转中心；锤头沿圆弧从抬起位置向下敲击底座。
- 建筑右上角显示无刻度圆盘；扇形从正上方开始顺时针扫过。
- 圆盘表达整栋建筑的连续总进度：0 秒为空，10 秒约 1/3，20 秒约 2/3，30 秒满圈。
- 锤子和圆盘只在真实、未完工、未失活的建筑上显示；预览和完工态隐藏。

## 架构

新增独立的 `ConstructionFeedback` 组件，负责施工锤子和圆形进度盘。`BuildingInstance` 继续拥有施工状态与累计时间，只向反馈组件传入建筑视觉尺寸、当前进度、预览/完成状态和帧间隔。

文件职责：

- `scripts/buildings/construction_feedback.gd`：创建并配置反馈节点，计算敲击角度，更新圆盘进度和显示状态。
- `assets/buildings/construction/construction_hammer_painted.png`：手绘透明锤子素材。
- `assets/buildings/construction/construction_progress.gdshader`：绘制透明外圈和顺时针扇形。
- `scripts/buildings/building_instance.gd`：实例化反馈组件并转发施工状态，不再直接维护锤子相位、位置或可见性。

这样施工反馈可以独立测试和替换，并避免继续扩大 `BuildingInstance` 的视觉职责。

## 手绘锤子资源

使用现有谷仓施工帧和正式建筑素材作为风格参考，生成一张 512×512 透明 PNG：

- 固定等距三分之四视角，暖色左上光照。
- 木质锤柄带手绘纹理，锤头为略有磨损的锻铁材质。
- 锤柄末端、完整锤柄和锤头均不得裁切。
- 无人物、文字、地面、阴影底板或额外工具。
- 锤柄方向清楚，便于将末端精确设为旋转中心。

若资源加载失败，只隐藏锤子并发出一次警告；建筑施工继续正常运行。

## 锤击动画

`ConstructionFeedback` 使用一个 `Node3D` 作为锤柄末端枢轴，手绘锤子 `Sprite3D` 相对枢轴偏移，使锤柄末端与局部原点重合。枢轴定位在建筑右前方、接近地面的底座位置。

动画周期为 0.9 秒，使用分段缓动而不是正弦摆动：

1. 周期 0%–25%：保持抬起角度约 25°。
2. 周期 25%–48%：三次方加速旋转到约 105°，锤头沿弧线向左下方落向底座。
3. 周期 48%–55%：在敲击角度短暂停顿，形成接触重量感。
4. 周期 55%–100%：缓出回弹到抬起角度。

锤柄末端在整个周期中位置不变。动画只修改枢轴的局部 Z 轴旋转；不修改建筑或施工帧位置。暂停场景树时动画与施工计时一起暂停。

## 圆形进度盘

进度盘使用一个面向镜头的 `Sprite3D` 和独立空间 Shader。Shader 根据 UV 坐标计算半径与极角：

- 外圈为低不透明度暖白色细环。
- 已完成区域为暖金色半透明扇形。
- 未完成区域完全透明，仅保留外圈。
- 无数字、刻度、指针或中心实体圆。
- 扇形从 12 点方向开始，随 `progress` 从 0 到 1 顺时针连续增长。

圆盘位于建筑视觉范围的右上方，尺寸按 `BuildingData.visual_size` 计算并限制最小/最大值，保证围栏、路灯和谷仓上都可辨认。圆盘进度直接使用 `BuildingInstance.get_construction_progress()`，因此切换施工美术帧时不会归零或跳回。

Shader 或承载纹理缺失时，只隐藏圆盘并发出一次警告，不影响锤子或施工状态。

## 组件接口与数据流

`ConstructionFeedback` 提供：

```gdscript
func configure(visual_size: Vector2) -> void
func update_state(progress: float, preview: bool, complete: bool, active: bool) -> void
func advance_animation(delta: float) -> void
static func strike_angle_for_phase(phase: float) -> float
```

数据流：

1. `BuildingInstance.configure()` 创建或取得反馈组件，并传入建筑视觉尺寸。
2. `start_construction()`、`restore_construction()`、阶段切换和预览切换后调用 `update_state()`。
3. `_process(delta)` 先推进现有施工时间，再把最新总进度传给反馈组件，并调用 `advance_animation(delta)`。
4. `complete_construction()` 进入完成态后，组件在同一帧隐藏锤子与圆盘。
5. `deactivate()` 明确传入 `active = false`，停止并隐藏全部施工反馈。

## 渲染隔离

整个 `ConstructionFeedback` 子树不加入 `BuildingInstance._visual_geometry()`：

- 不随建筑摄像机遮挡降低透明度。
- 不接受建造预览的绿色/红色染色。
- 不参与建筑淡入淡出、碰撞、交互或摄像机遮挡体。
- 不写入存档；进度始终由已保存的施工累计时间重建。

## 边界与兼容

- `progress` 在组件入口限制为 `0.0..1.0`。
- `delta <= 0` 时不推进锤击相位。
- 大帧间隔使用取模保持 0.9 秒周期，不改变施工时间的现有大步长行为。
- 旧 SVG 锤子资源在新 PNG 通过验收后删除；不得同时保留两套运行时锤子。
- 现有施工帧、30 秒工期、存档迁移、施工粒子、信号和物理规则保持不变。

## 测试与视觉验收

- 单元测试敲击关键点：抬起、加速段中间、触底和回弹结束角度。
- 验证锤柄末端枢轴位置在动画前后不变，只有旋转角度变化。
- 验证圆盘 Shader 参数随 0%、1/3、2/3、100% 总进度连续更新。
- 验证预览、完成和失活状态同时隐藏锤子与圆盘。
- 验证建筑遮挡和预览染色不会改变反馈组件透明度或颜色。
- 验证手绘 PNG 为 512×512、带透明通道且四角透明。
- 更新建筑视觉场景契约，并生成全景与施工近景截图；近景必须看见锤头向底座落下的姿态、右前方固定枢轴以及右上角无刻度扇形进度盘。
- 运行建筑、农场、网格、主游戏集成和玩家绑定回归套件。
