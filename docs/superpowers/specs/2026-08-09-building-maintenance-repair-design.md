# 建筑维护与维修交互设计

日期：2026-08-09

## 目标

把已经存在但难以发现的建筑维护逻辑改造成完整、直观的游戏闭环。玩家应当能从建筑本身看出轻微破损或停产状态，并在点击建筑后的操作界面中查看期限、费用和维修进度。世界中不再显示巨大的“修”字。

## 已有基础与问题

当前 `ProductionSystem` 已记录建筑维护到期日，维护逾期会暂停生产；`EconomyProgressionSystem` 也能生成维护报价，并在“服务 → 维护”页面完成结算。现有规则是每 7 天维护一次，所有建筑统一消耗 25 金币、1 木材和 1 石材。

主要问题是维修入口藏在全局服务页面，建筑上只有一个不可交互的“修”字，建筑操作界面没有维修按钮，也没有维修过程或可信的破损表现。

## 玩法规则

### 维护周期

- 每座参与经济生产或功能运转的建筑，建成或维修完成后获得 14 天维护周期。
- 到期日前 1 天进入 `warning` 状态，继续正常生产并允许提前维修。
- 到期当天进入 `overdue` 状态，停止新任务、暂停已有队列、停止被动产出和功能效果。
- 维修持续 3 秒，状态为 `repairing`；维修过程中保持暂停。
- 维修完成时，下次维护日设置为“当前游戏日 + 14 天”。提前维修不保留或叠加剩余时间。
- 停产期间不补算错过的生产、灌溉或被动产出。

维护状态为：

| 状态 | 条件 | 生产 | 可维修 |
| --- | --- | --- | --- |
| `normal` | 距到期至少 2 天 | 正常 | 否 |
| `warning` | 距到期 1 天 | 正常 | 是 |
| `overdue` | 当前日大于等于到期日 | 暂停 | 是 |
| `repairing` | 已支付维修费用且计时未结束 | 暂停 | 否 |

围栏、路灯等纯装饰建筑不进入维护系统；生产、仓储、灌溉、温室、蜂房、鸡舍和资源建筑进入维护系统。

### 维修费用

维修费用按建筑占地规模与已购买升级总等级计算。升级总等级是队列、速度和仓储升级等级之和。

| 占地面积 | 规模 | 基础金币 | 基础木材 | 基础石材 |
| --- | --- | ---: | ---: | ---: |
| 1–2 格 | 小型 | 20 | 1 | 1 |
| 3–4 格 | 中型 | 35 | 2 | 2 |
| 5 格以上 | 大型 | 55 | 3 | 3 |

最终费用：

- 金币 = 基础金币 + `10 × 升级总等级`
- 木材 = 基础木材 + `ceil(升级总等级 / 2)`
- 石材 = 基础石材 + `ceil(升级总等级 / 2)`

预警期与逾期后的费用相同，不提供等待惩罚或提前维修折扣，避免玩家为了最优收益被迫精确卡时点。

## 建筑世界表现

### 移除文字状态牌

- `EconomyIndicator` 不再为维护状态显示“修”。
- “满”仍保留为仓储满载提示，维护状态改由建筑破损视觉表达。

### 破损状态

新增独立的 `BuildingMaintenanceVisual`，挂在每个 `BuildingInstance` 下并根据建筑的 `visual_size` 和地面锚点缩放定位：

- `normal`：隐藏维护视觉。
- `warning`：建筑轻微降饱和；底部出现少量细裂纹和一块松动木板，不覆盖建筑主体细节。
- `overdue`：裂纹颜色加深并扩展，地基旁增加两三块散落碎片，建筑整体略微变暗；生产活动层停止。
- `repairing`：保留逾期破损视觉，在建筑右下方地基位置播放现有手绘锤子敲击动画，周期 0.6 秒；不显示建造进度圆盘。
- 维修完成：破损层在 0.35 秒内淡出，建筑色彩恢复，并播放一个轻微的暖色闪光反馈。

破损层使用项目内的手绘配色与不规则边缘，不用文字、红叉或软件式警告图标。破损仅作为视觉覆盖层，不替换每种建筑的完整建模图片，保证所有建筑都能统一适配。

## 建筑操作界面

### 入口

点击可维护建筑仍打开当前建筑操作界面。维修卡片固定放在“建筑状态”页的上方；处于 `warning`、`overdue` 或 `repairing` 状态时，界面默认打开“建筑状态”页，避免玩家先进入不可操作的生产页。

### 维修卡片

卡片保持当前苹果风格的紧凑布局，使用直角内容区域和细边框，不增加新弹窗：

- 标题：`建筑维护`
- 正常：绿色状态点，显示“距维护还有 N 天”，不显示维修按钮。
- 预警：黄色状态点，显示“明天需要维护，当前仍可生产”，按钮为“提前维修”。
- 逾期：红色状态点，显示“建筑破损，生产已暂停”，按钮为“开始维修”。
- 维修中：蓝色状态点，显示“维修中 2.4 秒”，按钮禁用并显示线性进度条。
- 费用行：金币、木材、石材各自显示 `持有数量 / 需要数量`。不足项使用红色，按钮禁用。
- 反馈行：显示具体失败原因，例如“木材还缺 2”或“建筑状态已变化，请刷新”。

生产建筑在破损时仍能查看原有队列和投入，但开始生产按钮禁用并解释“建筑需要维修”。已有队列只暂停，不清空。

### 全局服务页

保留“服务 → 维护”作为全部建筑的维护总览：

- 正常建筑显示到期日，不允许执行。
- 预警建筑允许提前维修。
- 逾期建筑允许开始维修。
- 维修中的建筑显示剩余秒数并禁用按钮。

建筑操作界面是主要入口，全局服务页是批量查看入口。两处调用同一个维修命令，不复制结算逻辑。

## 系统边界与数据流

### `ProductionSystem`

作为维护状态的唯一权威来源，新增：

- `get_maintenance_state(building)`
- `get_maintenance_days_remaining(building)`
- `can_start_maintenance(building, wallet, inventory)`
- `start_maintenance(building, wallet, inventory)`
- 维修剩余秒数字典和实时更新逻辑

点击维修时执行一次原子事务：重新检查建筑状态、金币和材料；成功后扣除费用并写入 `repairing` 状态。只有成功事务才发出库存、金币和维护状态事件。3 秒计时完成时更新到期日、清除维修状态并恢复生产。

`is_maintenance_paused()` 同时覆盖 `overdue` 与 `repairing`。配方预检会分别返回 `maintenance_overdue` 或 `maintenance_in_progress`，以便 UI 给出精确提示。

### `EconomyProgressionSystem`

根据建筑占地与自身记录的升级等级生成维修报价。`maintain()` 改为启动维修过程，不再同步瞬间完成。服务视图显示四种状态及剩余时间。

### `BuildingInstance`

接收维护视觉状态，不保存经济数据。它只负责：移除“修”字、切换破损覆盖层、停止活动层以及播放维修锤子和完成淡出。

### UI 刷新

`production_maintenance_changed` 在进入预警、逾期、开始维修和完成维修时发出。建筑操作界面、服务页、通知系统和建筑视觉均从 `ProductionSystem` 重新读取快照，不依赖缓存推断状态。

## 时间、暂停与存档

- 维修的 3 秒使用真实运行时间，不受游戏内时钟速度影响。
- 建筑操作界面会暂停世界，因此维修计时和锤子动画使用 `PROCESS_MODE_ALWAYS`，面板打开时也能完成。
- 维护存档版本升级，保存每座建筑的到期日以及维修剩余秒数。
- 旧版存档自动迁移：保留已有到期日，没有维修中记录。
- 维修中保存后重新载入，已支付的费用不会再次扣除，剩余动画继续。
- 建筑在维修中被拆除时清理维修记录，不退款；这是已有拆除行为的延续。
- 调试面板直接跳日后立即重新计算预警或逾期视觉。

## 通知与错误处理

- 第 13 天只发送一次“建筑即将需要维护”通知。
- 第 14 天只发送一次“建筑破损并暂停生产”通知。
- 维修开始和完成各发送一次状态变化事件；完成时不产生额外市场通知。
- 双击维修按钮、信号重入、库存或金币提交失败都不能重复扣费。
- 建筑失效、未注册或还未到预警期时拒绝维修，并保持全部状态不变。

## 测试与验收

### 系统测试

- 新建筑的到期日为当前日 + 14。
- 第 12 天为正常，第 13 天为预警且继续生产，第 14 天为逾期并暂停。
- 预警与逾期均可启动维修，正常与维修中不能重复启动。
- 小、中、大建筑及升级等级生成正确报价。
- 支付只发生一次；失败事务不改变金币、库存、到期日或维修状态。
- 3 秒前不恢复，3 秒完成后恢复队列并设置新到期日。
- 旧版存档迁移和维修中存档恢复正确。

### UI 与视觉测试

- 建筑上不再出现“修”字。
- 三种破损视觉状态和维修锤子按权威状态切换。
- 预警/逾期建筑打开时默认进入状态页。
- 维修卡片展示正确期限、费用、缺口、按钮和进度。
- 面板暂停世界时维修计时仍能完成。
- 服务页与建筑卡片均能启动同一维修流程。

### 完成标准

玩家不进入全局服务页，也能通过“看到建筑破损 → 点击建筑 → 查看费用 → 开始维修 → 观看 3 秒动画 → 恢复生产”完成整个维修闭环；过程中没有“修”字，也不会丢失生产队列或重复扣费。

## 非目标

- 本版本不加入 NPC 维修工、维修队列或多建筑批量付款。
- 不为每种建筑单独绘制完整破损帧。
- 不加入随机故障、灾害损伤或建筑永久毁坏。
- 不改变工具耐久度维修逻辑。
