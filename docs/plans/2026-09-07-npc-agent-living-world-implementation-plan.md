## 1. 交付原则与阶段总览

每个阶段交付一个能在正式场景中使用的完整循环，包括必要的规则、AI 接入、画面反馈、失败处理与存读档。不得以“接口已写好”“模型会说了”“调试按钮能强制完成”替代可玩的结果。

设计稿第 19 节的四个大阶段是产品里程碑；实际工作按本计划的 P0～P12 执行。这样把原来过大的“最小自主社会”分成多个可验证交付，不减少其最终范围。

| 阶段 | 交付主题 | 玩家能够验证的结果 | 直接依赖 | 状态 |
|---|---|---|---|---|
| P0 | 对话交易与执行结果可信 | 聊天议价、确认成交；关窗或重试不会重复扣款 | 现有系统 | 已验收 |
| P1 | 建筑产权与双向收费加工 | 玩家/NPC 使用他人的工坊，钱与成品归正确主体 | P0 | 已验收 |
| P2 | 最小居民生活经济 | 12 名居民工作领薪、购买并消耗食物，短缺有真实原因 | P1 | 已验收 |
| P3 | NPC 自发项目与持续执行 | 没有玩家发单，NPC 也能自己计划采购、加工与销售 | P2 | 已验收 |
| P4 | NPC 筹料自建并营业 | NPC 筹材料建风车，玩家和其他 NPC 付费使用 | P1、P3 | 已验收 |
| P5 | 真实需求与实体公告板 | 玩家/NPC 发单、接单、生产交货，需求和资金同步结算 | P2、P3 | 已验收 |
| P6 | 对话改目标与临时插单 | NPC 接受临时任务，做完后恢复原计划，读档仍连续 | P3、P5 | 未开始 |
| P7 | GameEnvAgent 公共采购 | 公共协调者用有限预算处理短缺，NPC 可以响应或拒绝 | P2、P5、P6 | 未开始 |
| P8 | 分工合作、学习与个人发展 | 角色雇工、分包、合作投资，承担不同长期项目 | P4、P6、P7 | 未开始 |
| P9 | 真实探索与私人情报交易 | 资助调查、取得证据、购买情报并改变后续行动 | P5、P6、P8 | 未开始 |
| P10 | 天气、运输与共同修复 | 路线受阻产生短缺，共同修复后供给实际恢复 | P7、P8、P9 | 未开始 |
| P11 | 公共活动与生活消费 | 活动有预算、供应、报名、真实参与和结束反馈 | P7、P8、P10 | 未开始 |
| P12 | 扩大社会并长期验收 | 更大人口下长期运行稳定，玩家可选择多种生活路线 | P0～P11 | 未开始 |

默认依次实施，前一阶段通过后再开放下一阶段的能力。直接依赖表示不能省略的功能基础，不表示需要并行开发或另开分支。

里程碑：M1=P0～P1（可信交易与经营）；M2=P2～P4（自主谋生与建造）；M3=P5～P7（完整最小自主社会）；M4=P8～P11（分工、探索与公共生活）；M5=P12（规模化稳定交付）。

## 2. 每阶段共同的完成标准

每个阶段同时满足以下要求，状态才从“实现中”变为“已验收”：

1. **完整路径**：正式场景中有入口，能够走通该阶段的成功、拒绝/失败与后续恢复；领域测试和开发者强制按钮不算唯一入口。
2. **事实正确**：资产、位置、耗时、所有权和完成凭据由规则执行。UI 成功提示与已提交结果一致，模型承诺不等于完成。
3. **恢复正确**：在关键中间状态保存并重载，结果与不中断执行一致；关闭 UI 不取消已接受事项，重复请求不重复结算。
4. **原功能可用**：执行涉及领域的现有回归测试；建筑、农田、市场、钓鱼、高尔夫、对话输入与小地图的已有体验不被破坏。
5. **模型与规则分开验证**：确定性集成使用可回放模型响应；凡涉及 AI 新决策的阶段另做真实服务试玩，保留实际观察和失败样本。未完成真实模型验证时标记“规则通过，AI 验收待完成”。
6. **留下证据**：阶段报告包含版本、测试命令、结果、试玩步骤、截图/关键事件、经济核对和已知限制。不能只报告“看起来正常”。

各阶段的任务按“领域规则 → 持久化/事务 → 工具和执行器 → 正式 UI/场景 → 自动化与试玩”顺序完成；这五项属于一次完整交付，不是五个可以单独宣布完成的产品阶段。

### 2.1 测试和存档隔离

- 基于正式场景创建测试世界，沿用 `--farm-test`、关闭真实自动读档/写档和远程调用的机制；测试存档写到独立的 `user://` 测试目录或 `tmp/living-world/`。
- 固定初始资源、世界随机种子和事件时间。测试夹具可以设定材料/地块/需求，测试动作必须走正式执行路径，不直接改金币或把任务状态写为完成。
- 真实模型试玩使用独立测试会话和存档，显式开启服务；绝不自动使用、覆盖 `data/farm_3d_save.json`。
- 测试初始数据/不含私人内容的可回放响应可以版本化；真实聊天、模型原始追踪、截图临时输出、存档和数据库留在忽略目录。
- 存档升级时保留旧版本夹具，验证一次性初始化和反复重载。读档损坏仍遵循既有初始开局行为；原文件按恢复策略保留，不能把迁移失败解释为“空资产迁移成功”后静默覆盖。

### 2.2 验收记录与运行入口

`tests/run_living_world_tests.ps1` 已支持 P0～P5 与依赖回归；`--living-world-scenario=P0` 到 `P5` 可用于隔离场景，显式 `--living-world-live-agents` 连接真实服务。P6～P12 尚不可运行。

```powershell
# 在项目根目录运行。
.\tests\run_living_world_tests.ps1 -Stage P0
.\tests\run_living_world_tests.ps1 -Stage P4 -IncludeDependencies

# 每个阶段都提供同名可试玩场景预设，使用隔离存档。
godot_console.exe --path . -- --farm-test --living-world-scenario=P4
```

运行器要求：检查阶段名、必需测试文件和工具；缺少测试时报错，不跳过并显示成功；按子进程退出码汇总；有超时保护；默认不调用真实模型。场景预设由开发参数加载，不出现在正式玩家流程；新增 `--living-world-live-agents` 作为隔离场景的真实服务验证开关，只改变测试会话的 Agent 连接，不绕过存档隔离。P0 明确区分“可否远程调用”和“可否写真实存档”，不再让这两个权限绑定。

每阶段新增 `docs/validation/living-world/Pn.md` 报告。首行填写“未执行 / 自动化通过但试玩未完成 / 已验收”，不预填通过结论。报告中的资源变化用实际事件 ID 或测试断言对应；无需提交任何私人模型配置。

## 4. P0：对话交易和结果反馈完整可用

**可试玩交付**：与老李谈一笔物物交换，看到双方物品和数量，进行一次还价，确认后真实成交；再次点击或关闭重开都不会重复扣物。

**实施任务**：

- [x] P0.1 记录现有 3D Agent、交易、生产和输入回归基线；建立上述测试运行器与隔离场景预设。
- [x] P0.2 改造原对话交易展示，使用物品/金币/有效期卡片替代 JSON；保留接受、拒绝、还价和失效反馈。
- [x] P0.3 以交易/动作实际提交结果驱动“已成交、已接单、失败”；修正先显示成功语句、后验证动作导致的误导状态。
- [x] P0.4 串联请求、提案版本、动作、生产订单和最终结果 ID；持久化必要结果和幂等记录，不只记录模型流完成。
- [x] P0.5 明确暂停时只处理 UI 确认的即时交易，后台动作等恢复后重验；关窗取消未完成生成但保留已接受交易/订单。
- [x] P0.6 用现有真实 NPC 租用加工验证“入队 → 加工完成 → 物品入账”三种事实与恢复。

**主要改动**：交易系统、`agent_runtime.gd`、事件存储、对话 UI、调试追踪、`farm_session.gd`；服务端返回语义与工具契约同步。

**自动化验收**：扩展 `run_3d_agent_tests.gd`、`run_agent_system_tests.gd`，新增 `run_living_world_p0_tests.gd`。覆盖重复确认、还价使旧报价失效、物品不足不扣款、先取消后旧回复到达、暂停/恢复、生产中读档、未接受提案不成任务。

**手工验收**：正式场景与 NPC 实际议价并成交一次；再人为移走所需物品使交易失败，界面准确说明。最后租用加工，关窗后查看成品和追踪。

**完成门槛**：成功/失败都能由 UI 完整操作；三笔关键账与规则记录一致；交易资产总量与预期一致，无重复扣费；真实服务回复不会把失败动作显示为已完成。当前阶段不创建自由项目或新人口。

## 5. P1：统一产权与双向收费加工

**可试玩交付**：测试世界有一座玩家风车和一座明确归老李所有的风车。玩家用老李的风车加工，老李用玩家风车加工，阿禾也能向老李下单；成品分别归客户，收入归建筑所有者。

**实施任务**：

- [x] P1.1 给真实建筑增加稳定实例 ID、所有者和经营政策；旧存档建筑默认归玩家，订单关联迁移后仍稳定。
- [x] P1.2 建立主体资产访问适配，统一玩家/NPC 收付与物品访问；逐步替换生产里固定 `_rental_wallet` 和只支持 NPC 租客的结算路径。
- [x] P1.3 将固定站点费率变成每座建筑的初始费表与版本，支持开放配方、所有者自用容量；已有订单锁定价格和容量。
- [x] P1.4 完成加工费托管、开工转款、未开工合法取消退款；旧订单标记已收款，不重复扣付，也不为旧预收订单凭空补出退款资金。
- [x] P1.5 复用原生产界面提供所有者/客户视图，按权限显示调价、维修、加工与客户成品；客户不能取他人成品或拆除建筑。
- [x] P1.6 统一维护和拆除保护，覆盖客户原料、在制品、待退款与未领取成品；自用不发生给自己转账。

**主要改动**：主体资产适配、建筑实例、生产系统及订单状态、`windmill_view.gd`、会话保存/验证、租用工具上下文。

**自动化验收**：新增 `run_living_world_p1_tests.gd`；在四种所有者/客户组合上验证扣料、托管、收款、产出与退款；覆盖排队后涨价、NPC 钱不足、背包容量不足、非法调价/取货、拆除有订单建筑及各状态读档。复用生产、风车、食品工坊和 Agent 测试。

**手工验收**：点击两座风车完成双向加工，界面能辨别谁收钱、谁拿货；修改未来费率，已排队订单费用保持不变。

**完成门槛**：所有组合都有真实 3D 建筑和实际订单；钱与物完全核对。NPC 所有的初始建筑由明确测试夹具提供，**本阶段不声称 NPC 已会自己建造**，P4 完成该行为。

## 6. P2：12 名居民与一条食品生活循环

**可试玩交付**：12 名居民（包含现有重点 NPC）和旅店/公共组织拥有持续状态。居民完成有限岗位、获得来源明确的工资、买食物并消耗；市场面板能说明缺货或购买力不足来自哪里。

**实施任务**：

- [x] P2.1 增加居民与组织初始配置、稳定 actor/account ID、库存引用和统计分组；一次性开局资金有来源，不每日刷新钱包。
- [x] P2.2 接入最小生活需要、储备目标和食物替代；先复用可生产食品，按实际消费扣库存，买不起与买不到分开记录。
- [x] P2.3 实现一种可验证工作班次，雇主预留工资，按在岗/工作完成事实结算；先由旅店或明确的场外雇主提供岗位和收入，不能无来源发工资。
- [x] P2.4 实现预算内市场采购和库存消费，显式记录市场做市商的外部边界流量，沿用原报价事务。
- [x] P2.5 对迁移的同源居民关闭旧人口需求注入与快捷生产，保持未迁移来源明确；聚合群体没有额外钱包。
- [x] P2.6 调试面板增加居民/组织和日结账目；正式市场显示需求来源摘要，附近少量人物表现对应真实居民记录。

**主要改动**：环境系统、季节/日结、运输与合作项目、钓鱼/生长规则的小范围适配、公共计划和市场因果记录。

**自动化验收**：新增 `run_living_world_p10_tests.gd`；固定种子校验预报/实际天气、休息跨日不漏结算、运输货物不提前出现、修复贡献不双计、完成修复后运力变化、补贴不能循环领取、重载不重抽事件。

**手工与真实 AI 验收**：同一事件分别走“玩家参与修复”和“玩家不参与”两条路径；观察 NPC/公共组织响应、实际工时材料、供货和恢复。AI 可以选等待或外援，不要求每局固定触发修路任务。

**完成门槛**：环境事实、实际生产/运输、需求、价格和恢复效果能串成一条证据链；不存在只改事件台词却没有世界变化的完成状态。

## 15. P11：公共活动、报名与真实消费

**可试玩交付**：GameEnvAgent 或 NPC 提出湖畔活动，落实场地、预算、供应和报名；玩家可以参加已有小游戏，居民采购/观赛/工作，结束后实际结算成本、收益与关系。

**实施任务**：

- [ ] P11.1 实现活动提案、场地占用、容量、准备/报名/进行/结束/取消状态，全部由游戏时间推进。
- [ ] P11.2 预算按实际赞助、票款和已拨款资金创建；供应采购、雇工、奖励走现有订单与托管，不花预计收入。
- [ ] P11.3 居民按兴趣、收入、路程与日程决定报名和到访；具名角色独立回应邀请，可拒绝、退出或要求条件。
- [ ] P11.4 将钓鱼/高尔夫参与或成绩接为可信活动凭据，绑定比赛/轮次 ID 和奖励组；NPC 尚无真实比赛执行器时仅观赛、经营或工作，不生成 NPC 比赛成绩。
- [ ] P11.5 提供报名、活动地图/日程、供应进度和结算反馈；报名不足可缩小或取消，未用资金/物品按条款退回。
- [ ] P11.6 支持 NPC/玩家提出活动，由公共协调者只处理公共场地、预算与协调部分；记录实际消费和参与对后续项目的影响。

**主要改动**：社会活动模块、公共计划、居民日程、原钓鱼/高尔夫完成事件、公告板/HUD、预算与存档。

**自动化验收**：新增 `run_living_world_p11_tests.gd`；验证场地/人数冲突、资金不足、预计门票不可支付、实际到访一次消费、同局比赛不重复领奖、报名后读档、取消退还与已完成合法交付不追回。

**手工与真实 AI 验收**：跑一次正常活动和一次低报名取消/缩小的活动；玩家参加或完全不参加都能继续农庄经营。检查邻近居民场景表现与真实报名/工作记录对应。

**完成门槛**：筹备、生产采购、参与、消费和结束结果都真实发生；活动丰富生活但不成为玩家每天必须完成的清单，组织者也可能亏损。

## 16. P12：扩大人口与长期稳定验收

**可试玩交付**：从 12 人扩至 30～60 人，再按性能结果尝试 60～120 人；重点角色逐步到约 6～8 人、组织约 3～5 个，场上同时展示人数独立控制，多个游戏周后仍能解释社会变化。

**实施任务**：

- [ ] P12.1 实现普通居民与重点 NPC 提升/降级，沿用原 actor、账户、项目、关系、日程与记忆引用，切换执行器不重复行动。
- [ ] P12.2 同步调校人口、粮食供给、设施/劳动产能、工资和外贸额度；扩展厨师、工匠等有不同能力与动机的角色，不只增加消费者。
- [ ] P12.3 控制可见人物池、批量居民日结、事件订阅、上下文摘要、分级请求预算与公平调度；测量真实耗时与调用占用。
- [ ] P12.4 按多种玩家策略跑长期经济试验，检查资金来源、库存、缺货、垄断、全员追同一配方、公共干预振荡和失败恢复。
- [ ] P12.5 做全存档版本迁移、服务中断、跨日休息、窗口暂停和长时间运行回归；关键报告与追踪均可重建因果。
- [ ] P12.6 发布操作说明、已开放能力清单、规模/性能测量和已知限制；将暂未验收的更大规模保留为实验配置。

**自动化验收**：新增 `run_living_world_p12_tests.gd` 与经济批量模拟入口；至少三个固定种子各推进 28 游戏日，比较确定性经营、加入自主 NPC、加入公共协调三组；回放模型记录保证规则重现，另以真实模型跑多次 14 日观察窗口。

**手工验收**：分别体验种植、转售、出租/投资、探索、休闲及不接委托；验证在不同路线中都能理解并利用世界变化。检查新角色有真实差异，玩家影响不被人口规模吞没。

**完成门槛**：所有整数资产/额度不变量零违例、无重复结算、无无法恢复项目；真实模型试跑至少观察两类自发项目、一条私人分工链和一次有证据的方案调整。性能在固定测试机器/分辨率记录 p50/p95 帧耗时、日结耗时、请求队列等待和 token/游戏日，按测量确定开放上限，不以未经测试的 120 人作为通过承诺。

性能初始验收预算：在 P0 记录的同机同分辨率场景下，新增社会模拟的主线程开销 p95 ≤ 4 ms/帧；日结拆批处理，单帧日结工作 ≤ 8 ms；稳定展示容量下采样至少 10 分钟，p95 总帧耗时不高于基线 p95 + 4 ms。真实请求并发不得超过配置上限，每游戏日模型用量不得突破测试前设定的预算，超限延后规划且 UI 保持可操作。预算是待测的验收目标，不是已有结果；若 60/120 人不达标，只开放已通过的规模，并明确记录未达标项，不能直接把测试阈值改大后宣称通过。

## 18. 迁移、渐进开放与失败处置

- 当前主存档版本为 v5；在首个需要字段变更的阶段新增迁移器，之后按真实落地版本递增。每阶段注明新增字段、默认值、旧状态映射和重复加载行为，不预先写一个尚未实现的最终大版本。
- 同一主体/需求/生产来源在任意时刻只有一个执行者。旧人口需求、快捷产出、NPC 虚拟建筑与新领域接管按来源登记，迁移后禁用旧写路径，不靠同时跑两套再抵消统计。
- 新系统先在隔离场景验收，完成后默认开放已支持能力；尚未完成的工具不出现在 Agent 能力目录，也不能接收需要它的付费任务。
- 模块停用或服务离线不意味着删除事实。保留已接受合同、托管、在途生产、人口账户和公共承诺；暂停新规划，按已确定步骤或规则保障继续。
- 代码回退不能让旧二进制静默写坏新存档。跨不兼容版本恢复使用相应旧存档备份，在隔离副本验证；不要在旧代码上强行删新字段后保存真实世界。
- 发现经济不变量或权益丢失时停止该新路径并修复，保留证据与本地存档；不能用重置 NPC 钱包或重建整个世界掩盖失败。

## 21. 多地图区域扩展 R1～R4

依据[多地图区域设计](../design/2026-09-07-npc-agent-living-world-design.md#23-多地图区域模式)。复用现有正式 3D 入口和系统，直接改造原文件；每张地图只增加区域内容与配置，不复制经济或 NPC 运行时。以下均为待实施任务，沿用第 2 节的完整交付、测试隔离和证据要求。

| 阶段 | 可玩的交付结果 | 直接依赖 | 状态 |
|---|---|---|---|
| R1 | 庄园四周看不到封边围墙和断面，找到四向出口并查看去向与条件 | 现有正式 3D 地图、P0～P5 基础 | 未开始 |
| R2 | 完成西侧入口解锁，在庄园与林地之间采集、往返、保存恢复，庄园生产连续 | R1、P1/P3/P5 的产权与订单基础 | 未开始 |
| R3 | NPC 自主通过合法入口旅行，跨地图采集/加工/交付，玩家能见到实际到达 | R2、P3、P5 | 未开始 |
| R4 | 集镇独立市场与真实运输形成价差，运费、时间、库存和收益可核对 | R3、P8 的合作基础 | 未开始 |

R1～R3 可在 P0～P5 基础上依次推进，不依赖 P7 的 AI 公共协调或完整探索链才开放第一个区域。P9 使用跨地图调查时需接入 R3，纯本地图探索可独立实施；P10 的跨区域路况和物流接入 R4，已有本地图事件不受此限制。R4 的 GameEnvAgent 扩展另外依赖 P7。这些依赖不要求并行开发，也不调整已验收阶段的范围。

### R1：自然边界与可发现的出口

任务：

- [ ] 区分玩法范围、空气墙、远景延伸范围与相机取景范围，替换沿边界制造墙面的地形；保留自然地势和七洞坡地。
- [ ] 在当前地图四向放置路口/路牌和公共通行缓冲区，提供稳定入口 ID、目标地图 ID、到达锚点及条件描述的配置契约。
- [ ] 正式交互可查看去向与进度；未知区域只显示允许公开的内容，小地图图标与 G 开关继续有效。
- [ ] 建造预览与实际建造都保护入口、返程锚点和通路；迁移布局避开已有农田、建筑、钓位和球道。
- [ ] 未实现的目标地图保持“尚未开放”，不收解锁材料或费用，不能出现可用入口却切换到空场景。

验收：从庄园步行找到四个方向的出口；贴边不能穿越，也看不到围墙或地形断面。实际检查日常镜头、最大旋转/缩放、七洞跟球及总览画面，截图证明边界隐藏有效。保存重载后已发现路口保持可见，已有资产、成绩和玩法位置不变。

### R2：入口解锁与双地图完整循环

任务：

- [ ] 将原会话拆清持久世界事实与当前地图表现的职责，统一时钟、账户、订单、合同保持唯一；区域 `map_id` 纳入地点、建筑位置和存档引用。
- [ ] 制作可活动的西部林地，具备实际资源和明确返回入口；其余新地图内容不在本阶段假装完成。
- [ ] 实现西侧公共通路的一组可组合解锁条件，接入真实材料/工程凭据、剩余需求、多人贡献和幂等结算；目标未就绪时禁止收取投入。
- [ ] 实现 E 交互、模态与小游戏状态检查、切换过渡、来源快照、目标准备、安全锚点、原子保存和失败回退；一次请求只切换一次。
- [ ] 非当前区域的种植、生产、维护和合同时间由持久领域状态继续推进，返回时只重建表现；首期 NPC 自主跨图能力尚不开放。
- [ ] 旧单地图存档归入 `farm_home`，保持建筑、NPC、托管、小游戏成绩和背包；新区域只初始化一次。切换后恢复当前区域小地图和相机。

验收：玩家投入真实资源解锁西侧路口，进入林地采集后返回庄园，采集物在自己的背包、原建筑与七洞成绩仍在；离开前接受的租赁加工按统一时钟完成并只交付一次。至少覆盖条件不足、重复贡献、重复按 E、入口自动弹回、目标加载失败、保存失败、过渡前后退出恢复、有效存档缺目标场景，以及整个存档损坏的分支。验证锁定地图无法由普通传送或坐标命令绕过。保留场景卸载期间的经济对账和双地图往返截图。

### R3：NPC 跨地图自主行动

任务：

- [ ] 主体位置增加地图归属；为 AI 投影区域内地点、可见入口、通行条件、已知目的地及行程信息，更新两端契约与能力版本。
- [ ] 在原项目执行器中接入入口查询与跨图旅行；区域内移动不能拿另一张地图的同名坐标执行，旧探索定时器不能替代真实入口旅行。
- [ ] NPC 先走到合法入口再出发，未加载区域使用持久旅行记录；到达时继续原项目并按需生成唯一的可见角色。
- [ ] 返回的模型命令校验主体地图、对象身份和相关版本；换图不重置世界 Agent 会话，不丢失其他 NPC 的已授权订单。
- [ ] 将跨图任务追踪导向当前地图的出口；调试面板增加区域选择、在途状态与切换失败记录。

验收：真实 AI 至少完成一次“观察入口条件 → 合法出发 → 林地获取资源 → 返回庄园 → 使用原工坊或交付委托”的计划，并展示玩家未跟随时的持续执行。锁定入口、路况变化、途中保存、迟到模型响应、服务断开和玩家先到/后到均不产生重复 NPC、免费货物或错误地图操作。未做真实 AI 验证时只标记规则通过。

### R4：区域市场与跨图运输

任务：

- [ ] 接入一个独立集镇地图及其通路，复用市场领域逻辑，为库存、供需、岗位/组织所在地增加区域归属；同一居民不因换图多消费一次。
- [ ] 运输复用原项目、合同与资产预留，保存出发地、目的地、运力、费用、到达时间和唯一货物归属；NPC 可自己运输或协商委托。
- [ ] 本地交易检查实际所在地或有效代理/运输授权；跨地图仓库不能直接当作随身背包消费。
- [ ] 临时断路停止新出发、保留永久解锁凭据，处理已在途货物与安全返回；公共组织通过真实预算发布恢复或运输委托。

验收：从庄园买货、付费运输、集镇卖出，两个市场的库存变化、运费和最终收益一致；改价、满仓、道路中断、超期、重复交付和中途读档不复制资产。已有市场回归与跨图长期结算通过后再扩大区域数量。GameEnvAgent 参与部分须另外完成 P7 及真实服务验收。

### 区域扩展的验证入口要求

实施时为每阶段补充正式场景测试与 `docs/validation/regions/Rn.md` 报告，并扩展测试运行器；这些文件和参数当前尚未提供，不能把本计划当成可直接执行的脚本。R2/R3 重点检查 NPC 寻路、Agent trace、模态输入、地图传送、种植、租赁订单、存档迁移、小地图和高尔夫；R4 再加入市场、居民消费、公共预算和运输账目。仅文档变更时检查链接、编号与依赖，不宣称运行期能力已验证。
