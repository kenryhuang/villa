实施文档：[分阶段实施与验收计划（P0～P12）](../plans/2026-09-07-npc-agent-living-world-implementation-plan.md)。本稿描述产品设计，实施任务、依赖、逐阶段可试玩结果和完成门槛以该计划为准。

## 1. 设计定位

玩家经营农庄，同时生活在一个有需求、计划、消息和变化的小社会里。NPC 会自主谋生、提出合作、承接委托、探索世界，也会根据玩家的建议调整自己的计划。玩家可以当生产者、商人、情报交换者、投资者或活动参与者。

核心循环是：**观察世界 → 获得消息 → 判断机会 → 谈成交易或委托 → 投入时间与资源 → 完成行动 → 世界与关系发生变化。**

集市公告板是公开需求的一个入口，对话是协商入口，地图与建筑是执行场所，市场和关系是结果反馈。NPC 也可以从自己的生活需要、见闻、技能兴趣和经营判断发起行动，不必等玩家或系统发任务。任务应从世界状态产生，并把完成结果写回世界。

本设计强调三个体验：

- **自主性**：玩家不参与时，NPC 和背景群体仍会进行有限、可解释的活动。
- **可干预性**：玩家提供原料、资金、设备或消息，就能改变一项计划的走向。
- **可理解性**：玩家能知道谁需要什么、为什么涨价、谁正在工作，以及承诺兑现到哪一步。

日常节奏以轻度经营为主。公告板提供机会，不构成每日必须清空的作业；普通玩家错过委托不会受到惩罚。

### 1.1 本次评审结论

v1 的资产归属、验收、失败处理和世界反馈值得保留。主要问题是：内容围绕任务模板展开，背景社会推迟到后期，而 NPC 为什么主动做事、怎样创造新机会、公共组织如何参与还不够具体。照原阶段顺序实施，容易先得到一个可靠但仍机械的接单系统。

| 优先级 | 发现 | v2 调整 |
|---|---|---|
| 高 | 固定职业目标加固定任务模板，仍可能只是在预设选项中选动作 | 引入持续个人需要、自主提出目标、可组合计划与动态能力发现；模板保留为执行积木 |
| 高 | 背景需求有价格作用，但缺少真实购买力和生活循环 | 先接入少量居民、组织账户、工作、消费与有限产能，再扩大人口 |
| 高 | 缺少 GameEnvAgent 权责边界，容易变成控制全世界的导演 | 将其定义为公共事务协调者，有独立预算；通过订单、激励、公共资源排程影响社会 |
| 高 | 把社会模拟放到公告板之后，无法验证任务是否来自真实社会 | 首个纵向切片同时包含居民需求、NPC 主动项目和公共协调 |
| 中 | 自主性没有验收标准，可能用更多对话和随机行动冒充 | 验证无人干预下的目标生成、因环境变化而改计划、跨角色协作与长期差异 |
| 中 | 群体、具名 NPC、市场压力和订单可能重复表现同一经济活动 | 明确唯一资产所有者、人口提升/降级、需求引用与旧模拟切换规则 |

### 1.2 三种方向与推荐选择

| 方向 | 优点 | 主要代价 | 结论 |
|---|---|---|---|
| AI 世界导演：统一安排剧情、产量和每个人的任务 | 容易控制节奏，容易展示精彩场景 | 个体服从剧本，因果容易被导演覆盖 | 仅借用活动策划能力，不作为社会核心 |
| 分布式居民 + AI 重点角色/组织 + GameEnvAgent 公共协调 | 有真实利益冲突、协作与可追溯经济，计算量可控 | 需要可靠的计划、账户和执行系统 | **推荐作为主方案** |
| 每个居民都持续调用大模型 | 每人都有丰富表达的潜力 | 调用延迟、上下文与行为一致性成本高；人数不等于社会深度 | 后续按实际互动提升部分居民，不作为首期前提 |

这里的自由度定义为：**同一个世界问题，可以由不同主体自发提出不同目标、组合不同手段，并产生可持续的不同后果。** 多写几种任务、让模型随机换台词或给所有人一个大模型，都不能单独满足这个目标。

## 2. 现有基础与待补齐的体验

以下基于本次仓库检查，区分已经存在的能力和本设计新增内容。

| 领域 | 现有基础 | 本设计补齐 |
|---|---|---|
| NPC | 阿禾、老李、学者林，职业、关系、记忆、定时与事件决策 | 持续项目、个人困境、主动委托、更多经营角色 |
| 对话交易 | 报价、接受、拒绝、还价、玩家资产结算与合作协议 | 面向玩家的物品卡、明确市价报价、自然语言生成可确认条款 |
| 探索 | 移动、调查、采样、发现登记和知识状态 | 实际探索地点、私人情报交易、信息时效、可交付的调查成果 |
| 生产 | NPC 自备原料、支付加工费、使用玩家真实建筑队列、成品归租客 | 玩家/NPC/组织统一产权、自主建造、相互收费加工、经营计划与出租政策 |
| 市场 | 库存、供需、价格历史、背景人口需求、Agent 市场压力 | 群体预算与产能、运输、需求来源解释、任务和市场统一需求结算 |
| 环境 | 地形、季节、河湖、钓鱼、高尔夫等 | 天气状态、可应对的事件、群体需求与环境变化联动 |
| 调试 | 请求追踪、决策间隔、环境查询、小地图传送 | 任务/项目生命周期、资产来源去向、事件原因追踪 |

当前 3D 日结调用人口模拟后再结算市场；虽然经济接口有事件因子入口，不能据此视为完整天气和事件系统已经接入。当前职业目标来自固定列表，任意对话目标也尚不能直接成为持续计划。

本次复查还确认：`NpcEconomySystem._apply_population_demand()` 目前把群体配置换算成 `add_external_demand()`，尚未从居民钱包购买并消费；非 Agent 托管 NPC 的 `_produce()` 可按配方直接转换库存，尚无对应建筑时段。`AgentRegistry.buildContext()` 仍按职业筛选目标和工具；探索路由已有 `travel/survey` 等命令，但其中包含定时活动与预置发现映射，不能视为地图任意地点都已具备完整探索执行能力。v2 所述居民生活、自由项目、真实劳动力和 GameEnvAgent 都是待实现能力。

现有交易界面仍有协议 JSON 展示，需要先改成物品、金币、期限和操作按钮。近期租用加工与模型动作冲突问题也说明：执行可靠性和结果反馈应与玩法扩展一起推进。

## 3. 一段目标体验

以下是一段可能发生的故事，不是要求每局固定演出的脚本。

1. 旅店预计两天后有游客到访，在公告板发布早餐采购需求。
2. 老李看到了利润，准备接单，但缺原料与加工时段。
3. 学者林掌握一条消息：山路有积水风险，下一批商队可能延迟。他愿意用调查记录交换绳索。
4. 玩家可以自己承接订单，也可以把消息告诉老李，与他谈加工合作，或继续经营自己的农田。
5. 阿禾根据订单与玩家建议，决定拿两块地试种适合作为后续供货的作物，并要求玩家提供种子。
6. 天气发生变化。提前备货的人按时交付；没有备货的人需要采购替代品、协商延期或放弃。
7. 旅店收到早餐并消耗库存，工坊获得租金，市场相关需求减弱，参与者留下履约记录。

这条链里，交易、情报、任务、生产、目标和天气各自改变玩家的选择。收益不只表现为金币，也包括销路、独家消息、关系与新能力。

## 4. 世界主体与人口规模

### 4.1 人口、组织与公共协调

| 层级 | 建议规模 | 运行方式 | 玩家体验 |
|---|---|---|---|
| 重点 NPC | 先深化现有 3 人，再增加到约 6～8 人；属于居民总数 | AI 提出目标、协商和改计划，规则执行动作 | 可认识、可交流、可长期合作 |
| 普通居民与访客 | 首轮 30～60 人，验证后试 60～120 人 | 持久个体记录，按需要、价格和日程批量决策 | 有收入、消费、职业、偏好和可持续生活 |
| 组织 | 先旅店和公共事务组织，后约 3～5 个 | 独立账户、库存、设施、成员与授权；重要经营决策可由 AI 负责 | 大额采购、就业、合作与活动 |
| 统计群体 | 首批 4～6 类，如农户、游客、工人 | 聚合居民和组织的统计视图，不额外创建一份钱和消费 | 理解需求结构、购买力和价格趋势 |
| GameEnvAgent | 1 个公共协调者 | 低频 AI 提议、规则校验、公共预算执行 | 公共订单、活动与基础设施协调 |

人口数、场上模型数和模型调用数是三个独立参数。首轮附近同时展示约 6～12 个普通居民即可；未展示的人继续按游戏时钟生活。以上是待测规模，不是已有性能结论。

重点 NPC 可以代表一个群体经营，例如老李代表商队、厨师负责旅店采购。他的经济影响由真实业务资金与订单规模支撑。个人钱包和组织钱包分开，不能同时从两处支付同一笔交易。

一名普通居民成为重点 NPC 时，沿用同一个 actor ID、账户、工作、关系和已签承诺，只升级规划与对话方式；降级时保留这些事实，由轻量执行器接续。统计群体只汇总，不能再为其成员额外下单。场景模型只是同一主体的表现，不能产生第二次生产或消费。

### 4.2 角色分工

| 角色 | 主要动机 | 主动行为 | 对玩家的价值 |
|---|---|---|---|
| 阿禾：农夫 | 稳定收入、保留口粮、谨慎试种 | 换种、供货、试种、求助照料 | 原料和种植合作 |
| 老李：商人 | 周转资金、寻找价差、维护客户 | 收购、补货、接单、租用生产 | 销路、原料与行情 |
| 学者林：探险家 | 安全探索、取得证据、研究发现 | 调查、采样、出售消息、筹措补给 | 地点、样本与知识 |
| 厨师：拟新增 | 按时完成餐饮订单 | 采购、代工、研发、预订设备 | 稳定食品需求 |
| 工匠：拟新增 | 获得材料、改善设备 | 制作、维修、承接建设 | 设备维护与环境修复 |
| 旅店经营者：拟新增 | 客流、服务质量、采购成本 | 发布需求、筹办活动、共享来访消息 | 活动与消费需求 |

新角色必须带来不同的决策和交易机会。第一阶段由具名组织发布旅店等需求，不要求提前制作所有 NPC 模型。

角色分工是初始倾向，不是永久行为边界。阿禾可以卖货、学加工或组织互助；老李可以投资种植；学者林也会为生活收入接普通工作。技能、设施访问权、土地与资金决定能执行什么，性格和职业决定更愿意做什么。

## 5. 统一六个概念

| 概念 | 解决的问题 | 例子 |
|---|---|---|
| 需求 Need | 世界为什么需要行动 | 旅店明天缺 12 个面包 |
| 委托 Commission | 谁公开提出可验收、有报酬的工作 | 公告板收购面包 |
| 项目 Project | 一个主体准备怎样持续完成目标 | 老李采购、租磨坊、加工、交货 |
| 交易 Trade | 双方交换哪些现有资产 | 两袋面粉换四个鸡蛋 |
| 合作 Agreement | 多方如何投入并分配成果 | 玩家提供设备，老李提供原料 |
| 事件 WorldEvent | 什么正在改变环境与需求 | 降雨导致道路受阻 |

同一需求可以通过公开市场采购、公告板和私下合作解决；这些渠道共享同一个剩余需求量。项目可以为了完成委托而创建，也可以是 NPC 自己的小试验。单笔交易完成不代表整项合作或任务已经完成。

## 6. 集市公告板

### 6.1 位置与界面

公告板位于正式集市旁，有可点击的 3D 实体，并随集市迁移。靠近可交互；HUD 任务入口可查看已接委托和进度。地图显示任务地点和交付位置，但未知地点只显示任务允许公开的范围。

板面分为「可承接」「我的委托」「共同项目」「我发布的」。公开收购也支持关注，不要求先接单。NPC 正在承接的公开任务显示承接者和已公开进展。

每张卡片展示：发布者、需求原因、目标、剩余数量、报价/奖励、截止时间、交付地点、接单方式、必要条件。只展示玩家做决定需要的信息，不展示内部数据结构。

示例：

> **旅店早餐采购**  
> 游客团明天到达，还需要面包 ×8。  
> 收购价：20 金币/个，剩余报酬已预留。  
> 截止：明天 18:00；交付：集市交货处。  
> 已收 4/12，可分批交付。  
> 操作：交付 / 关注 / 找发布者聊聊

### 6.2 发布节奏与候选选择

每天游戏时间 06:00 汇总公开机会，首轮观察目标为新增 2～6 条；这不是每天强制补满的数量。居民、组织和 NPC 可在自己发现需求时提出委托，校验通过后发布；日更主要进行汇总和过期整理。初始先保留 4～6 种常用条款模板，模板数量不代表必须按模板顺序发生的故事。

使用当前世界需求和模板形成候选，检查：

1. 发布者是否有预算，需求是否仍未满足。
2. 所需商品、配方、设施、地点与活动是否实际存在且可达。
3. 玩家或至少一个允许接单的主体能否在期限内完成。
4. 同一需求是否已有足够公开额度，是否刚重复发布过。
5. 工作量和风险是否与奖励相称。

再按紧迫程度、内容多样性和近期重复率安排展示；玩家能力只影响推荐顺序，不决定社会中哪些真实需求允许存在。玩家暂时无法完成的项目可以标为长期机会，或由 NPC 承接。AI 可以主动决定需求是否外包、选择合作对象、提出采购量和预算内报价；规则检查权限与可执行性，不要求 AI 只能给既定任务改文案。

没有足够真实候选时允许少发。长期需求仍展示原委托，不通过每天换 ID 伪装成新任务。常驻活动可补充选择，但不无限创造奖金。

### 6.3 任务类型与验收

| 类型 | 目标 | 权威完成条件 | 设计要点 |
|---|---|---|---|
| 紧缺采购 | 收集并交付物品 | 接收库存实际增加，承接者资产实际减少 | 可用旧库存或市场采购，支持贸易玩法 |
| 加工生产 | 使用设施完成指定产品 | 指定生产订单完成，并交付对应数量 | 绑定订单与可交付额度，避免用旧库存冒充生产 |
| 地点调查 | 到达区域并获得调查成果 | 指定区域到访、调查行为与报告状态满足 | 仅经过或在对话中声称完成不算 |
| 稀缺品搜寻 | 取得并交付样本 | 真实物品交付，或满足明确的采集来源要求 | 文案提前说明是否允许购买样本 |
| 活动参与 | 参加钓鱼、高尔夫等 | 活动系统提交的合法完成记录 | 区分参与、完成与成绩挑战 |
| 应急支援 | 修复路线、筹集补给 | 贡献达到阈值，环境阶段实际推进 | 多主体协作，世界反馈明显 |

采购和生产任务必须明确区别。代工任务可由发布者预付原料，原料进入专用订单托管，只能用于该委托；自备原料任务则明确说明由承接者承担采购成本。

调查只需交报告时，已有报告是否可用由任务条款定义；要求接单后复查时必须有新的调查记录。活动成绩通过唯一比赛记录验收，退出重开不会重复领奖。首期高尔夫任务只开放给玩家，直到 NPC 具备真实比赛执行能力。

### 6.4 承接方式

- **独家委托**：接受后锁定承接者、报酬和交付期限。NPC 不能抢走玩家已接受的份额。
- **公开收购**：多人交付，剩余额度实时更新。不接单可直接交货；也可短时预订一部分额度，预订占用承接容量，到期释放，防止囤占。
- **共同项目**：按贡献推进阶段，记录每个主体的实际投入。可有按件报酬和阶段奖励，但分别预留预算。

普通任务初始允许每个主体同时承接 3 项，包括公开收购的有效预订。关注不占名额。NPC 以正常决策节奏接单，不在公告刷新同一瞬间抢空所有内容。

### 6.5 生命周期、交付与终止

委托状态：`draft → open → fulfilled / expired / cancelled`。接单记录独立管理：`active → ready → completed / failed / abandoned`。一项公开收购可以同时有多个接单记录；独家委托只允许一个有效记录。

交付时重新核验主体、期限、剩余额度、物品所有权、任务资格和预留资金，原子完成扣物、入库、减额度和付款。交付操作有唯一编号，网络重试、重复点击和读档重放都不能重复支付。

若所选交付数量超过剩余额度，返回新报价和最大可交数量，请玩家确认；不擅自扣除一部分物品。NPC 获得同样的确定性反馈后重新决定。

普通公开任务到期即结束，未接单者没有惩罚。接受独家委托后主动放弃影响履约记录；是否存在押金必须在接单前明示。首期不引入强制债务或永久性惩罚。

任务开始后发布者不能单方面降低奖励。不可抗力可以触发规则化延期或取消；未使用的资金与托管原料返还原所有者，已合法完成的分批交付不追回，未交付的自有产品仍归承接者。已开工的托管加工订单应完成后返还成果给出资方，取消界面预先说明。

### 6.6 玩家也能发布委托

玩家可以通过公告板选择模板，或在对话中说“帮我收四份蜂蜜，预算最多 80”。系统形成待确认的委托卡，玩家确认后冻结奖励预算并公开发布。

初期支持采购和调查；禁止发布没有对应执行与验收能力的自由文本任务。对任务的聊天描述不会自动扣款、发布或修改条款。

玩家可通过委托组织分工，但不能替 NPC 决定接受。NPC 会比较报酬、能力、已有承诺和风险，也可能提出更高价格或更长交期。

## 7. 对话交易、行为协商与临时任务

### 7.1 即时交易

支持物物交换、金币购买、出售给 NPC、按市价生成报价。市价作为参考；最终价格受实际数量、当前报价、NPC 保留库存和关系影响。买卖双向使用对应报价，界面明确展示参考价、成交价和有效期。

对话提出交易后生成物品卡，列出双方支付和获得的资产。玩家点击确认当前版本后才成交。还价创建新版本并使旧版本失效；价格或库存变化导致旧报价失效时，返回新的明确条款。

NPC 只能交易自己的可用资产或有授权的组织资产。未交付、已预留和正在加工的物品不能假装成现货。玩家只向 NPC 展示主动提供的交易资产，不公开完整背包和钱包。

### 7.2 合作与长期供货

合作协议包含参与者、投入、交付节点、期限、产出归属、分成和退出条件。常用模板：原料换加工、设备换分成、探索补给换报告、定量供货。

“你提供种子，我种两块地”可以生成合作提案；接受后才创建对应项目与资源预留。改交期、加预算、改分成都要重新确认涉及自己的条款。

长期供货先做固定批次和明确周期，暂不开放无限期自动扣款。允许从合作卡查看欠缺投入、当前阶段和下一次交付。

### 7.3 履约比聊天更重要

请求模型时展示“思考中”，接受委托后展示“已接单”，原料支付成功后才展示“已付款”。动作失败时应说明失败原因和下一步；自然语言里的承诺不能写成成功事实。

交易、生产、委托三个状态分别显示。例如“加工完成，尚未交货”与“委托已完成”必须明确区分。

### 7.4 对话可以改变哪些事情

对话是通向世界行动的自然语言入口。系统结合上下文识别一句话是在询问、提供消息、提出建议、议价还是请求承诺；同一句话可以包含多个意图，但不能把闲聊或假设当作已经接受的任务。

| 对话例子 | 可能形成的变化 | 生效条件 |
|---|---|---|
| “我用两袋面粉换你的四个鸡蛋。” | 即时交易或还价提案 | 双方接受同一版本，原子结算真实资产 |
| “西边的工坊便宜些，你可以去看看。” | 增加线索，查询后调整路线或生产选择 | NPC 自己判断可信度、时间与收益；消息不是自动成立的事实 |
| “这几天先别扩大种植，留点粮食。” | 修改有限时间内的储备策略或当前项目 | NPC 接受建议后保存范围和期限，不永久重写性格 |
| “你可以攒钱开一家食品铺。” | 提出长期志向，拆成筹资、学习和设备等里程碑 | NPC 愿意采纳，且存在可执行的近期步骤；不立即生成店铺 |
| “先帮我把这批面包送到旅店，再做你的事。” | 插入临时配送项目 | NPC 有配送能力、时间和合法物品访问权，接受明确交付条款 |
| “刚才那件事不做了，改成调查北岸。” | 取消/修改提案，或协商变更已接受项目 | 对照具体项目和版本处理；已签合同走取消或改约条款 |

玩家给建议时，不必每次弹出确认框；NPC 使用自己的空闲时间和未承诺资源，可以自主采纳并告知。涉及玩家付款、交出物品、授权建筑或签订合同，才生成清楚的条款卡，由玩家确认。NPC 可以拒绝、还价、附加条件、晚点再做或推荐另一个人，不能把“对话改变行为”实现成玩家随意控制所有角色。

目标修改记录来源、NPC 接受的具体内容、影响范围、持续时间和原目标的处理方式。仅增加一条聊天记忆不算改变目标；需要反映在后续计划、行为及恢复逻辑中。模糊的“先帮我办一下”应结合最近有效提案解释；仍缺数量、对象或目的地时，先询问必要信息，不凭空签约。

### 7.5 临时任务怎样插入与恢复

临时任务成为独立的 Project，可为私人请求，无需先公开到公告板；有报酬或交付责任时引用对应协议。它记录来源对话、请求者、接受条件、截止时间、资源占用、被暂停项目以及完成/失败后的恢复策略。

NPC 在接受前比较新任务与既有承诺的时间、成本、关系和风险，选择“现在做 / 当前步骤后做 / 排队 / 还价 / 拒绝”。玩家说“很急”是请求信息，不自动获得最高优先级；受雇且处于约定班次的 NPC 按已签工作范围响应，也仍受执行能力和其他合同约束。

插入流程：

1. 识别请求，核对对象、时限、能力和资源，形成提案；只缺关键信息时继续询问。
2. NPC 接受，涉及玩家资产的条款完成确认后，为临时任务建立有效记录和必要预留。
3. 在动作允许的中断点暂停原项目，保存当前位置、步骤、在途命令与恢复条件。等待机器加工通常可以离开，已付款入队的加工继续；已提交交易不回滚，不能重复提交原料。
4. 执行临时任务并记录真实结果。失败时可改约、放弃或返回，不无限重试。
5. 重新核对原项目的期限、原料、设备和已完成步骤，再恢复、调整或协商结束。不能直接重放暂停前最后一条命令。

首期建议每人最多一个正在执行的临时插入任务，另外保留少量排队请求，并计入总承接容量。新的请求不会无限压栈；若反复插单会使原承诺逾期，NPC 应拒绝或先请求原合同方同意延期。`suspended` 表示为另一个任务主动暂停，`blocked` 表示缺条件无法推进，两者分开显示和恢复。

示例：老李已经支付租金，工坊正在加工。他接受“顺路给旅店送现成面包”的请求，机器继续运行。配送结束后，他发现加工已完成，就去处理成品；如果配送使原订单临期，他应在接单时说明冲突并议价或拒绝，而不是做完之后忘掉原订单。

### 7.6 对话结束之后仍然有效

对话中展示“提出方案”“已接受，等当前步骤结束”“执行中”“遇到阻碍”“已完成”等事实状态，并提供查看条款、询问进度、修改或取消的入口。先发“我正在考虑”可以，只有计划或交易提交成功后才能显示“已接单”或“已成交”。

关闭聊天窗口只停止当前未完成的对话生成，不取消已接受项目、已付款交易或生产订单。存读档保留临时任务与恢复关系；重新聊天时可以明确询问“刚才送货的事情怎么样了”。同一对话消息重发或旧请求延迟返回，不能再创建一份任务或覆盖较新的计划版本。

对话期间沿用游戏时间暂停：可以协商、确认提案和执行玩家明确确认的即时界面交易，但移动、生产计时与消费不推进。接受的行动计划等恢复游戏后执行。后台 AI 的自主动作暂存，恢复后重新校验；不能因为聊天暂停而让 NPC 在后台先跑完配送。

## 8. 私人情报与探索

情报记录包含事实标识、持有人、来源、发现时间、有效范围、可信级别、失效条件和公开程度。分为已验证事实、现场观察、传闻、预测。可信度来自证据，模型不能自行把传闻升级为事实。

可交易内容包括真实资源点、季节性资源窗口、路况、可验证的订单消息和调查报告。购买后解锁地图标记、调查线索或已确认事实，形成可玩的能力。

第一阶段出售“向买方披露”的服务，不承诺唯一知情权。买方已知道的同一内容不可重复收费；已经公开的事实不可包装成独家出售。付款和知识授权同时结算。

未成交时只给足够判断价值的概要，例如“北侧山谷有一处未公开矿点”，隐藏坐标等收费内容。若 NPC 已在免费对话中披露可用内容，系统应同步知识状态，不能再次收费。

对未知资源地点的调查任务只公开搜索区域；采样成功可以解锁后续任务、配方研究或公共发现。预测可以落空，已验证地点是否过期由世界变化决定，不能为了剧情临时撤销玩家已获得的可靠证据。

## 9. NPC 的持续目标与自主尝试

### 9.1 三层目标

1. **长期偏好**：角色性格、口粮储备、生活方式和关系倾向。
2. **当前项目**：交付某笔订单、准备一次探索、试种一种作物。
3. **下一步动作**：买原料、走到建筑、提交加工、交货。

玩家对话通常影响第二层，也能通过长期互动逐步改变第一层。一次随口建议不会永久改写 NPC 性格。

项目包含负责人、目标类型、绑定委托/协议、预算与风险上限、资源预留、截止时间、步骤、阻碍原因、重试条件和结果。推荐状态为 `proposed / active / suspended / blocked / completed / failed / abandoned`。临时插入任务的恢复引用与中断规则见第 7.5 节。

### 9.2 一项可执行的小试验

玩家建议阿禾尝试耐寒作物。阿禾可以拒绝，也可以提出“先试两块地，你提供种子，收成分三成”。达成协议后，系统创建种植和交付步骤。

结果由实际生长、投入、产量和成交数据评估。NPC 可以记住“这次收益较低”，但不能把一轮试验当作普遍规律。后续尝试应限制投入，保留口粮和已承诺资源。

### 9.3 执行与调整

模型在接单、重要事件、步骤完成、资源不足或玩家对话时决定计划；可重复且条件明确的步骤由游戏执行，不必每次移动、等队列或交一件物品都请求模型。

连续失败的相同动作进入阻塞状态。例如队列满了等待空位事件，原料不足等待补货或重新协商。不能只是提高 `max_fee` 后无限重复原命令。

每个 NPC 只优先执行一个主项目，允许少量后台等待项目。已有承诺、保留资源和剩余时间优先于新的利润机会。

### 9.4 让目标来自角色的生活

每个主体持有持续需要与偏好：基本生活储备、可支配时间、收入稳定性、社交联系、好奇心和个人志向。需要随实际消费、休息、收入和社会事实变化；性格决定取舍，例如阿禾重视稳定，老李愿意承担有限库存风险。初期先做生活储备、时间、收入目标和一种个人兴趣，不一次加入全部心理数值。

机会来自自己的观察、别人提供的信息、价格和设施变化、未完成承诺、公开需求及私人项目。AI 可以提出规则未预先列成任务的新组合，例如“赚够一笔学习预算，同时保留两天口粮”“利用闲置工坊为旅店试供两批早餐”。这些目标不必经过玩家同意；使用 NPC 自己未承诺的资源可以直接决定，涉及他人资产和承诺则需要相应主体接受。

持续目标同时保存自然语言意图和可验证里程碑。里程碑使用有限的事实条件组合，例如可用金币达到阈值、交付指定订单、取得报告、完成培训；好奇或友情等开放志向用周期复盘和具体行动记录表达，不让模型一句“我已经成功”结束项目。角色允许拒绝利润更高但不符合偏好的机会，也允许休息、犹豫和小额失败；不是每个人都要最大化金币。

### 9.5 动作积木有限，计划组合开放

建立统一能力目录，列出动作的前置条件、投入、耗时、占用资源、可产生的证据以及执行器。AI 根据当前技能、资产、设施授权和已知对象查询目录，自行组合计划。职业提供默认专长和行为偏好；能力授权由游戏验证，模型不能自授权限。

| 决策空间 | 允许 NPC 自己决定的事项 | 必须接入的真实变化 |
|---|---|---|
| 生计与时间 | 留多少口粮、做什么工作、休息还是赶单 | 消费、班次、收入和时间占用 |
| 经营 | 选商品、采购量、报价、停产或换产品 | 钱包、库存、配方、订单与成交 |
| 分工 | 找谁供货、雇人送货、把哪个步骤外包 | 对方接受的合同、报酬与交付证据 |
| 投资与学习 | 为工具、技能或扩产存钱，提出共同投资 | 真实费用、学习时间、设备或能力变化 |
| 社会与兴趣 | 拜访、帮助、邀约、组织小活动 | 双方日程、实际参与与关系事件 |
| 探索与实验 | 调查哪里、验证哪个假设、试种多少 | 可达地点、资源投入、观测与结果 |

未有执行器的能力标为未开放，只能讨论或提交愿望，不能接受收费委托。首期不让 AI 运行任意代码、创建任意配方或仅靠叙述生成建筑；新的玩法维度仍需开发者添加执行积木。自由主要体现在目标、对象、数量、时机、合作者和步骤组合，而不是虚构尚不存在的物理能力。

### 9.6 持久计划、外包与有限理性

计划使用带依赖的步骤图，每一步记录输入、等待事件、执行结果和替代选择。例如原料采购可以与设备询价并行，但开工必须等两者满足。先预留已签约承诺和最近可执行步骤所需资源；未谈妥的整张计划不能长期锁住全社会的库存和产能。预订有截止时间，项目之间禁止循环等待和重复占用同一劳动时段。

NPC 可向其他 NPC 提出分包或合作，对方独立决策。原承接者继续对总合同负责，付款与交付链由合同确定；收到一个邀约不立即递归唤醒全体角色，每轮只联系少量候选并等待实际答复。

普通重复动作按已批准计划执行；关键分叉才请求 AI。若玩家把租金提高，老李可以缩小试产、找别的设备、与玩家议价或退出项目。固定条件下重复请求模型随机换方案不算自主调整。

NPC 对价格、需求和他人意图的认识可以滞后或错误。每次预测保存当时依据和时间，事后与实际成本、交付和收益对照；成功和失败改变后续偏好与风险估计。不同角色只见自己的信息，同一职业也不能共享所有私人记忆，否则会集体追逐同一机会。

### 9.7 三个自主性验收场景

1. **没有任务也会谋生**：公开板没有面包任务，老李观察到食品需求与闲置设备，自己提出小额试产，询价、开工、销售并评估利润；允许最终判断不值得做。
2. **同一问题存在不同回应**：粮价上涨时，阿禾选择稳住口粮再供货，老李寻找替代原料，学者林接调查工作筹措补给；选择有各自信息和偏好依据，不要求每次演出固定分工。
3. **玩家建议改变未来行动**：玩家提议合作种植，NPC 接受或还价后形成持久项目；数日后能观察到实际土地、产出和关系变化，或可解释的中止，而不是只得到一句同意。

## 10. 统一建筑产权、自主建造与收费加工

### 10.1 玩家与 NPC 使用同一套生产建筑

生产建筑可以属于玩家、NPC 或组织。NPC 可以付费使用玩家的建筑，也可以在筹齐建筑材料后自行建造；建成后，其他 NPC 和玩家同样可以付加工费使用。主体不同不应产生另一套虚拟配方、免费生产或隐藏产能。

| 使用者 → 建筑所有者 | 加工费去向 | 成品归属 |
|---|---|---|
| NPC → 玩家 | 使用者付款，玩家收款 | 使用者 |
| 玩家 → NPC | 玩家付款，NPC 收款 | 玩家 |
| NPC 甲 → NPC 乙 | 甲付款，乙收款 | 甲 |
| 玩家/NPC → 组织 | 使用者付款，组织业务账户收款 | 使用者或已签订单指定的所有者 |
| 所有者自用 | 不给自己转一笔虚假加工费 | 所有者；原料、工时和维护仍有成本 |

对外服务统一称“加工费”，按配方和批次数量报价。建筑所有者提供设备与约定服务，通常不拥有客户投入的原料及产出。共同经营、来料代工等特殊归属通过明确协议覆盖，不能只因产品位于自己的建筑里就拿走。

### 10.2 NPC 怎样自己建造

建造是可由 NPC 自己发起的持续项目：比较长期租用与自建成本 → 选择已有建筑类型和可用地点 → 通过采集、购买、交换或合作筹齐材料 → 提交施工 → 等待真实建造完成 → 自用或开放加工。

按本次需求，**筹齐所选建筑材料清单是 NPC 开工的核心资源条件**。不额外要求玩家批准、不绑定玩家等级，也不为 NPC 增设强制建筑许可证、技能升级或一笔凭空增加的建造金币费。施工所需时间沿用建筑规则；若 NPC 自愿雇工、购买材料或租别人土地，才支付相应交易费用。筹得起材料不代表必须建，NPC 仍可因需求不足选择继续租用。

地点必须合法可用，满足建筑占地、地形和通行约束，不能占用玩家农田、他人建筑、道路、钓位或球场。首期在地图上提供明确的公共可申请建造地块，以低成本实现土地权限；默认可用空地不收费，使用玩家私有土地必须另行协商。地块申请只做规则校验和有限时长预留，不需要玩家逐项审批。

开工时原子检查地块仍可用、材料真实可支配、建筑执行器存在，然后扣除建造者材料、登记稳定实例 ID/所有者并进入施工状态。重复请求和读档不能重复扣料或生成两座建筑。施工中不对外接加工单，取消施工沿用明确的阶段材料退还规则，不能取消后保留建筑又拿回全部材料。

NPC 建筑必须出现在正式 3D 地图，具有碰撞、入口、施工表现、配方、队列和维护状态。复用原建筑系统及模型，不只在 NPC 注册表里添加一个名字或用定时器宣布建成。

### 10.3 所有者经营政策与自主定价

所有者可决定是否对外开放、允许的配方、每批加工费、自用预留容量以及是否接受某项协议。对外开放的普通订单，只要符合公布条款即可入队，不必每次等待所有者聊天确认；议价、长期供货和设备包用才进入协商。已有订单锁定原条款，涨价、停接新单或调整容量不挤掉已接受客户。

NPC 根据周边价格、设备利用率、维护成本、关系和自己的生产需要调整未来报价，允许打折或竞争，不保证永远盈利。界面同时展示配方报价、预计等待、地点、设施状态与所有者，供玩家和 NPC 比较。当前按站点生成的固定费表可作为初始建议价，逐步改为每座建筑持有自己的费表与版本。

所有者自用与他人加工共享真实队列；自用预留只影响尚未承诺的容量。首期沿用现有队列，后续再增加预约时段，避免两套产能规则冲突。NPC 出远门、换工作或不在场，不会让已入队的自动加工停止；配方确实需要人工时，则由真实日程或雇工提供劳动。

### 10.4 订单、收款与维护

每笔订单记录建筑实例、所有者、付费者、原料所有者、成品接收者、配方批次、实际加工费、报价版本、输入预留和执行状态，资金不能固定转入玩家钱包。自备原料订单接受只代表入队，尚不代表成品或委托交付完成。

新订单建议在接受时扣取并托管加工费，实际开工时转给建筑所有者；未开工且符合取消条款时，可完整退回加工费与未使用原料。已开工订单按约定取消和在制品规则处理。现有已经预付到玩家钱包的订单要标记收款状态，迁移时不能再次扣款或重复发放费用。

建筑所有者承担约定维护费用与维修责任；维护不足暂停加工并显示预计影响，不凭空补出成品。恢复后继续原订单。客户原料、在制品和成品与建筑自有库存分开记账。有人尚有在制品、待退费用或未处理成品时，不允许直接拆除或移除建筑。首期不做建筑产权转卖，避免带着未结清订单更换收款人。

### 10.5 经营与社会反馈

支持自备原料付费加工、来料代工委托以及协议约定的共同经营。首期每座建筑只有一个明确所有者，多方投资可以通过合作协议约定收益分配；复杂股份与产权交易后续再做。

例子：老李最初租玩家风车磨面粉。持续订单让他认为自建更划算，于是积攒木料和石料，在合法空地建风车，给厨师和阿禾提供收费加工。玩家也能去使用老李的风车，或降低自己的费率、保留自用容量、转做食品加工。新增供给通过真实设施与队列改变等待时间和竞争格局，不由系统直接下调所有加工费。

GameEnvAgent 可以观察产能短缺、发布公共采购、招租公共地块或提供有预算的建设合作，但不能替私人决定必须建什么，也不能免费给偏爱的 NPC 生成建筑。

### 10.6 玩家可见信息与当前接入缺口

建筑面板展示所有者、开放状态、配方费表、预计等待、关联订单和物品归属。非所有者可以提交加工、取回自己的成品和查看公开信息，只有所有者或授权经营者能调价、维护决策和拆除。NPC 移动、等待与工作图标对应真实订单，动画卸载不重复结算。

P1 实现更新（2026-09-08）：`ProductionSystem.start_rented_recipe()` 已通过原资产适配与生产队列支持玩家 → NPC、NPC → 玩家、NPC → NPC 和所有者自用，收款方由建筑产权决定，费用排队托管、开工结算；详见 [P1 验收报告](../validation/living-world/P1.md)。原 Agent 的 `build` 命令使用活动/注册表路径，也尚未等同于正式 3D 中扣真实材料、占地施工和经营产权。实现时应改造原建造、生产与账户接入，补齐主体参数、所有权、费表、权限和迁移；不另造一套 NPC 专用建筑与经济系统。

## 11. 背景群体与价格趋势

### 11.1 群体状态

首批统计群体建议为本地居民、周边农户、旅店游客、施工队和外地商队。居民或组织维护实际钱包、库存、目标储备、消费周期、生产能力、运输状态及公开需求；群体视图汇总这些数据。组织有独立业务资产，统计分类没有额外钱包。

资金来源明确：游客带入外来消费，商队有外部贸易资金，居民通过已完成的工作、售货或有来源的补助取得收入；初始资金按开局规则分配一次。消费会消耗物品，消费付款和本地租费只是主体之间转账，不是本地货币的消失。出口、进口、外来补助和离境携款是与外部经济的边界流量，各有来源、上限与记录，AI 不能随意创造钱包余额。

普通居民按游戏时间批量模拟，但结算仍落到唯一账户和库存；访问市场、出席活动等场景表现不再扣第二次物资。具名 NPC 代表组织下单时使用组织授权及组织预算，其个人生活支出使用个人资产。

### 11.2 从变化到价格

基本传导是：

```text
天气 / 客流 / 运输 / 生产变化
              ↓
     库存、产能、消费和采购需求
              ↓
 公共市场成交 / 公告板交付 / 私下合作
              ↓
     剩余供需、库存与成交信号
              ↓
       平滑价格调整与新机会
```

同一需求拥有来源标识和未满足数量。公告板交付旅店 8 个面包后，旅店下一次采购减少 8 个；这些面包归旅店库存，不能同时计入公共市场库存。私下成交可以留下交易信号，但不额外制造同量实物供需。

有效承接或预订的数量从其他采购渠道的可用需求中扣除。其他渠道只能满足未承诺部分，不能通过自动补货取消玩家已锁定的份额与报酬。发布者确实需要撤销已签需求时，走明确的取消与补偿条款。

现有直接价格偏移和事件因子需要按来源审计。同一场暴雨如果已经通过减产降低供给，不能再无依据叠加一份同量“暴雨涨价”。未成交意向和真实成交分开计算，防止反复挂单、撤单影响价格。

持续高价可以吸引补货、替代消费和扩产，反应有运输和生产延迟。低价可能使生产者减产或把原料用于加工。价格仍保留平滑和范围约束，具体强度通过模拟调参。

### 11.3 市场解释与影响范围

市场界面为重要变化显示主要原因，例如“商队延误，面粉补货减少”“旅店已收齐早餐，采购需求下降”。公告板显示同源需求，避免两处描述冲突。

先强化单一本地市场。玩家和重点 NPC 应能影响特定商品的一段供需，但一次小交易不应引发整个市场震荡。第二阶段再考虑区域价差、运输成本和外地市场，不在首期引入多个交易所。

### 11.4 最小社会循环：工作 → 收入 → 消费 → 新需求

| 环节 | 首期规则 | 可产生的选择 |
|---|---|---|
| 生活 | 每日消费少量食物，保留储备，休闲有可选预算 | 购买便宜替代品、减少非必需消费、寻求帮助 |
| 工作 | 居民接受有薪班次或计件工作，雇主预留工资 | 比较报酬、路程、技能与既有安排 |
| 生产 | 原料、设施、时间与需要的劳动共同形成产出 | 换配方、雇工、租设备、延后生产 |
| 流通 | 搬运或运输订单占用时间和运力 | 本地采购或等待外地补货 |
| 消费反馈 | 买得起且买得到才成交，交付后才入库 | 短缺转成需求，没钱转成收入/救助问题 |

不是所有生产都必须有人全程站岗。按配方定义装料、维护或取货所需工时，机器自动加工期间可以去做别的事；同一个人不能在两个需要持续劳动的班次中同时工作。生产等待、旅行、社交和休息都进入个人日程，防止时间没有成本。

先提供可模拟的旅店、商队与公共岗位，给社会必要的收入来源。若暂时没有对应可交互建筑，可明确表现为场外雇主或外地供应商；其资金、履约时间、产能和运输额度照样有限，不能冒称使用了玩家的某座建筑。公共救助有预算、资格与周期上限，不靠每天重置居民钱包维持表面繁荣。

基础需求可按“饱腹份额”等类别映射到已有商品：昂贵面包可由较便宜的食物部分替代，奢侈消费优先减少。首期不做完整营养学、出生死亡和复杂家庭继承；生活压力先表现为可恢复的储备、满意度与工作选择变化。

### 11.5 生产与货币的边界

保留现有市场报价与事务接口，逐步给市场收付补上明确的对手账户。若首期公共市场仍代表外地做市商，就记录其规则授信额度、结算流量与补货限制，作为外部经济边界；不能宣称所有本地交易已完全实现封闭货币守恒。随后可将其演进为独立商户或组织资金池。

验证以下平衡关系，而不是要求物品或全世界货币永远不变：

```text
本地期末金币 = 期初金币 + 记录的外部净流入
某商品期末数量 = 期初数量 + 生产 + 进口 - 配方投入 - 消费 - 出口 - 损耗
可承诺产能 = 有效设施时段/订单容量 - 已有占用 - 自用预留 - 维护不可用量
```

物品在生产、库存、运输和托管之间移动时总量不变。合法生产、食物消费和损耗可以改变数量，但必须有原因。NPC 可以失败、亏损和退出某门生意，市场也可以暂时低迷；GameEnvAgent 的目标不包括每天把所有人恢复到盈利。

### 11.6 迁移现有背景模拟

按明确的经济来源切换，禁止新旧模型同时记账：某群体改为真实居民采购后，关闭它原来的 `_apply_population_demand()` 注入；某 NPC 或组织改用真实生产订单后，关闭对应 `_produce()` 快捷产出；同一项私下交易、市场成交与 Agent 压力快照保留一个权威来源，其他仅用于展示或有明确定义的统计。

AI 不直接写 `price_bias_bps` 或临时商品涨价系数。迁移期若保留外部宏观因子，需要说明它代表哪项尚未显式模拟的外部条件，并且不能与已经落实为库存、运输或产出的同一原因叠加。

调整人口规模时同步校准可用土地、生产能力、工资与外贸额度；不能只把需求乘十。用商品周转、可买得起的消费、岗位空缺和设备利用率衡量社会规模，保留玩家通过专精少数商品影响本地市场的空间。

## 12. GameEnvAgent、公共事务与环境变化

### 12.1 两类变化

- **连续状态**：温度、降水、土壤湿度、季节，影响生长、资源出现与工作效率。
- **有阶段事件**：道路受阻、节庆、游客团、丰收、建筑故障等，有开始、影响、恢复和结束条件。

天气结果由世界模拟决定，使用可保存的随机状态；模型根据可见预报和现场事实解释、建议和应对。读档不会为了重抽天气重新生成同一事件。

| 情境 | 提前可见线索 | 实际影响 | 可玩的应对 |
|---|---|---|---|
| 连续降雨 | 预报、河水上涨 | 指定作物受涝、部分野生资源增加 | 排水、提前采收、调查新资源 |
| 热浪 | 温度与湿度变化 | 耗水提高、部分作物减产 | 储水、换种、调整供货 |
| 道路受阻 | 探索报告或运输通知 | 商队延迟、进口商品不足 | 修路委托、替代材料、协商交期 |
| 节庆与游客 | 提前发布活动日程 | 食品与装饰需求增加 | 加工、摆货、参加比赛 |
| 大丰收 | 周边产量消息 | 原料供应增加 | 加工储存、签外销订单 |

初期天气集中作用于少量明确对象。例如先验证降雨对作物、鱼类和运输的影响，再扩展复杂水文。道路事件也应有实际路线和状态变化；若首期只影响外地运输，文案明确说外地道路，不在当前可走的桥上虚构封锁。

### 12.2 事件节奏与公平性

大多数负面事件提供预警和至少一种缓解方式，首期限制同时出现的主要事件数量。玩家已接单的不可抗力延期规则在接单时可见，并对玩家与 NPC 一致执行。

活动奖励来自组织者预算，修路效果来自真实贡献。完成共同项目可以缩短阻断时间、恢复运力或解锁通行。玩家不参与时，NPC 和群体也可能缓慢解决问题，或事件在自然周期后结束。

天气与价格只按游戏内时间演化。首期不在退出游戏后继续扣资源、推进合同或计算灾害；暂停对话时保持当前暂停语义。

### 12.3 GameEnvAgent 的定位

推荐把 `GameEnvAgent` 定义为“世界公共事务协调者”，玩家可以把其行为理解为镇务委员会或公共公告。它使用社会的聚合状态制定公共计划，拥有组织者权限；天气、经济结算、NPC 私人决策依然由各自系统负责。它不是所有 NPC 的上级，也不是可以直接修改任意状态的游戏管理员。

```text
规则模拟：时间、天气、库存、资金、生产、消费、运输与事实事件
       ↓ 授权摘要                         ↑ 已校验的订单/政策/活动
GameEnvAgent：判断公共问题 → 比较干预或不干预 → 提出公共计划
       ↓ 公告、采购、补贴、邀请、公共资源排程
NPC / 组织：基于自己的利益决定响应、还价、另做计划或拒绝
       ↓ 执行结果、真实需求与新的阻碍
规则模拟与公共效果复盘
```

AI 可以既规划经济供给又组织生活活动，但用不同的目标、预算分项和冷却时间管理。先是同一个服务中的一个独立主体，不必再建一个服务或全新记忆系统。以后公共建设、活动和贸易业务大到需要拆分时，再分为组织代理；不要首期就让多个世界导演互相发布指令。

### 12.4 读取范围与操作权限

GameEnvAgent 可读取食品可用天数、实际消费满足率、失业/缺工、公共预算、库存趋势、公开订单、设施利用率、运输状况、季节预报、活动日程和近期措施效果。统计以人口组或组织的授权数据聚合；不读取玩家完整背包、私人聊天、NPC 秘密坐标或未来天气随机结果。调试面板可以有开发者全景视图，不能把该视图直接当成 AI 上下文。

| 能力 | 可以自主执行的范围 | 边界 |
|---|---|---|
| 公共采购与系统任务 | 用公共预算发布修路、采购、调查与公共服务委托 | 与普通委托共用托管和验收，不另造无限奖励任务 |
| 调配公共生产 | 在公共拥有或已获经营授权的设施中调配原料、队列和劳动 | 玩家建筑与私人设施必须租用或签约，不能强占队列 |
| 引导扩产 | 发布限量收购承诺、培训名额、已预算补贴或设备招租 | NPC 自己决定是否投入；补贴绑定真实结果，不能反复领同一笔 |
| 公共资源排程 | 预约公共场地、分配公共维修资金、安排已签公共岗位 | 已有预约与合同优先；有限场地、人数和工资 |
| 组织活动 | 选择活动主题、时间、地点、供应订单、票价/报名费与赞助方案 | 使用已开放的钓鱼/高尔夫等执行能力，参与者自由报名 |
| 外部协作 | 按外地供应商目录提出运输、救助或访问邀请 | 受外部预算、运力、到达时间和邀请接受结果约束 |
| 调整公共政策 | 修改自己管理的新合同费率、补贴配额或公共储备目标 | 只在预设范围内，对未来生效；不暗改玩家私有租金或历史合同 |
| 暂不行动 | 观察市场自行补货，等待已发布措施见效 | 明确等待什么证据，不把“必须有新任务”当目标 |

它不能直接设定市价、生成库存、重置钱包、改 NPC 性格或私人计划、给玩家强行接单，也不能通过触发灾害制造需要救援的剧情。自然风险由模拟产生，活动由组织行为产生，二者拥有不同的来源记录。

### 12.5 公共目标、预算与决策循环

目标采用优先顺序：履行已承诺公共责任 → 减轻基本生活短缺 → 维护可用公共设施与通行 → 提供就业/经营机会 → 在余裕内丰富生活。展示各项指标和取舍，不压成一个“繁荣分数”让 AI 为刷分反复花钱。娱乐不自动优先于粮食保障，也不要求所有指标同时最优。

公共账户的来源只允许开局一次性拨款、规则确定的外部周期预算、实际收到的服务费/票款、被接受的赞助或捐款；首期不加入自动向玩家征税。尚未卖出的门票和预计游客消费不能支付当前委托；必须先有可用资金或已经确认的赞助。预算按活动、基本保障、建设等用途分项，跨项调整受规则限制，支出与剩余承诺可公开查看。

一次决策循环：

1. 读取带日期的公共摘要，找出趋势、成因和正在执行的措施。
2. 提出少量方案，包含“不干预”；说明目标、目标群体、替代方案与判断依据。
3. 给每个方案写出预算上限、资源需求、依赖、预期影响、最早见效时间、期限和退出条件。
4. 规则检查资金、权限、场地、执行器及已有措施冲突；合法方案才创建公共计划、订单和预留。
5. NPC、组织与玩家独立响应，结果通过真实执行反馈。
6. 到观察窗口再比较预测与实际效果，继续、调整未来额度或结束；不撤回已签承诺。

先建议每天一次计划复盘，关键短缺或公共项目阻塞可额外唤醒；每游戏日额外唤醒初始上限 2 次，事件合并。措施有可配置幅度上限、滞后观察期和冷却；“短缺触发”与“恢复退出”使用不同阈值，避免价格一涨一跌就反复开关补贴。阈值按基础商品与人口规模试算，不由模型临时修改。

### 12.6 从供给协调到活动组织的例子

**早餐短缺**：旅店有游客预约，却缺加工产能。GameEnvAgent 先查询已在途供货，判断是否是短暂等待；必要时发布有限的公共配送岗位或开放公共设施。老李可承接供货，阿禾可选择卖粮或自己加工，玩家可调整对未来订单的租价。若当前只是高利润商品暂缺而基本食物充足，公共协调者可以不干预。价格变化来自这些订单与产出，不由 AI 直接调低。

**湖畔周末活动**：委员会看到闲置公共场地和可用活动预算，提议钓鱼与食品摊活动，先确认场地、赞助和物资，再发布采购与邀请。厨师可以要求提高供餐报价，老李可以拒绝，普通居民按收入、兴趣和日程报名。实际到访受报名、路况和活动容量决定；低报名可以缩小或取消，未收到预算不能继续发奖。NPC 钓鱼执行尚未接入时可以参与观赛、采购和摊位工作，不能伪造 NPC 钓鱼成绩。

**共同修复路线**：真实外地路线受阻，运输系统产生延迟事实。GameEnvAgent 发布公共维修项目，工匠提出材料与劳动需求，玩家或 NPC 承接。完工后运输时长恢复，后续供货改善。若无人接单，可以提高尚未签约部分的预算、寻求有限外援或等自然恢复，不瞬间宣布修复成功。

这些例子用于测试可组合能力，不作为必须轮流播放的剧情。公共活动也能由普通 NPC、组织或玩家先提出，GameEnvAgent 只处理赞助、公共场地和需要协调的部分。

### 12.7 运行故障与权威位置

Godot 的领域系统是唯一事实写入方；Agent 服务负责提案与记忆，GameEnvAgent 也走同一条验证、事务与事件通道。公共计划记录提案者、授权组织、版本与效果证据。模型返回“预计增加 20 个游客”只是预测，不是生成游客的指令。

服务中断时，已承诺生产、工资、生活消费、运输与签订的订单继续推进；暂停新 AI 公共计划。只执行事先配置且有预算的基本保障策略，并标注“规则保障”，不冒充 AI 新决定。暂停游戏时不提交后台自主动作；网络响应可以接收并排队，恢复后按最新版本重新校验，过期提案丢弃或重新规划。玩家正在使用的对话交易等界面按第 7.6 节处理即时确认，不能混同于后台世界推进。

## 13. 关系、口碑与可持续合作

先建立三类可解释记录：履约可靠度、帮助与互惠、情报可信度。它们由交付、失约、援助、报告验证等事实累计，不由模型直接写入。

关系影响提前通知、保留商品、协商意愿和有限优惠。友好关系不能让 NPC 放弃必要口粮、无条件赠送所有资产或接受无法履行的合同。

NPC 之间也有关系和已履行承诺，能自然形成经常合作的供应链。玩家可以参与、替代某个环节，或者帮助关系紧张的双方解决短缺。

普通失败主要影响当前合作与短期信誉，提供补交、重新协商和后续履约的修复路径。首期不做复杂派系政治、恶意造谣和永久性封杀。

## 14. 完成条件、资产归属与结算规则

这些规则直接决定任务是否可信，是首期就需要确定的部分。

| 问题 | 规则 |
|---|---|
| 谁付报酬 | 发布者个人、组织或活动预算；公开发布时托管最大承诺金额 |
| 谁拥有交付物 | 交货前归当前所有者，成功验收后归指定接收者 |
| 钱不够能否发单 | 只能缩小数量、补充预算或保留草稿 |
| 多人同时接单 | 以当前任务版本和剩余额度原子抢占；失败者收到最新状态 |
| 多人同时交货 | 按提交顺序重新核验，不超收、不超付 |
| 报酬何时归属 | 按件收购逐次支付；整体验收任务在验收后支付；阶段付款须明示 |
| 同一物品能否完成多个任务 | 实物交付只消耗一次；生产与调查凭据按资格规则消费或复用 |
| 比赛成绩能否兼容多个目标 | 发布时定义互斥奖励组；默认同一比赛不能重复领取同类奖金 |
| 委托与合作如何分钱 | 对外委托向约定收款方支付一次，合作协议再从实际所得分配 |
| 取消后资产去哪 | 未承诺资金解冻；未用托管原料返还；已开工订单按原归属处理 |
| 调价是否影响已接订单 | 已签条款锁定；新报价使用新价格 |
| NPC 超时或离线怎么办 | 已签条款保留，已入队工作继续，等待协商的事项保持等待 |

任务报酬不能仅按当前高价机械加成。报价同时受需求紧迫度、预算、采购数量、工作时间和竞争渠道约束。允许玩家通过判断与效率获利，避免廉价买回自己反复交付的同一库存刷奖励。

## 15. 信息可见性与游戏反馈

### 15.1 玩家入口

- 公告板：今天有什么需求、谁在做、我能拿到什么。
- 对话：谈现货、谈消息、建议计划、提出合作、询问进度。
- 任务追踪：初始只固定显示 1 项，支持手动切换，其他留在列表。
- 地图：交付点、调查范围、公开项目和已购买情报。
- 建筑：自用与租用订单、预计完成时间、成品归属。
- 市场：价格、剩余供需和主要变化原因。

首次打开对话可以提供“买卖物品”“打听消息”“看看委托”“谈个计划”等快捷入口，同时保留自由输入。不要求玩家每次为了完成一笔小交易写长文本。

### 15.2 NPC 能知道什么

所有主体可见公告板公开条款、市场公开状态、已认识角色的公开活动。独家目标、私人钱包、未出售坐标和组织内部预算只向授权主体开放。任务提供必要能力要求，但不透露其他承接者完整资源。

工作状态只发布必要摘要，如“老李正在为旅店筹货”。私下价格、私人情报和完整目标优先级不因显示状态而泄露。

### 15.3 消息与追踪

普通完成通知合并，重要报价、临期风险和需要决策的阻碍单独显示。NPC 主动消息设置频率限制，同一阻碍不每轮重复催促。

调试追踪应能从一次模型决策追到：计划变更、动作提交、接受/拒绝原因、生产订单、交付、付款和最终收益。模型流完成与游戏动作完成是不同事件。后续动作结果应持久化为可关联的记录，不能只留在内存或只记录模型的 `completed` 状态。

## 16. AI 与规则系统的职责

| AI 负责 | Godot 规则负责 |
|---|---|
| 理解对话、表达性格、比较机会 | 钱包、物品、库存、位置与时间 |
| 提议目标、委托、交易或合作条款 | 权限、预算、预留和条款版本校验 |
| 选择已有可执行步骤，遇阻时调整 | 移动、生产、调查、比赛和交付执行 |
| 根据证据解释结果 | 判定任务完成、结算报酬、产生世界事实 |
| 对不确定性给出角色化判断 | 天气、事件结果及受约束的随机性 |

GameEnvAgent 适用同样的分工：AI 决定公共行动的目的、组合与预算内参数，规则验证权限并执行。普通居民使用轻量需要/效用策略选择行动，不必伪装成一次模型决策；重要居民与组织在需要开放规划、协商和表达时调用 AI。

新增能力建议按角色和上下文逐步开放：

| 查询能力 | 命令能力 |
|---|---|
| 查询可接委托、已接任务、当前项目 | 提议发布、接受、放弃委托 |
| 查询交付资格、剩余额度、任务进展 | 交付物品、提交调查报告 |
| 查询自己的情报与公开线索 | 提议情报交易、披露已授权事实 |
| 查询出租政策、订单与产能 | 提交租用订单、提出加工合作 |
| 查询合法建造地块、建筑材料与自己的建筑经营状态 | 提交真实建造、设置自有建筑费表/开放政策、安排维护 |
| 查询天气预报、公开事件与需求来源 | 提议项目、调整未承诺的项目步骤 |
| 查询自己可使用的能力、工作机会与已知设施 | 创建自主项目、接受工作、提出分包、安排空闲时段 |
| GameEnvAgent 查询公共指标、资金与措施效果 | 在授权内发布公共采购、排程公共设施、提议补贴与活动 |

以上是职责命名，具体工具名与 Schema 在实现阶段确定。优先复用现有交易、合作、探索和租用命令，不为同一资产变化再造平行结算接口。

对话允许产生提案、交易和目标协商；玩家仍通过界面确认涉及自己资源的承诺。对话不会让 NPC 自动操控玩家移动、完成游戏或接受任务。

### 16.1 决策频率与失败处理

首期沿用当前每轮最多两轮查询、至多三个命令的约束作为起点；需要更多信息时保存调查进度，下轮继续，不因为工具预算耗尽就要求 NPC 盲目付款。单次项目提案可以描述多步依赖，但只批准其计划，不一次执行全部动作。GameEnvAgent 使用自己的有限请求预算，不能借“公共计划”打包无限多订单。

公告板更新、收到报价、关键事件和项目阻塞可以唤醒相关角色；常规等待只订阅完成事件。相同事件合并，控制排队和重复请求。

调度同时限制游戏时间内的唤醒频次和真实时间的请求并发、token 用量。对话、临期履约、普通自主规划、GameEnvAgent 分别排队，给每类保留最低处理机会；公共复盘不能长期挤占玩家对话，也不能因为玩家一直聊天使公共任务永久饥饿。预算耗尽时优先继续已有确定计划，推迟新规划；不为赶进度把 NPC 未做过的选择补写成历史。

模型延迟必须与合同期限相容：报价有效期和任务期限需覆盖正常排队、往返与执行时间，不能在数秒真实时间内让整天合同过期。世界不会为每个后台请求暂停；超时后旧版本报价失效，必要时重新协商，不追溯性占用已经被别人买走的商品。

模型超时、协议错误、领域拒绝分别展示。有限纠错只用于明确的格式或组合错误；资金不足、队列满等领域拒绝必须等条件变化或修改计划。服务不可用时，公告板规则生成、既有生产与已授权计划步骤继续运行，需要新协商的事项保持等待，不伪造 AI 已作出的决定。

### 16.2 接入现有上下文与协议

当前服务端会按职业过滤固定目标和工具。迁移为“偏好/需要 → 自主目标 → 当前项目 → 动态可执行能力”四类上下文：`goals` 中保留既有职业倾向以兼容旧协议，新目标与项目使用独立的结构化字段，动态能力由 Godot 根据身份、技能、授权和执行器生成，服务端按同版本能力目录复核。自由目标不能被旧职业字符串白名单直接丢弃，也不能反过来通过自由文本绕过权限。正式替换职业授权逻辑前，两端和测试必须同步更新。

任务、情报和项目查询都使用主体可见性裁剪。默认只提供与当前角色相关的少量摘要，详细条款按需查询，避免把整个公告板、全体群体库存和完整任务历史塞入每轮请求。

Godot 与服务端同步增加能力声明和 Schema 校验，并显式版本化扩展。旧服务不能识别新能力时，暂不向该服务发布相应命令权限；原有交易、生产和地图玩法仍可使用。

| WorldEvent | 类型、随机种子/状态引用、阶段、范围、效果、恢复条件 |
| CompletionEvidence | 来源系统、唯一行动/订单/比赛 ID、主体、结果、可用额度、已消费额度 |

原始资产仍由现有库存、经济、生产等领域维护；新对象引用它们，不复制一份会独立变化的钱包或生产状态。

`Project` 从“目标模板”扩展为目标引用、可选模板、带类型的步骤图和里程碑；模板是常用起点，不是所有项目的必填枚举。能力目录中的每个可验收节点有稳定语义；自然语言说明可自由生成，资产变化和完成条件不可自由解释。PublicPlan 与私人 Project 共享生命周期和执行机制，只增加公共权限、预算和效果复盘。

对话插入的项目另存来源消息 ID、插入方式、暂停项目 ID、中断步骤记录、恢复条件和恢复策略；这些是计划事实而非仅在 AI 记忆中的描述。

### 17.2 提交顺序

交付等跨系统操作遵循：重新读取条款和资产 → 校验 → 暂存变更 → 一次逻辑提交 → 发布结果事件。失败时撤销本次暂存与预留，不留下扣物但未付款的中间态。

委托、交易、项目各有版本，验收按相关实体检查，避免无关 NPC 交易导致所有在途请求作废。每个结算动作使用唯一键；同一输入重复提交返回已有结果。

拟新增事件包括需求创建/满足、委托发布/承接/交付/结束、项目开始/阻塞/结束、知识授权、天气变化和环境项目完成。广播只包含允许公开的信息。

每笔经济结果带 `source_actor / owner / demand_id / project_id / action_id` 中适用的引用以及来源系统，公共干预再关联 `public_plan_id`。订单完成事实、市场统计和画面表现消费同一个结果，不各自追加资产。聚合统计必须可追到来源，NPC 知道的则是按权限裁剪后的视图。

### 17.3 每日更新与重放

时间推进由一个调度器管理。事件时间相同的“完成”和“到期”采用固定顺序，允许在截止时刻已合法提交的交付先结算。日结建议顺序：推进到期生产、班次、运输与自然事件 → 应用已签交付/工资并处理过期预留 → 消费与储备评估，更新同源剩余需求 → 各主体按既定采购/外包策略分配需求渠道 → 执行规则可完成的采购并结算当日市场 → 汇总公告和社会摘要 → 唤醒相关 NPC 与 GameEnvAgent。

不能先让背景自动采购吃光全部额度再尝试给 NPC 发单。主体预先选择现货采购、公开委托和私下洽谈的比例或条件，各渠道共用预留；AI 响应到达后提交面向当前/未来的提案，不倒回刚结束的日结。普通移动、加工、交货和协议确认仍在日内执行，不全挤到 06:00 瞬间发生。

精确先后顺序应与现有季节、生产和市场事件连接核对，避免同一日被多个监听者重复结算。委托生成使用游戏日期、来源需求和生成序号构成唯一标识。

休息跨越多个游戏日时依次推进经济、事件、期限和持续工作。只展示当前仍有效的公告，不因补算过去公告向模型发起大量过期决策。默认不模拟真实离线时长。

存档保存任务、承接、托管、自主目标、项目步骤图、居民/组织、建筑产权与经营政策、施工与加工收款状态、统计分组、知识、公共计划与预算、活动、事件阶段、随机状态和验收凭据。AI 的预测记录与最终采纳方案也要有版本和输入事实引用；存档中已提交事实优先于服务端记忆。旧存档采用版本迁移，为新系统建立空状态或基于当前世界的起始需求，不补发历史奖励；新增居民和公共开局拨款只初始化一次。

旧 3D 存档中由玩家建筑系统保存的建筑默认归玩家，原租赁订单保留租客、成品归属与已经收取的加工费记录。旧 NPC 建筑注册表中的逻辑记录不能未经校验直接生成为新实体或重复增加产能；先区分它们与已有 3D 实例的映射，缺少位置/施工事实时按迁移规则处理。建筑实例采用持久 ID，地块坐标作为位置属性，移动或表现重建不改变订单所引用的产权身份。

读档后显式重新绑定执行器、任务系统和生产系统对当前农场的引用，重建事件订阅，并校验托管资金、剩余额度与已结算凭据。迁移或校验失败时不覆盖原存档。游戏事实保存在游戏存档，AI 服务中的记忆不能成为任务是否完成的唯一依据。

## 18. 初始参数建议

以下用于首轮试玩，不是已经确定的平衡数值。

| 项目 | 初始建议 | 调整依据 |
|---|---|---|
| 每日新增委托 | 观察目标 2～6 条，不强制补满 | 真实需求数量、重复率与阅读负担 |
| 公告板有效条目 | 约 12 条，已承接的独家任务移到进行中 | 阅读负担与公开机会数量 |
| 同时承接 | 每主体 3 项，含公开收购预订 | 是否出现占单与过度承诺 |
| 新手任务 | 优先 1 个可短时完成的任务 | 是否能理解交付和结算 |
| 普通任务期限 | 半天至 2 个游戏日 | 真实移动、生产时间及玩家反馈 |
| 长项目期限 | 3～7 个游戏日 | 作物周期与事件规模；模板可延长 |
| 重点 NPC | 先 3 人，后约 6～8 人 | 每人能否产生不同互动 |
| 居民总数 | 首轮 30～60，再试 60～120；含重点 NPC | 购买力、就业、产能和日结成本 |
| 可见普通居民 | 附近约 6～12 个 | 场景性能、拥挤与活动表现 |
| 组织 | 先 2 个，再约 3～5 个 | 是否带来独立预算和不同决策 |
| GameEnvAgent | 每日 1 次复盘，关键事件最多加 2 次唤醒 | 干预是否必要、调用占用和稳定性 |
| 公共措施并发 | 先 1 项有实质经济影响的措施 | 是否能分辨效果与成因 |
| 主要事件并发 | 初期 1 项 | 是否能理解原因和应对 |
| 同类主动催促 | 一个阻碍只在状态变化或关键期限时提醒 | 消息噪声 |
| 项目投资 | 先小额、保留生存与已承诺资源 | NPC 是否反复破产 |

利润、奖励和 NPC 业务规模通过供需模拟调整，不以单纯提高任务奖金让玩家感到有影响。稀有商品允许较大局部波动，基本生活资源应有受成本约束的补货途径。

## 19. 实施顺序：先证明自主社会，再扩内容

以下为产品里程碑划分；原“阶段 1”涉及多个完整循环，执行时已拆为 P1～P7 等独立交付，具体顺序见[实施计划总览](../plans/2026-09-07-npc-agent-living-world-implementation-plan.md#1-交付原则与阶段总览)。每一阶段都须具备真实执行、正式界面、失败处理和存读档验证，不以只完成底层模块作为交付。

### 阶段 0：让承诺和结果可信

- 改造对话交易卡，去掉 JSON 展示，明确双方资产与确认条款。
- 打通模型请求到游戏动作、生产与交付的持久化追踪。
- 统一资产预留、报酬托管、凭据与需求引用。
- 验证重复执行、存读档和服务中断不造成重复扣费或错误成功状态。
- 明确唯一动作执行者、经济来源引用和两端能力版本；补足已有租用等关键动作的结果反馈。

### 阶段 1：最小自主社会纵向切片

- 用现有三名 NPC、少量轻量居民、旅店和公共事务组织，接通一条食物链；第一轮可只用约 12 个居民账户做验证，稳定后再扩到 30～60 人。
- 居民有生活库存与来源明确的收入，旅店有真实预算；按来源关闭对应旧需求注入，避免双算。
- 实现自主目标与持久项目的最小版本，支持发现经营机会、比较成本、采购、租用加工、等待与销售/交货。
- 统一生产建筑所有权和账户结算；先开放一种 NPC 自建建筑（如风车），打通筹料、选址、施工和开放营业，验证玩家与其他 NPC 都能向该 NPC 付费加工。
- 对话可协商修改项目，并插入一种已有执行能力支持的短任务；验证关闭对话和存读档后继续执行，完成后恢复原计划。
- 公告板先只做采购/加工的条款和交付；保留玩家发布需求、NPC 自己发单与协商，不急于铺齐所有任务类型。
- GameEnvAgent 先提供公共指标查询、“不干预”和一种有预算的公共采购能力，共用项目与任务执行。
- 没有新增美术时组织通过已有集市交互，居民可以先用占位表现；经济真实性不等待所有模型完成。

阶段验收：玩家连续数日不下指令，居民的工作收入形成食品购买，NPC 至少能提出并执行一项有依据的私人经营计划；出现短缺时公共协调者可选择采购或等待，NPC 可以响应也可以拒绝。另在提供足够材料和合法地块的场景下，验证 NPC 自建的真实风车能向玩家和另一名 NPC 收加工费，成品分别归使用者。产出、收入、消费、需求和加工费都追得到来源。若只能靠固定脚本给老李发单才能发生，就没有通过本阶段。

### 阶段 2：形成分工与不同人生路径

- 扩展居民工作、雇佣、运输、私下分包和设备访问权，支持公共设施排程与真实产能约束。
- 将已验证的自建和相互加工能力扩展到其他工作建筑，补充 NPC 经营调价、维护与合作投资决策。
- NPC 能为学习、投资、兴趣和关系创建项目；加入有限小额试验、经验复盘与替代方案。
- 接通真实调查地点、可交换情报、样本、探索补给换报告和设备换分成。
- 引入动态能力目录，逐步解除“职业等于全部权限”的限制；扩展普通居民升级为重点 NPC 时的状态接续。

阶段验收：同一供货机会因价格、私人消息、关系或设施可用性变化，形成不同的供应链；提高某座工坊租金后，角色能议价、换供应商、改项目或退出。不能只随机替换计划名称。

### 阶段 3：公共协调与生活活动

- 扩展到经性能与经济模拟验证的人口数量，完善采购替代、就业与外部贸易边界。
- GameEnvAgent 增加有限补贴、扩产招标、公共建设和活动策划，附带观察窗口、预算分项与退出条件。
- 先完成一种天气/运输链和一种湖畔活动链；公共支出、实际到访、消费和后续效果可查看。
- 扩充厨师、工匠等有不同经济作用的角色，补充工作、交付和社交表现。

阶段验收：公共活动可以成功、缩小或取消；运输延误能由不同主体协力缓解，也能自然结束。关闭 GameEnvAgent 的新规划后，私人经营和居民日常仍继续，社会不会因为失去总指挥立刻停摆。

### 后续扩展

区域贸易、精细建筑预约、长期供货、探索带队、NPC 参与小游戏、联合经营、住宅与更复杂的组织关系。计划和合同允许自然语言表达与已有能力的自由组合；没有可验证条件的任意合同、运行时生成代码创造新玩法、复杂债务与永久惩罚均不进入首期。

## 20. 验证方式与成功标准

### 20.1 规则与集成验证

| 场景 | 应满足的结果 |
|---|---|
| 同日重复刷新、保存后重载 | 不重复生成任务或奖金 |
| 多人接最后一份额度 | 只有合法份额被承接，预留总量不超需求 |
| 多人交付、重复点击 | 物品、报酬和进度只结算一次 |
| 原料不足、库存已被预留 | 明确拒绝且不扣其他资产 |
| 用旧产品交生产任务 | 拒绝缺少生产凭据的部分，采购任务仍允许 |
| 加工完但未交货 | 产品归合法所有者，任务保持未交付 |
| 委托过期或协商取消 | 资金、托管原料与在制品按条款处理 |
| 公开需求从另一渠道满足 | 同源剩余额度更新，不二次采购同一需求 |
| 情报交易失败或重复购买 | 不泄露付费内容，不重复扣款 |
| 同一比赛重复提交 | 奖励按唯一凭据与奖励组正确去重 |
| 服务超时、模型指令无效 | 不承诺已成功，既有规则任务正常推进 |
| 读档、休息跨日 | 项目继续，预算守恒，到期与随机事件不重抽 |
| 大量任务与 NPC 事件 | UI 可响应、唤醒有界、重复失败进入阻塞 |
| 普通居民提升为重点 NPC 再降级 | 账户、库存、承诺与日程不变，不新增一份消费和收入 |
| 新居民需求接替旧人口参数 | 相同来源只结算一次，关闭对应旧需求和快捷产出 |
| 两个项目争用一个工人或设备 | 有效劳动与产能预留不重叠，失败方能等待或改计划 |
| GameEnvAgent 使用公共预算 | 承诺不超可用资金，未来门票收入不能先花，私人资产未经同意不变化 |
| NPC 拒绝公共订单或活动 | 保持自主性，公共计划如实缩减、重新招募或结束 |
| 反复发起同一补贴/活动 | 原始贡献、需求和活动 ID 去重，不重复领取或制造虚假购买力 |
| 模型超时、暂停期间回复、恢复后旧提案到达 | 不倒写历史、不抢已占资源，按版本重新验证 |
| GameEnvAgent 停用或公共预算耗尽 | 私人社会继续运行，新增公共承诺受限，已有承诺仍履行 |
| 对话建议、疑问或假设 | 不擅自付款/接单，只有采纳的建议才改变计划 |
| 对话接受临时任务后关窗、读档 | 临时任务保留，完成后重验原计划并恢复，不重复生产或扣款 |
| 原任务临期、动作不可中断、反复插单 | NPC 说明冲突，排队、协商或拒绝，不无限暂停原承诺 |
| 对话重发、改约后旧响应到达 | 去重并校验计划版本，不创建重复任务、不覆盖新条款 |
| NPC 自建、重复开工、多人争用地块 | 只扣建造者真实材料，只生成一个有产权的 3D 实例，不占他人土地 |
| 玩家 → NPC、NPC → NPC、自用加工 | 外部加工费归对应所有者，成品归客户，自用不重复转账 |
| 排队后调价、关门或拆除 | 已接受订单的费率和容量受保护，存在未结清权益时不能拆除 |
| 取消未开工订单、旧预付订单迁移 | 退款有托管来源，材料归还正确；既有已收款记录不二次扣付 |
| NPC 建筑施工中/完工后存读档 | 所有者、地块、费表、队列、收款和成品归属保持一致 |

### 20.2 经济模拟

在固定种子下跑多轮、多个游戏周，记录资金来源与去向、群体库存、缺货天数、补货量、任务报酬、NPC 利润和完成率。重点观察：是否永久短缺、是否无成本刷钱、是否所有 NPC 都追逐同一种配方、玩家影响是否被背景规模吞没。

同时用不同玩家策略模拟：专注种植、市场转售、加工出租、只做探索、完全不接委托。不同路径应各有机会，公告板不应成为维持农庄生存的唯一方式。

至少比较三个对照：普通居民与确定性经营基线、加入自主 NPC、再加入 GameEnvAgent。固定相同初始经济与外部事件种子，分别观察基础消费满足率、收入分布、缺货持续时间、设施利用率、破产/停业、公共支出和恢复时间。公共支出更多不一定更好；如果 GameEnvAgent 只增加消费却没有改善目标问题，或使供需波动更大，应减少权限/调整策略再试。

确定性回归回放保存的模型提案与事件结果；相同世界种子并不保证远程模型再次生成同样的决策。另做多次真实模型试跑，记录选择差异、无效提案率、等待时间、每游戏日请求与 token 用量。先设预算并测量，不预先承诺某个人口数的调用费用或帧率。

GameEnvAgent 初次接入采用可切换的观察模式：记录提案和规则检查结果，暂不执行公共支出；通过有效性验证后才切到有限预算执行。观察模式只是开发验证开关，不把它宣称为已经影响经济的 AI。

### 20.3 试玩观察

- 玩家能否在一分钟内理解一张任务卡，知道去哪交付。
- 是否会因为消息、关系和设备条件选择不同任务。
- 能否准确说出一次价格变化的主要原因。
- NPC 的主动计划是否引发玩家回应，而不只是产生通知。
- 玩家离开一段游戏时间后，能否看见可解释的工作进展。
- 玩家是否能不接单、不参加活动，也正常经营农庄。

### 20.4 自主社会的验收指标

首轮以多个连续 14 游戏日的试玩/模拟窗口记录下表。窗口长度和门槛均为测试建议，应覆盖实际作物周期；它们是开发验收，不能反向变成要求 AI 每日完成的配额。

| 指标 | 如何验证 | 不算成功的情况 |
|---|---|---|
| 自发行动 | 至少观察到两类未由玩家/公共委托直接触发的项目，以及真实执行结果 | 换名字的固定日程或纯对话承诺 |
| 对条件作出反应 | 同一角色面对租费、需求或路线变化，会按证据重新选择 | 只在计划名称和台词上随机变化 |
| 社会分工 | 至少一条私人协商形成的跨主体供应/服务链，能追到各自利益与结算 | 世界代理直接给每人下命令 |
| 生活持续性 | 玩家不接单时仍有工资、消费、生产和失败恢复 | 每日凭空刷新货币、库存或剧情订单 |
| 公共协调价值 | 能说明花了谁的钱、改善了哪个问题、还剩什么代价；允许合法不干预 | 通过改价格/改统计直接使指标变好 |
| 玩家自由 | 农业、贸易、出租、合作和休闲仍可选择；拒绝活动不阻断主玩法 | 玩家必须救援每个项目才能维持经济 |
| 角色连续性 | 不同偏好与经历影响后续选择，存读档能接续 | 每次对话重新随机生成一个人格 |

若一个方案经济正确却无聊，优先增加可争取的资源、信息差、合作方式和长期目标；若故事很热闹却结算不可信，先修复执行与来源追踪。不要通过提高随机事件频率掩盖这两类问题。

## 21. v2 的关键设计选择

本次评审建议采用以下方向：

1. **NPC 有自己的生活和志向**：没有玩家指令、没有公告板任务，也能决定谋生、学习、试验、交往或休息。
2. **自由主要来自组合与后果**：统一可执行能力，开放目标、对象、数量、时机和合作关系；持续项目把一次对话延伸到数日后的实际变化。
3. **GameEnvAgent 是有资源边界的公共组织者**：它能策划经济与生活活动，通过订单、激励和公共资源调配产生影响，也允许失败与不干预。
4. **人口先有经济身份，再增加模型数量**：持久居民、组织和外部经济构成购买力、劳动力与消费循环；统计群体与可见人物不再重复创造需求。
5. **社会不只有利润**：兴趣、关系、闲暇、学习与小规模公共活动提供长期目标，但仍对应真实时间、资源和参与结果。
6. **玩家是社会参与者**：可以发布委托、谈条件、投资、承接一个供应链环节，也可以拒绝参与，NPC 保留独立回应。
7. **先验证最小社会，再扩大系统**：首个切片就检验自发计划、生活经济与公共协调，公告板、美术和角色数量随后丰富。

本稿采用轻度经营、局部竞争、可恢复失败的默认方向。首期核心循环调整为“个人需要与世界机会 → 自主目标/公共提议 → 独立协商与分工 → 真实执行和结算 → 消费、关系及环境反馈 → 下一轮选择”。公告板服务于这个循环，而不承担制造整个社会动机的职责。
