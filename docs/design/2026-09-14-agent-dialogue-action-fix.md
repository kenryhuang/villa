# 对话排队与 NPC 动作反馈修复

## 现场证据

检查 `tmp/farm3d-65b684bc56128-106b300f19b-1789353366-5530987.ndjson` 与只读存档中的动作回执：

- 玩家对阿禾说 `hello`，模型直接提交 `harvest`；另一轮“你要点什么？”也提交收获。v3 Loop 缺少对话模式限制，暂停中的游戏把整个回复替换成“行动请求已排队”。
- 阿水多次提交 `prepare_supplies → travel → survey`。第一步返回 `assets_reserved`，后续步骤按失败规则跳过。存档实际金币为 58，面包参考价 186、市场库存 0，外部资产预留为空。真正原因是交易条件不足，旧错误码导致模型误以为等待释放预留后可以重试。
- 铁匠存在出售 5 条鲤鱼的成功回执，不能据此判断所有 NPC 的移动执行器失效。
- 模型流结束时 trace 就已落盘，之后的行动事件只更新内存，磁盘上的 `action_events: []` 不代表没有执行动作。

## 修改

1. v3 对话直接回应当前玩家消息，普通问候不启动后台农活。对话菜单限制为互动与短期目标；错误动作可纠正一次，实际权限不扩大。带行动也必须给玩家一句回复。旧协议的对话菜单保持原行为。
2. 游戏保留 NPC 回复；确有需要延期执行的动作才追加暂停提示。恢复游戏后仍按真实条件重新核验，执行回执作为补充信息。
3. 交易出发前和到达后均核验；区分缺货、缺钱、真实预留和背包不足。失败回执携带余额、可用资产、总报价及库存。下一轮近期事件压缩保留这些字段，详情仍可按事件 ID 查询。
4. 已结束流的行动回执以独立 NDJSON 行追加：`record_type: "action_event"`，通过 `request_id` 关联请求，内容为 `action_event.event/timestamp_msec/metadata`。分析日志时应按记录类型区分模型请求和行动事件，不能把每行都计为一次模型请求。相同执行回执不重复追加。
