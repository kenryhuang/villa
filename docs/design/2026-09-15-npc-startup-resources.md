# NPC 初始资源调整

## Trace 诊断

检查 `tmp/farm3d-65b875f674560-106ea00f19c-1789486839-4343633.ndjson`。这是游戏第 179～180 天的运行，不能把余额直接视作初始资源。

- 阿禾有 5,577 金币和种子，完成了种植、收获。
- 老李只剩 5 金币，盐、粮食和粮食种子耗尽。
- 阿水只有 16 金币；准备 2 份面包报价 403 金币，被 `insufficient_gold` 拒绝，后续也出现面包缺货。
- 林先生有 76 金币，没有面包和绳索；一次调查还因未抵达目标，被 `survey_requires_arrival` 拒绝。
- 铁匠有 323 金币，没有铁矿、铁锭和木板，只能发起铁矿采购请求。
- 阿云有 49 金币，随后买入少量盐并继续请求补给。

资源不足确实限制了行动，但提高新开局资源不能恢复已消耗了 179 天的旧存档，也不能单独解决长期收支、矿物供给或行动顺序问题。

## 实现

新增 `data/living_world/npc_startup_resources.json`，由 `ResidentSocietySystem.economy_profiles()` 在构建 3D 初始居民经济状态时读取。通用补给与职业补给均按数量下限合并，不反复累加。

| 居民 | 初始金币下限 | 主要职业补给 |
| --- | ---: | --- |
| 普通居民 | 2,000 | 面包 12、胡萝卜 20、土豆 12 |
| 阿禾 | 5,000 | 三类基础种子各 24、粮食 24、木材和石头各 30 |
| 老李 | 8,000 | 盐 40、基础种子合计 70、粮食 40、面包 24 |
| 阿水 | 6,000 | 面包 32、绳索 12，以及粮食、面粉、蛋、盐 |
| 林先生 | 6,000 | 面包 32、绳索 12、木材 12、金矿和水晶各 4 |
| 铁匠 | 6,000 | 铁矿和煤各 24、铁锭 12、木板和石砖各 16、木材和石头各 40 |
| 阿云 | 5,000 | 面粉和蛋各 24、盐 16、胡萝卜 40、鲤鱼 8 |
| 小花 | 5,000 | 玫瑰 24、蜂蜜 8、纤维 16、玻璃罐 8 |

职业居民也获得通用口粮；原有更高数量保留。资产仍存放于 NPC 经济账本，Agent context 从账本获取实时资源。公共组织资金和旧 2D 初始配置保持原有规则。

读档以存档资产覆盖初始状态，不每天补给、不在读档时重新发钱。2026-09-16 经用户确认，另行向当前第 180 天存档的 36 名居民一次性补足上述下限，共增加 55,453 金币及对应物资；已有较高余额和物资不减少。补给计入初始资金基线及居民账本，并添加 `ResourcesGranted` 待处理事件供下一次决策读取。

替换前的完整存档、记忆旁文件和原 `.bak` 保存在 `tmp/save-backups/npc-topup-20260916-000334/`，其中 `report.json` 记录逐人差额及文件校验值。原存档和补给候选均经 Godot 实际加载通过，36 名居民资源 context 和补给事件验证通过，日期仍为第 180 天。替换时校验原文件未变，并原子替换主存档；玩家、农田、建筑、任务和其他游戏进度保持原值。

## 验证

`tests/run_npc_startup_resources_tests.gd`：26 项检查通过。使用隔离的完整 3D 新世界、真实初始资产和动作执行器，验证：

- 初始配置生成可重复，Agent context 与账本一致。
- 铁匠走到市场出售 2 个铁锭，库存减少且金币增加。
- 阿水、林先生执行前往溪流后调查，实际抵达、消耗面包并取得私人调查记录。
- 恢复已花完资源的经济存档不会再次发放初始资源。

动作由测试明确提交，验证的是执行能力，不代表已验证 LLM 会自主选择这些动作。测试仅加快移动和推进模拟分钟，未额外注入测试资产，也未访问或覆盖玩家存档。

回归：Agent system 1,719 项、商行闭环 86 项、3D 存档保护 18 项全部通过。

## 后续观察边界

这是一组便于观察有效行动的宽裕开局参数，尚未做长期平衡标定。铁矿 `request_supply` 仍是非约束性需求登记，不会凭空生成矿源。调查仍要求先抵达地点；相关规划失败应单独修复。
