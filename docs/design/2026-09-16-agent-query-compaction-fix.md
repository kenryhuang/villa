## 查询结构

`data/agents/query_catalog.json` 是服务端和 Godot 共用的领域分区目录。`discover_tools` 直接返回已开放领域的分区、默认列表和查询提示；已发现目录写入本轮 header，压缩后仍保留。未发现领域的世界实例不预先加载。

- `query_world` 的 section schema 枚举来自当前已开放目录。
- `query` 支持空格、逗号分隔的任一关键词匹配；`market/detail` 支持 `ids` 精确批量查询。
- 省略 section 且提供 id/ids 时查询详情；提供 query 时查询默认列表；无定位参数时保留 overview 兼容行为。
- 市场旧 `list/price/prices` 分区兼容到当前查询，避免无效消耗。
- 缺少详情 ID、未知物品、未知建筑、错误报价参数明确返回错误；空列表带匹配数量、分页和继续搜索提示。
- 建筑详情保留当前库存、生产队列摘要、维护、配方费用和服务政策，排除完整历史订单及其他顾客领取记录。
- `buildings/quote` 接受 `id/recipe_id/batches`，通过真实生产服务预检，返回原料、总费用、产出、可用性和可提交的 `rent_production` 参数。失败时保留配方条款。查询不扣资源、不下单；实际执行仍重新检查状态。

示例：

```json
{"domain":"market","section":"detail","ids":["flour","egg","bread"]}
{"domain":"buildings","section":"quote","id":"food_workshop:20:19","recipe_id":"bread","batches":2}
```

## Compact 规则

`agent_context_compaction.ts` 使用结构化观察代替原先的前 240 字符截断：

- 身份、当前资源、最近经历、相关记忆、短期目标和已发现目录保留在 header。
- 保留查询参数、观察 ID、模拟时间和版本，以及完整的费用、原料、ID、位置、前置条件、失败原因、行动参数。
- 仅剔除指定的历史明细字段，并记录被剔除字段；不把截断的数字或字符串当作事实。
- 同一查询的新观察覆盖旧观察；报价、详情、到达检查和错误优先保留；重复压缩继续保留已有结构化事实。
- 超预算时整体移除观察，不拆散 ID 与其报价；保留有上限的缺失详情查询引用。明确要求缺失或过期信息重新查询，不能把缺失费用当成零；无读取额度则等待。
- 观察不是库存预留、合同或完成回执。原有执行时校验及循环读取/行动上限继续生效。
