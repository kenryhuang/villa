# Agent Loop 工具发现错误修复

来源：`tmp/farm3d-65b651fef2618-106b300f19b-1789339745-3296412.ndjson`，本次检查时共 9 条终态记录。

- 5 条 `provider_unauthorized_tool`，全部发生在第一次 `discover_tools`。
- 3 条取消，原因均为 `game_closed`。
- 1 条完成，但在剩余 2 次读取额度时请求 4 次读取，经过纠错后选择等待。

## 原因

初始 `discover_tools.actions` 是没有说明或枚举的字符串数组。模型尚未收到行动目录，就把“查询价格”等意图、`check_plots` 等猜测名字、或 `inspect_self_resources` 等读取工具名填入其中。服务将“目录选择无匹配项”当作实际执行越权，立即终止 Loop，没有给模型机会使用已经找到的查询入口。

此外，连续发现领域会替换先前行动菜单；已经被角色授权但暂未启用 schema 的行动也被归为真正越权。剩余读取额度只进入 trace，没有进入模型上下文。

## 修复

首次 schema 只要求领域；发现目录后才提供可选行动名枚举和准确说明。对旧式/错误选择返回结构化目录反馈及可用名字，不授权、不执行未知行动，也不终止正常领域查询。真正调用角色未授权的行动仍拒绝。

仅发现领域时保留已有行动菜单（额外菜单最多 6 项）；明确选择时才替换。已授权但未启用的行动允许一次纠错，必须先发现/启用才能提交。每轮上下文包含剩余回合、读取次数及单批上限；新增验证失败 trace 记录具体调用和当轮工具列表。

## 回归覆盖

原 5 条失败输出提取到 `services/agent-service/tests/fixtures/loop-discovery-errors.json`，保留原始工具调用参数。`agent_loop_discovery.test.ts` 回放全部 5 条，并验证可继续查询且没有动作被意外执行；另验证菜单保留、未启用行动纠错、公共角色不能获得私人行动权限、超额读取不消耗剩余额度。

后续查询/回复由测试脚本提供；这是原始失败输出的确定性回放，不声称真实模型的新行为已经验证。代码仅在重启 Agent Service 后被现有游戏连接使用。
