# 角色存档调试

入口：开发调试 → 角色存档。角色下拉框包括玩家、重点 NPC 和普通居民。

选择角色后，第二个下拉框列出其关联的真实存档记录，包括金币/背包/储备/配方、居民生活需求、双向好感与关系、职业、目标、日程、合同、执行回执、知识及农田作物。共享名单和合同保持完整结构，因此编辑会影响对应的其他参与者。好感尚为零的关系也提供可编辑记录。

记录正文使用带行号的 JSON 编辑器。切换角色或记录保留各自草稿；重新读取会丢弃当前角色的草稿。所有记录按当前农场存档结构展示，ID、版本和引用需保持有效。不存在的目标、负库存、超过 100 的好感和不一致合同会被存档校验拒绝。

进入此页暂停模拟，退出此页或关闭调试窗口恢复此前暂停状态。应用时只合并改动记录；若改动记录与读取时不同，拒绝覆盖并提示重新读取。其他未修改记录使用最新值。校验通过后失效旧 Agent 请求，复用正常存档恢复流程，然后保存当前存档；写入失败回滚运行状态。调试应用不会清空服务端的对话记忆。

世界存档版本 9 增加 `character_overrides`，保存每个角色的名字、性格、价值观、说话风格、风险偏好，以及年龄、性别、恋爱兴趣、交往风格、接受关系阈值。未设置覆盖时仍读取原配置。版本 8 及更早世界存档继续兼容。

覆盖值同时用于角色称呼、恋爱规则和下一轮 Agent 的固定身份头部。Agent Service 接收严格校验的 `identity_override`；它不改变角色 ID、职业权限或工具授权，不额外加载世界详情。

金币、背包、生活需求、好感、共同经历和恋爱关系本来就随农场存档保存。服务端提取的长期记忆不是农场当前状态存档的一部分，此页明确说明不编辑该数据库；不会把仅在运行时的缓存或配置文件伪装成已落盘状态。

验证：`run_character_state_editor_tests.gd -- --farm-test --living-world-scenario=P12` 覆盖多字段应用、实际存盘重载、双向好感、性格进入下轮请求、错误 JSON、无效值不部分写入、并发旧值保护、写入失败回滚、UI 布局与暂停恢复。所有测试使用隔离存档；另用现有存档副本验证旧版本迁移。
