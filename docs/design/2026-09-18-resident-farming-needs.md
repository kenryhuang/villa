# 多农户与居民生活需求

小花、阿水、阿山默认职业改为 farmer，保留各自人格和兴趣。加上阿禾，四位自营农户各有 20 块真实农田，独立所有权、库存和作业队列。重点角色池从 6 人扩展至 8 人，其他居民继续背景模拟。模型每日调用预算保持原值。

`npc_farm_group.gd` 保留原阿禾农田存档结构，在 `additional_farms` 中保存其他农户。查询、行动按 actor ID 分发，各自控制器执行行走和作业；完成事件回到同一 Agent 执行器。收成归所属账户，不能操作别人的田。

## 职业之外的生活

所有居民都有独立于职业的五项需求压力，0 表示满足，100 表示迫切：

| 需求 | 每游戏小时基础增长 | 实际缓解方式 |
| --- | ---: | --- |
| 饥饿 hunger | 4 | 背包真实食物、每日用餐、活动配餐 |
| 口渴 thirst | 6 | 到旅店的公共饮水点饮水 |
| 疲劳 fatigue | 3.5 | 休息或睡眠 |
| 社交 social | 1.8 | 实际拜访、接待拜访、到场参加活动 |
| 陪伴 companionship | 0.7 | 与信任值至少 3 的居民实际相处 |

个体增长系数稳定在 0.85～1.15 之间，初始压力也因人而异。达到 70 时记录需求事件并唤醒重点角色，仍受既有调度预算约束。数值当前影响自主规划，不直接造成伤害或强制取消已签工作。

感情需求落实为长期信任与陪伴动机，以及可持久化的陪伴压力。后续已增加好感、单身约会与对话确认恋人关系，见 [社交、日程与地图闭环](2026-09-18-social-navigation.md)；不会自动配对。

## 按需获取与行动

初始 GameEnv 和职业目标说明生活需求；详细实时数值通过 `discover_tools(self)` 后调用 `query_world(domain=self, section=needs)` 获取。查询永远只返回本人状态，不把其他人的私人需求加入 context。

`start_leisure(activity, partner_id)`：

| activity | partner_id | 游戏分钟 | 完成效果 |
| --- | --- | ---: | --- |
| eat | 本人 ID | 15 | 扣除一个真实食物，饥饿 -65；完成时无食物则取消 |
| drink | village_inn | 10，另计行走 | 口渴 -80；当前为免费公共饮用水，不从河湖直接饮水 |
| rest | 本人 ID | 60 | 疲劳 -35 |
| sleep | 本人 ID | 180 | 疲劳 -85 |
| visit | 另一位可见且空闲居民 | 60，另计行走 | 发起人社交 -45，对方 -25；原有信任足够时双方陪伴 -30，沿用既有信任增长 |

提出计划、报名、单纯发消息不会直接满足陪伴需求；取消和失败没有完成收益。活动报名后必须实际到场才获得社交收益，配餐继续扣除活动真实食物。背景居民沿用每日食物结算，闲暇时有基本饮水与夜间休息规则；重点角色由模型自主选择生活行动。

需求保存在居民存档的 `needs` 中；完成和迫切需求事件进入 Agent loop 事件流。新存档包含上述状态，旧存档第一次读取时补齐，不重置玩家资产、建筑、关系和作物。

## 迁移与验证

未主动转职的小花、阿水、阿山从旧默认职业迁移到 farmer；有明确转职记录的角色保留其选择。旧存档首次迁移为新农户补足胡萝卜、土豆、谷物种子各 24 份，登记物资来源，此后读取不重复发放。新游戏使用初始资源配置。

验证覆盖独立农田所有权、真实行走与作业、消耗和收益幂等、实时查询隔离、需求增长与恢复、可信陪伴、旧职业迁移，以及当前实际存档的隔离副本读写。测试不会覆盖正式玩家存档。
