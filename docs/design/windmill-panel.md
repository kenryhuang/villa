# 风车操作面板设计

状态：交互设计稿，待评审。此轮只设计界面与操作，不改正式游戏逻辑。

[打开可交互原型](windmill-panel.html) · [桌面界面](windmill-panel.png) · [窄屏界面](windmill-panel-narrow.png)

原型使用固定示例数据，可切换配方、调整批量、提交订单、收取产物、关闭重开、预览异常状态和演示维护。顶部状态切换、推进时间、重置属于设计演示工具，正式游戏面板不包含这些控件。示例价格用于展示信息层级；正式接入时必须使用市场批量报价。

## 1. 操作入口与完整流程

1. 走到已建成风车的院落入口，点击风车打开面板。交互距离沿用 3D 农庄的近距离限制，并以院落外侧交互点判断。施工中的风车显示施工进度。
2. 收起鱼竿、退出建造预览、停止玩家移动；面板居中，背景农庄变暗。打开时暂停游戏时间，明确提示“关闭面板后继续生产”。
3. 左侧选择面粉、动物饲料或葵花油；切换配方时批量重置为 1。
4. 中间查看本次投入、产出、背包持有量和时长，使用减号、数字输入、加号或“最大”调整批数。
5. 点击“投入原料并加入队列”。提交成功后立即扣除整笔订单原料，右侧新增订单，背包数量同步更新。失败不扣物品，并显示准确原因。
6. 关闭面板恢复游戏时间；队列按先后顺序加工。关闭或重新打开不会取消订单，也不会重置进度。
7. 完成后，成品进入风车输出仓，院落内出现袋装或瓶装产物。可点击院落成品收取，也可在面板逐类收取或全部收进背包。

## 2. 界面布局

视觉沿用农庄的暖白纸色、深绿主按钮、木色图标。主要操作始终是“投入原料并加入队列”。

| 区域 | 内容与职责 |
| --- | --- |
| 顶栏 | 风车名称、空闲/加工中/维护暂停等当前状态、金币、关闭按钮 |
| 时间提示条 | 游戏时间已暂停；自然风驱动、无需燃料 |
| 左栏：配方 | 三张配方卡，显示图标、名称与单批投入产出；选中项清晰高亮 |
| 中栏：加工 | 投入 → 产出、背包数量、批量、本单时长、排队等待、行情估算、提交按钮、失败原因 |
| 右栏上：队列 | 当前订单、进度、剩余时间；等待订单；空闲位置。默认 2 个队列槽 |
| 右栏下：成品 | 按物品列数量、逐类收取、全部收取、容量与背包不足提示 |
| 底栏 | 维护剩余天数与维护入口；院落收货提示 |

桌面三栏同屏；不足 900 逻辑像素宽时切换成“配方 / 加工 / 队列与成品”三个页签，保留配方与批量。窗口高度不足时内容区滚动，顶栏、时间提示和维护底栏保留。

## 3. 配方与批量规则

| 配方 | 每批投入 | 每批产出 | 基础加工时间 |
| --- | --- | --- | --- |
| 面粉 | 谷物 ×2 | 面粉 ×1 | 27 游戏分钟 |
| 动物饲料 | 谷物 ×1 | 动物饲料 ×2 | 27 游戏分钟 |
| 葵花油 | 向日葵 ×3 | 葵花油 ×1 | 27 游戏分钟 |

- 数量指“批”，不是最终产物件数。面板随批量实时计算投入与产出。
- 一笔批量订单占一个队列槽。例如面粉 3 批消耗谷物 6，产出面粉 3，基础工期 81 游戏分钟。
- “最大”受持有原料、原系统批量上限和权威预检限制；数量合法范围沿用原面板 1–9999。达到上限不会自动提交。
- 加工与等待时间分别显示。已有升级时使用权威快照中的有效时间，不重新实现加速公式。
- 第一版保持原规则，不提供已提交订单的取消按钮。
- 原料来源明确为背包；未来真正接通谷仓物流后再增加来源和自动生产设置。

## 4. 状态与反馈

| 状态 | 显示 | 玩家能做什么 |
| --- | --- | --- |
| 原料不足 | “还缺谷物 ×4”，主按钮禁用 | 换配方、减少批量，或关闭面板补充原料 |
| 队列已满 | “队列已满，现有订单完成后可继续添加” | 查看已有订单、收取成品、关闭等待 |
| 成品无法入库 | 当前订单显示“等待入库”，保留成品与进度 | 先收取已有成品；恢复条件后继续 |
| 背包不足 | 收取按钮禁用，并说明不足 | 关闭后整理背包；不发生部分“全部收取” |
| 维护预警 | 底栏提示剩余 1 天，允许提前维护 | 查看费用并确认维护 |
| 维护到期 | 顶栏“维护暂停”，主按钮禁用，已有订单保留 | 点击“进行维护”；已经完成的成品仍可收取 |
| 维护中 | 显示维护状态；避免重复付款 | 等待维护完成，保留原队列 |
| 配方未解锁 | 配方可查看，显示解锁条件 | 在正式进度系统接入后沿用原解锁预检 |

容量必须准确表达：当前风车默认输出仓是 **3 类物品**，不是 3 件。同类物品可叠加；不能把“已存 3 / 3 类”直接当作无法生产。是否暂停入库必须读取 `ProductionSystem` 的真实状态。原型中的“成品无法入库”用于评审通用暂停样式。

全部收取先校验完整背包容量；失败保持输出仓和背包不变。单项“收取”表示收取该类全部数量，沿用现有收取接口。

## 5. 维护与时间

- 沿用现有维护周期 14 游戏日，到期前 1 日预警。
- 维护费用当前为 25 金币、木材 ×1、石材 ×1；确认弹层显示费用、持有量、不足项和恢复说明。
- 维护历时 3 现实秒，沿用现有可在游戏暂停期间执行的维护计时；期间游戏时间和加工计时继续暂停。维护完成后重置维护周期，关闭面板才继续加工。
- Esc 优先关闭维护确认，再关闭风车主面板；关闭后恢复玩家控制与打开前的时间暂停状态。
- 维护警告及暂停沿用 3D 谷仓修复后的显示方式，避免将旧版裂纹贴图覆盖到立体模型上。

## 6. 行情与信息边界

展示“原料卖出参考 / 成品卖出参考”和两者差额，帮助玩家决定直接卖原料还是加工。输入按同一批量的 `MarketSystem.quote_sell` 估算机会成本，输出按产出批量报价。差额明确未扣维护成本，不称作保证利润；该面板不直接买卖物品。

自动取料、自动回仓、动力网络尚未接入当前 3D 操作流程，本稿不摆放无效开关。风车本身不要求水车或电力。

## 7. 接入与验收依据

正式实现复用 `BuildingProductionPanel` 的选配方、批量、快照与请求流程，接入现有 `ProductionSystem.preflight_recipe`、生产提交、收取和维护接口。时钟与玩家锁定由 3D 面板宿主管理；存档保留队列、投入、成品与维护进度。已选择配方按建筑记忆，临时批量不写存档。

设计原型已通过浏览器交互检查：桌面及窄屏布局、选配方/最大批量、原料扣除、队列占位、关闭重开保留、逐类/全部收取、缺料与背包满限制、维护扣费和维护期间保留加工进度。原型不读取游戏存档；正式 Godot 接入后仍需进行游戏集成测试。
