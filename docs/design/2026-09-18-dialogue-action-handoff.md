# 对话行动交接

玩家与 NPC 说定稍后行动时，下一轮后台 Agent Loop 必须显式复核这段约定，并用实时查询和动作工具继续执行。

## 数据与调度

- NPC 明确采纳的后续计划使用现有 `adopt_short_term_goal` 持久化。对话首轮直接提供此工具，来源 ID 为 `dialogue:<request_id>`，建议一分钟后复核。没有接受、闲聊或假设不创建目标。
- Runtime 收到并验证对话回复后，将双方原话、已提交动作、真实执行回执写入 `loop_state.dialogue_handoffs`，同时记录到经验事件。即使模型只口头答应，也不会仅依赖最近 15 条历史或相关记忆检索来找回对话。
- 普通历史上传成功只确认事件同步，不删除交接。交接随现有游戏存档保存，旧存档缺少该字段时按空队列读取。
- 对话结束后触发后台事件循环。暂停期间不启动后台请求；仍服从已有执行锁、角色日程、并发和预算限制。
- 每轮请求携带最早四条未复核对话；积压超过四条时额外携带最新一条，以便看到后续修订或取消。其余原文留在持久队列，必要时查询历史核对中间对话。单轮最多五条，不预加载地图、市场等世界数据。

## 模型执行

`turn.dialogue_followups`、带版本及来源的 `goal_refs` 放在受保护头部，工作上下文 compact 不删除它们。模型先复核约定，只推进 NPC 明确接受且没有取消的部分，再通过 `discover_tools` / `query_world` 核实当前条件，返回 `move`、`travel`、`start_leisure` 等具体动作调用。不得靠“准备去”完成后台决策。

交接包含对话期间已经提交的动作及最新回执，避免重复交易、移动或下单。新的取消或更改优先；玩家单方面指令、NPC 拒绝和闲聊允许不执行动作。多步骤或暂时受阻的约定必须转为持久短期目标，而非反复口头承诺。

## 回执与确认

后台批次执行中保留交接；失败或拒绝保留交接并使用现有反馈退避重试。成功完成批次后只确认该轮开始时绑定的前四条交接，执行期间新到的对话不会被误删。没有需要行动的对话可在空动作复核后确认；长计划记录目标后由目标继续承接。

“交接已复核”不表示所有承诺已经完成。目标完成仍按现有权威成功条件或实际执行结果判断，不能把文字答复当完成回执。`BatchFinished.dialogue_handoff_ids` 关联动作批次来源，服务 trace 的 `dialogue.handoff_review` 标识复核开始。

## 验证

- `tests/run_dialogue_handoff_tests.gd`：真实 Runtime 接收对话、暂停边界、资源刷新、存档兼容、同步独立性、失败/异步回执、并发新对话、积压边界。
- `services/agent-service/tests/dialogue_handoff.test.ts`：真实 Loop 配合模拟模型输出，验证交接 → 按需地图查询 → 具体 move、对话目标工具、压缩保护、拒绝/闲聊和协议校验。
- 保留既有 Agent Loop、回执和服务测试。模拟模型测试验证数据与执行链路，不代表线上模型对所有自然语言的语义判断都正确。
