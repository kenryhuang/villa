# Agent Context / Loop 重构实施记录

对应设计：[Agent context 重构](2026-09-13-agent-context-refactor-design.md)。正式入口仍是 `scenes/farm3d/main.tscn`，分支为 `feature/3d-farm-preview`。

## 已落地的结构

| 文件 | 职责 |
|---|---|
| `data/agents/game_env.json` | 简要玩法和可发现领域；不装入世界实例 |
| `services/agent-service/src/agent_loop.ts` | 多轮读取、动态工具菜单、行动上限、输入计量和工作上下文压缩 |
| `services/agent-service/src/world_read_broker.ts` | 将当前请求的世界查询通过 SSE 交给 Godot，并核对请求、角色、存档和 epoch |
| `scripts/ai_agent/agent_world_query_router.gd` | 按领域/分区/ID/分页读取当前授权世界状态 |
| `scripts/ai_agent/agent_loop_state.gd` | 资源版本、事件待确认队列、短期目标、执行批次和反馈冷却 |
| `services/agent-service/src/memory.ts` | 原始事件、最近 15 条、历史摘要、重要记忆、相关检索、迁移和 checkpoint |
| `scripts/ai_agent/agent_runtime.gd` | 接入原 scheduler/gateway/executor；周期同步、结果回写、保存恢复 |

初始消息保留 GameEnv、身份/人格/职业目标、完整自身资源、最近 15 条事件及早期摘要，附带当前输入/触发和相关记忆。较长事件使用标记过的摘录和原始事件 ID；完整原文保存在数据库，可再次查询。

工具读取只进入当前 Loop。下一次驱动重新读取权威资源、经历和相关记忆。查询本身不会成为游戏事实触发循环；执行结果、目标检查和原有世界事件可以触发下一轮。

短期目标由 NPC 明确调用行动工具采纳，最多三个有效目标。保存来源 ID、版本、复查时间、期限，以及可选的结构化成功条件。背包数量、完成项目、已知发现由 Godot 判定；到期优先于迟到的成功条件。目标、未确认事件、资源版本、执行批次和合并后的后台触发一起存档。恢复后未提交的后台推理重新排队；对话不自动重放。

## 实际接口与默认值

- 正式 3D 的决策请求为 v3；禁止装入旧的完整世界投影。独立旧 2D 入口保留 v2。动作、回执、SSE 封套继续使用已验证的 v2 执行契约。
- 初始读取工具是 `discover_tools`、`inspect_self_resources`、`recall_memory`。按领域动态增加 `query_world`、原始记忆工具和当前允许的行动 schema。
- 世界查询采用统一的 `query_world(domain, section, id, query, cursor, limit)`，默认五项，列表最多十项；没有创建大量同义的独立查询函数。
- 默认每轮最多六个读取回合、十二次读取，最终最多三个顺序行动；对话、公共协调最多一个行动。异步行动完成后续行，失败停止剩余动作。
- 资源及待确认事件每 60 游戏分钟同步一次；决策前和动作结果后更新资源版本。公共角色也参与周期同步。
- 动作反馈最多连续推进三次，随后冷却 60 游戏分钟。短期目标和未消费事件仍会保留。
- 服务配置新增可选 `loop` 节；旧本地配置使用默认值，无需覆盖密钥配置。
- 输入按 UTF-8 字节上界保守估算，并在 trace 明确标注。默认压缩阈值 24000、目标 16000、硬上限 32000，最多压缩两次。它们不是精确模型 token 数；应按实际模型窗口及输出预留调整。
- 工作上下文压缩当前采用确定性的结构化摘录，合并先前摘要，成对移除旧工具消息；被移出的精确条款要求重新查询。固定头部不改写；目标不可达通过 `target_met=false` 记录，超过硬上限返回明确容量错误。
- 长期重要记忆和滚动历史摘要使用既有真实 Provider 异步提取；相关检索使用文本匹配及中文相邻字组合。原始经历始终保留，摘要失败可重试。
- 调试记录保留各模型回合的输入/输出、查询结果、压缩计量和真实执行回执；开启原有 session 日志配置后写入磁盘。

## 验证

本地验证未调用外部真实模型，未修改本地 Provider 密钥或实际玩家存档。

- 服务测试：95 项通过（包含显式启用的 Godot 集成测试）。
- 新 Loop 场景测试：97 项检查通过，包括按需读取、资源版本、目标幂等/完成/到期、存档恢复和失败批次关闭。
- 原 Agent 系统：1713 项检查通过；3D Agent 59 项、存档保护 18 项、并发 33 项、trace recovery 39 项通过。
- Living World P0–P12 场景回归通过，覆盖生产、建设、委托、工作、公共事务、知识、环境、活动和迁移。
- 实际 Godot 暂停场景 ↔ Agent Service ↔ 本地测试上游：三回合完成发现工具、读取农田、回复；初始 Provider 请求体约 11 KB（UTF-8 字节，非 token 数）。
- 修订旧 trace recovery 测试，使其等待实际移动完成，并通过新世界查询取得市场报价。

运行方式和配置示例见 [Agent Service README](../../services/agent-service/README.md)。代码切换后需要重启 Agent Service 和游戏，以运行相同版本的客户端与服务。真实模型是否能稳定选择工具、规划经济行为，仍需后续游戏观察；上述测试证明通信和状态机制，不替代行为效果评估。
