# 种子与商行最小闭环实现

正式入口：`scenes/farm3d/main.tscn`。核心规则在 `scripts/systems/merchant_system.gd`，由 `living_world_system.gd` 随游戏时间推进。

## 已接通的循环

- 村庄商行成为现有市场全部现货交易的资金对手方。客户买货给商行入账，卖货由商行付款；资金不足或库存超过收购上限时整单拒绝。既有 MarketSystem 事务将商行账本一并回滚。
- 谷物、胡萝卜、土豆可在现有风车选种：消耗 1 份作物，18 分钟后产出 2 份种子；沿用真实加工队列、租金、材料托管与交付。风车界面显示投入和产出，支持滚动全部配方。
- 有种子现货时，短缺先发布预付奖励的本地采购委托，等待 60 分钟。无人认领部分退款；已认领部分保留资金和货量，仅对剩余缺口进口。种子库存为零时直接启动外部采购恢复供给。
- 外部种子供应商有有限库存和每日生产额度。下单扣商行资金、扣货源、占用运力；到货才增加可售库存。封路延迟交付，在途数量参与缺口计算，重复推进不重复付款或入库。
- 商行可将持有的多余谷物、胡萝卜、土豆外销。发货扣现货，到达后才收到净货款；保留本地安全库存，正常资金条件下不主动亏本出售。
- 市场界面显示到货、短缺原因与最大可收购量，并支持登记补货需求。需求登记不扣款，不承诺买到货。

## 初始参数与范围

商行期初现金 10,000，核心种子保留资金 2,000。每 60 游戏分钟检查，基础种子保底目标最多 20 份；目标同时参考有效需求和近期真实销量，最高为目录目标库存的两倍。

运力 24 单位/日，与旧商队共享；种子每 10 份占一个运力单位，树苗等物品每份占一个单位。进口基础成本为目录基价的 55% 向下取整（最低 1），加每运力单位 1 金币。晴天进口 180 分钟，雨天 480 分钟；出口基础时间 180 分钟，封路同样暂停。

非基础种子由需求登记或实际销量触发，需求有效期 1,080 分钟，同一角色同一物品更新原需求。旧食物供应仓库仍有限，仅在相应现货断货时尝试采购；本版没有为所有食物增加无限场外生产。

NPC 储备目标仍由其自身目标与决策管理。系统在已有种子储备不足时产生 `SeedReserveLow`，到货和本地委托也写入相关 NPC 的事件记录并通知调度器；不替 NPC 强制消费或承接合同。模型可逐步发现市场工具，使用 `query_world(domain="market", section="supply", id=物品ID)` 查询，再执行 `request_supply`。初始环境说明只增加简短玩法提示。

## 保存与兼容

商行状态保存在 `market.merchant`：现金、期初资本、村内/跨境/合同净收支、库存成本、供应商库存、采购委托引用、需求与幂等回执、运输单、运力计数及最近 256 条流水。现金满足 `opening_capital + local_net + external_net + asset_net`；合同锁定资金仍在原委托 escrow 中。已完成运输只保留最近 64 单，累计收支保留。

现货仍只有 `market.items` 一份。旧存档缺少商行状态时才创建期初账户，不补现货；新存档重复读写不重复注资。已有 NPC 付款运输继续按原所有者履行，新应急单转由商行创建。

场外仓库升级为版本 2，新增 `merchant_withdrawals`，校验“剩余仓库 + 旧商队提货 + 商行提货 = 原始货源”。保留版本 1 读取。世界存档另外校验商行时钟及采购委托引用。

## 验证

- `run_merchant_loop_tests.gd`：86 项通过，覆盖双边资金、回滚、断货、封路、供给请求幂等、本地部分认领与退款、进口抵扣、实际出口回款、场外仓库守恒与存读档，以及三种作物各三轮真实播种/成熟/收获/选种。包含真实 Agent 校验器与执行器补货行动。
- Agent Service：108 项通过（包含 Godot Loop 互通）；新增对话中“发现市场→查询短缺→登记需求”的工具链测试。
- 既有 Agent 回归 1,719 项、3D Agent 59 项、动作流程 20 项、P1 60 项、P5 39 项、3D 存档保护 18 项通过。
- P12 rules/farmer，seed 42，30 游戏日：通过；每天金币边界差额为 0，商行状态每天校验通过，第 7/14/21/28 日保存恢复成功，玩家完成 24 次真实收获。最后商行现金 20,944 = 10,000 + 村内净收入 4,515 + 跨境净收入 6,429。
- 扩展生产链回归有 3/89 项未通过，均为伐木场/采石场自动产出收集；本次未更改这些建筑的生产规则。日志见 `tmp/agent-refactor/merchant-production-chain.log`。

长周期结果与轨迹保存在 `tmp/living-world/P12-strategy-farmer-42.json`，定向日志为 `tmp/agent-refactor/merchant-final4.log`，服务日志为 `tmp/agent-refactor/merchant-service-final.log`。测试使用独立存档，未修改玩家正式存档。

这验证了供给恢复、交易与持续再生产机制，不代表已完成全部经济平衡。第 30 日仍有 1 名居民因无力购买而缺粮（市场食物未断货）。规则模拟未调用真实 LLM，也不证明每个 NPC 都会自主采用留种策略或所有季节的经营均盈利。

加载改动需重新启动游戏；新工具契约需重启 Agent Service。
